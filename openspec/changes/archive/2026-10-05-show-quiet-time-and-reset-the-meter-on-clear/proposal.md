## Why

The ship meter (`draw-the-ship-run-live`) draws a run while it runs, but it cannot answer the one question a person has when the status line stops moving: is the run stuck, or is it waiting on a plan window? On a subscription the Workflow runtime pauses at a usage limit rather than failing (vendor fact orchestration-7 in `briefs/claude-code-teams-and-orchestration-briefs.md`), and that pause looks exactly like a hang. The meter shows the plan windows on request, but nothing on the status line, the spinner or the pane says how long it has been since the run last did anything.

The same module also keeps its run state past the one boundary the engine treats as a new session. `session.start` does not fire after `/clear`, `/resume` or `/branch` (mods-11 in the same brief; the engine's classic session-start event fires instead, with a `source`), and `hooks/mod.mjs` resets its run only there and on an accepted launch. So after a `/clear` mid-run the status line keeps naming a run the conversation no longer holds, while the launch guard's ledger in `$.state`, which the engine does empty at that boundary, already allows the next launch. The two things the module keeps are reset on two different boundaries. The built-in `diff` mod resets on this boundary; the meter must too.

## What Changes

- **The meter says how long the run has been quiet.** While a run is live the module stamps the time of each thing the run does as the engine reports it: the accepted launch, each step the CLI prints, each model request a run agent starts and each answer it receives, each agent's turn end, each spawn. An interval the engine runs for the module (`$.clock.every`, the host's own timer) recomputes the quiet time on each period, and once it reaches a published cap the word `quiet <n> min` is appended to the status line, to the spinner's suffix and to the pane, beside the plan windows the pane already lists with no threshold and no colour. The next activity clears the word. The module names no cause: `quiet 7 min` beside `five_hour 100% used · resets 23:00` is the person's inference, never the module's.
- **The figure is never guessed.** A clock read that fails leaves the stamp as it was and the word absent; the pane says `last activity unknown` rather than a time it does not have. The interval ends at close, at halt and at the session boundary below, and a period the engine refuses simply stops the ticking: the pane still computes the figure at each draw.
- **The session boundary resets the meter.** A `classic.SessionStart` whose `source` is `clear`, `resume` or `fork` ends the run as the module holds it: the interval is cancelled, the run record is fresh, the status line is cleared and the pane redraws to its no-run text. `startup` and `compact` leave the run alone, because a compaction mid-run is still the same run. A step that crosses the module after the boundary is ignored, as a step with no live run already is, and the first one is named once on the debug log so the silence is spoken. The pane is not closed by the module: it has no close call, the pane is dismissed by Escape, and a pane reading `no ship run is live in this session` is true. This is a bug fix: the vendor reference establishes that `session.start` does not fire at these boundaries, the code has exactly two reset sites, and the repro is the kit test task 1.1 lands first, which fails against today's module.
- **Two caps are published, not restated.** `interlock limits` prints `meter quiet after (ms)` and `meter tick (ms)`. Both are keys in `lib/limits.mjs`, read by a new Node-free rule module under `lib/` that the hooks module imports, the way the launch rule reads the ledger age; the module itself holds no number and `test/spine/limits.test.mjs` pins the reader under `lib/`.
- **The observe-only pins move by exactly one call and one event.** The allow-list in `test/spine/mod-pins.test.mjs` gains `$.clock.every`; the hooked-events pin gains `classic.SessionStart`. The forbidden tokens are unchanged: no deny, no catch, no model, prompt, message, process, network, file write or permission check is added. `claude plugin validate --strict` records the new `hooks:` and `calls:` lines in the design.
- **Docs and the changelog.** `docs/07-cli-and-configuration.md` describes the quiet word and the reset; `docs/13-the-guards.md` adds `classic.SessionStart` to the module's row and section and says why `compact` is not a boundary; `CHANGELOG.md` Unreleased carries both. `briefs/claude-code-teams-and-orchestration-briefs.md` gains the three-line note the review of the built-in mods produced (the `diff` mod's boundary reset, the version-only `mods` doctor row on a managed machine, the inline-dialog fallback), so the next reader finds it.
- **Two probes come first, and one can move the design.** (1) In a `--plugin-dir` session, does an interval a module started survive the module's hot reload, and does the engine cancel it? If an orphan keeps ticking, the interval's callback must recognise its own generation and go silent. (2) In a live run with the person idle, the status line and, where it draws, the spinner carry the word after the cap. Neither probe changes the spec; the first may change the callback's shape.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `hooks/ship-meter`: the meter gains the quiet figure from a published cap (new requirement); the inertness requirement gains the session boundary and the compaction exception; the pane requirement gains the activity line; the observe-only requirement's recorded calls gain `$.clock.every` and its hooks gain `classic.SessionStart`.

## Impact

- **Changed:** `hooks/mod.mjs` (the stamps, the interval, the boundary hook, the pane line, the status and spinner text); `lib/limits.mjs` (two keys, two printed rows); `test/spine/mod-pins.test.mjs` (allow-list, hooked events); `test/spine/limits.test.mjs` (the two printed caps and their reader under `lib/`); `test/mod/meter.test.ts` (the boundary repro, the quiet word under the kit's mock clock, the compaction and startup pass-through); `docs/07-cli-and-configuration.md`; `docs/13-the-guards.md`; `CHANGELOG.md`; `briefs/claude-code-teams-and-orchestration-briefs.md`.
- **New:** `lib/meter-quiet.mjs` (pure, Node-free: the quiet time from two stamps, the word from the cap, the tick period) and `test/spine/meter-quiet.test.mjs`.
- **Untouched:** every settings hook, `lib/launch-rule.mjs`, `types/index.d.ts` (no new session-state key: the stamps and the word are module state, reset with the run), the CLI, the drivers, the trajectory and every corpus. No dependency. No new `$.state` key, so `claude plugin validate` sees the same contract.
- **Hosts:** below the mods floor nothing changes; the settings hooks and the close summary are what they were. On a mods host the module ticks once per published period for the life of a live run and never outside one.
