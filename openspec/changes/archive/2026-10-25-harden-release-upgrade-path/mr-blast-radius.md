### ↩️ Rollback

Reverting is safe for data in most cases. Every new key the head code writes is ignored by the old code, because the manifest schema string is unchanged and the old readers take named fields. That covers `cli`, `plugin`, `closedAt`, `defaultedFields` and `hostEnv.advisor` on the manifest, `cliVersion` on steps, the version fields on `run-start` and the receipt, and `schema_version`, `extractor` and `overlays` on the graph manifest. `autonomy.json.unreadable-*` files become orphans. **Exceptions:**
- **Resumed runs.** A run that halted or closed under the new CLI and is resumed under the old one loses the D15 protection. `run next` on a halted manifest re-emits a batch, and `run close` re-runs fully, writing a second receipt, run-halt event and outcome row.
- **Restarted counters.** A record moved aside by B6 is not restored. The old code reads the restarted counters.
- **Deleted classification.** A `classified.json` deleted by B3 is not restored. It is transient, and the planner rewrites it.
- **Eval crons.** A revert brings the crons back, so the scheduled jobs resume reporting green with nothing metered.
