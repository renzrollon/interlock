### ↩️ Rollback

A revert is safe for data. Every key the new code writes is additive and ignored by 1b16c5e: `coverage`, `proof`, `proofHashes`, `dimensions.degraded` in `review.json`, `width` in the validate JSON, and `reviewProofBanner` in the run manifest. The old `readReviewRan` never reads `proof`, so records written by this version read green again under the old rules. **One exception:** the old CLI drops a dimension record's `degraded` key silently (its validator keeps only the four keys plus `depth`), so a review in flight across the revert loses the `domain-partial` / `blast-radius-partial` flag without saying so. The graph reads stale once more after a revert (the archive is re-indexed) until `interlock-graph update`.
