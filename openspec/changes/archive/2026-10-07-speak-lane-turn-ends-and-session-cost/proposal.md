## Why

The ship meter already hears a run agent's turn end. `hooks/mod.mjs:595-604` hooks `turn.complete`, keeps the host's `reason` and `durationMs` on the agent's record, and shows them only on the pane: the agent row's last field (`hooks/mod.mjs:441`) and, where the agent is joined to its lane, the wave row's state (`:427`). A lane the host stopped with `error`, `aborted` or `refusal` is therefore visible only to a person who has the pane open and reads the right row, and with the agent-to-lane join dormant on 2.1.289 (`agent.spawn` did not fire for a Workflow `agent()`, `openspec/changes/archive/2026-10-05-draw-the-ship-run-live/design.md:138-139`) the wave row reads `waiting` for the rest of the run. The record of that stop is the driver's banner `AGENT RETURNED NO RESULT: <label> — the runtime stopped it, the API failed, or a usage limit ended it` (`workflows/ship.js:305-311`), and the driver folds its own banners into the close through `--host-banners` (`workflows/ship.js:180-186, 547-557`), so on the Workflow host the meter first sees that banner in the close record, after the run has spent the rest of its waves. The meter has a push surface for exactly this: one toast per banner text, the moment it crosses (`hooks/mod.mjs:347-354`). Nothing uses it for the host's own word about a turn.

The same pane reads `$.session.usage()` at every draw (`hooks/mod.mjs:453`) and keeps one field of the answer, `rateLimits` (`:454`). The engine's declaration answers four: `startedAt`, `context`, `rateLimits` and `cost` (`claude-code.d.ts:10829-10856` in the 2.1.286 declaration), "the status line's figures", with `cost.usd` "US dollars, summed over every priced API response this session" (`:10109-10114`) and `context` the live window's `tokens`, `window` and `percent` (`:10079-10098`). The repository deliberately records no dollar figure of its own: the archived cache-cost change's Non-Goals line reads "No derived cost figure in this change. The multipliers land in `MODEL_PRICES` so a dollar figure becomes computable; computing and presenting one is a later decision" (`openspec/changes/archive/2026-09-10-surface-prompt-cache-cost/design.md:23`), and `CHANGELOG.md:133` records that "neither the ship receipt nor `interlock report` shows dollars". The engine's own total is not that figure: it is the host's ledger, already summed, already on the status line, and the meter can show it as it shows the plan windows, with no price table, no threshold and no colour.

Of the mod candidates the 2026-10-06 report ranks (`reports/Interlock mods beyond the ship meter.md`, candidate 7 in `research_notes/Interlock mods beyond the ship meter/candidate_mod_catalog.md`), this is the one that moves no pin: `turn.complete` is already in `HOOKED_EVENTS` and `$.ui.toast` and `$.session.usage` are already in `ALLOWED_CALLS` (`test/spine/mod-pins.test.mjs:31-49, 62-73`). It lands first among the mod changes proposed beside it.

## What Changes

- **A run agent's turn that ends without an answer is spoken the moment the host says so.** While a run is live, a `turn.complete` carrying an `agentId` and a `reason` other than `answer` raises one toast: the lane's descriptive title where the agent is joined to a wave row, or `lane unknown` while the join is dormant, the agent id, and the host's reason word repeated verbatim (`aborted`, `refusal`, `error`, or whatever word a later host sends). One toast per agent per run; a second abnormal end for the same agent, and every `answer`, raise nothing. The module names no cause and reads no `isAborted`, `refusal.category` or `usage`: the word is the host's, as `TurnCompleteReason` declares it (`claude-code.d.ts:12339`). The agent row keeps the reason and duration as today, so the pane still shows it after the toast is gone.
- **The record is unchanged, and the toast is earlier than it.** `AGENT RETURNED NO RESULT` stays the driver's banner and the close summary's line; on the runner host `LANE STOPPED BY HOST` (`lib/run.mjs:691-693, 798`) stays the CLI's. The toast hands the CLI nothing: the two residual Brief 9 items (`draw-the-ship-run-live/proposal.md:67`) stay out of scope.
- **The pane shows the engine's own session cost and context, as the host reports them.** The one `$.session.usage()` read the pane already makes gains two keyed lines in a `session` section before the plan windows: the context fill (`tokens`, `window`, `percent`) and the session's cost (`cost.usd`). Only fields the host answered are shown: a `cost` the host does not keep reads `session cost not reported by this host`, a window with no fill yet reads so, and a read that fails names its reason on both lines and on the plan-window line instead of the subscription guess the plan-window fallback makes today. The plain call is made with no `breakdown` argument, because the declaration says only the plain call costs nothing (`claude-code.d.ts:2601-2605`).
- **No dollar figure of the module's own, ever.** The module computes nothing from `MODEL_PRICES` or from token sums; the figure is `cost.usd` as answered, formatted and labelled as the engine's total for this session, not the run's. A static pin asserts the module never names `MODEL_PRICES` and never passes an argument to `$.session.usage`.
- **Which pins move: none.** `HOOKED_EVENTS` already carries `turn.complete`; `ALLOWED_CALLS` already carries `$.ui.toast` and `$.session.usage`; `FORBIDDEN_TOKENS` is unchanged; `types/index.d.ts` declares the same one key; no `lib/limits.mjs` key is added because no number is involved. `claude plugin validate . --strict` is expected to print the lines the archived quiet-time design D7 records, with at most an attribution difference (`(via …)`) on `$.ui.toast` or `$.session.usage`; the design records what it prints.
- **Probes come first, and none can move a pin.** (1) Whether `turn.complete` carries `agentId`, `reason` and `durationMs` for a Workflow-spawned run agent whose turn ends with `aborted` or `error` on 2.1.289, provoked from a scratch workflow under `$TMPDIR` through `scripts/host-probe.mjs`; the captured `answer` payload (`test/fixtures/mod/turn-complete-subagent.json`) already carries all three. (2) The exact `$.session.usage()` shape at runtime beside the 2.1.286 declaration: whether `cost` is present in a `-p` session and in a terminal session, and whether `context.tokens` and `context.percent` appear after the first response. (3) In the kit, whether a test's `on('session.usage')` answering `{ deny }` rejects the plugin's read, so the failure case can be written as the clock-failure cases were. If (1) shows no abnormal `turn.complete` for a Workflow agent, the toast is still pinned on the declared enum under the kit and the design says it is unproven on the host; if (2) shows no `cost`, the pane line says so and nothing else changes.
- **Docs and the changelog.** `docs/07-cli-and-configuration.md` gains the turn-end toast beside the banner toast and the two session lines in the pane's list; `docs/13-the-guards.md` gains the toast under the `turn.complete` bullet and the session figures under the pane; `CHANGELOG.md` Unreleased carries both. `briefs/claude-code-teams-and-orchestration-briefs.md` gains a short dated note that candidate 7 of the mods report was taken up and that the driver's `AGENT RETURNED NO RESULT` reaches the meter only at the close.
- **Serialization.** This change touches `hooks/mod.mjs`, `test/mod/meter.test.ts`, `test/spine/mod-pins.test.mjs`, `docs/07-cli-and-configuration.md`, `docs/13-the-guards.md` and `CHANGELOG.md`. It depends on no sibling and lands first; the changes proposed beside it that touch the same module or test files, as proposed, land after it: `speak-permission-prompts-and-guard-denials`, `show-preflight-and-interrupted-runs-at-session-start`, `draw-the-wave-board-in-the-meter-pane` and `observe-the-spec-run-live`. `draw-wave-plan-and-handoff-graph-from-the-cli` and `print-json-from-the-spec-gate-lines` are CLI changes and do not wait on this one.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `hooks/ship-meter`: a new requirement, the turn-end toast (the host's reason word, once per agent per run, naming the lane title or `lane unknown`); the pane requirement gains the session's context and cost lines as the engine reports them, with no figure of the module's own, and names a failed usage read instead of guessing a cause.

## Impact

- **Changed:** `hooks/mod.mjs` (the toast in the `turn.complete` hook, the agent record's toasted flag, the `session` section of the pane from the existing usage read); `test/mod/meter.test.ts` (the harness answers `session.usage` from a per-world value; the toast cases, the session-line cases, the failure cases); `test/spine/mod-pins.test.mjs` (two regression pins: no argument to `$.session.usage`, no `MODEL_PRICES` in the module; no list moves); `docs/07-cli-and-configuration.md`; `docs/13-the-guards.md`; `CHANGELOG.md`; `briefs/claude-code-teams-and-orchestration-briefs.md`.
- **New:** nothing. No pure module under `lib/`, because there is no rule to hold: no threshold, no computation, no number.
- **Untouched:** every settings hook, `lib/launch-rule.mjs`, `lib/meter-quiet.mjs`, `lib/limits.mjs`, `types/index.d.ts`, `hooks/hooks.json`, the CLI, the drivers (`AGENT RETURNED NO RESULT` is raised where it was), the trajectory and every corpus, the status line and the spinner.
