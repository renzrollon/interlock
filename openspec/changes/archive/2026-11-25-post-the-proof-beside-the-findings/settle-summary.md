## Description

## Summary
- A person approving a settled pull request could not see what ran, what it returned or what no check would catch, and the scenario confirmation rested on the worker's own report. Settle now posts a `## Validation — <sha>` comment rendered from the pass's own records, and a confirmed scenario has to cite a file and line that exist at the head (`post-the-proof-beside-the-findings`).
- `review.ran` read amber whenever a reviewer left any input unread, documentation its rubric never asked for included. An `unread` entry can now name its files, and an entry that names only changed prose outside `openspec/`, `.claude/` and `REVIEW.md` raises a `prose-unread` flag instead of failing the proof (`flag-the-prose-a-reviewer-left-unread`).
- There was no build check, and nothing read a lint result. A `build` check kind now runs at the final gate and halts it when red. `verify.suite` reads lint and build beside the unit suite and the type check, and every reviewer prompt leaves formatting, lint and type errors to the project's tools (`let-tooling-own-the-small-checks`).
- A teammate's pull request had no way in. `/interlock:review-code --pr <ref>` reviews the head the platform pins in a detached worktree. It writes nothing to the author's branch, and it posts its one comment only with `--post` (`review-a-teammates-pull-request-read-only`).
