### ↩️ Rollback

Reverting is safe for stored data in the sense that nothing throws: the earlier code ignores a `build` section in the profile, `proseUnread`, ledger `paths`, `preExisting`, the handoff's extra keys and the timings line. Labels keep their names. Posted comments stay true to their commit.

**Three exceptions**, each a record that reads more favourably under the earlier code than under this one:

- A stored verdict whose only failure is a build reads `verify.suite` green on the earlier code, which iterated typecheck and unit and never read `halt`. One whose only failure is lint also reads green.
- A review record with `proven: true` and a non-empty `proseUnread` reads proven with no flag: the earlier `proofAnswer` trusts the stored boolean. Re-running the review corrects it.
- A plan holding a build step, judged by the earlier CLI with a build result, is refused as an unknown kind. Only a downgrade in the middle of one run hits it.

The reverse matters after release too: the new settle skill's `verify exec --record` and `conformance-brief --out` are refused by an earlier CLI (M9 in the earlier comment).
