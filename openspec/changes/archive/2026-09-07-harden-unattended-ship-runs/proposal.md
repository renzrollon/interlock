## Why

A ship run that halts at wave three while its operator is away prints `SHIP HALTED` to a terminal nobody is reading, and when they return nothing in the summary names the run or the directory a later tool could join to a session transcript. A clean run leaves the change unarchived and says nothing, so the next `/interlock:spec` plans against stale living specs — the failure `interlock drift` exists to catch and that this repository has already paid for (`docs/10-agentic-workflow-ship-and-spec.md:31, 434`). And `interlock doctor` reports the allowlist green for a run whose very first ping shells out to `test -f …` and `printenv …`, neither of which the host auto-approves, so an unattended run can still stall on an approval prompt three seconds in. These are the four "quick wins under a day" from the 2026-09-05 ideas review, independent of the five larger ideas, and all four land at the run's close — the one seam both hosts already pass through (`lib/run.mjs:2172`, `workflows/ship.js:530`, `bin/interlock-run:438`). The explore brief is `.claude/handoff/explore-harden-unattended-ship-runs-20260907-105557.md`.

## What Changes

- **Push at close.** A new `lib/notify.mjs` posts one message to an ntfy topic over Node's global `fetch` (no dependency), exposed as `interlock notify` and as a `--notify` flag on `interlock run close`, which both drivers pass from their existing `closeArgs()`. The topic comes from `INTERLOCK_NTFY_TOPIC`, the server from `INTERLOCK_NTFY_URL` (default `https://ntfy.sh`). It fires on every terminal close — halt, complete, complete with leftovers — with ntfy priority `high` on a halt. The body is the summary's first line, the change and the run id; never the topic, the cwd or the slug. The outcome is spoken: a `push:` row in the summary when a topic is configured, a `PUSH FAILED:` degradation banner when the post fails, and an `interlock doctor` row (`ok` / `skip`) that says whether push is configured. The exit code never changes. The post is bounded by a new `LIMITS.notifyTimeoutMs`. The test suite never passes `--notify`, so no test reaches the network; `README.md`'s "without the network" claim gains its one documented exception and a test pins that only the notify path imports the transport.
- **Archive reminder.** `runClose` calls `detectUnarchived(root)` and the summary prints a verbatim `ARCHIVE PENDING — <change>: after merge, run openspec archive <change>` line on a clean `SHIP COMPLETE` whose every task is ticked, plus one `also unarchived: N completed change(s) — run interlock drift` line when other completed changes are still unarchived. Exit code unchanged: docs/10's "blocking reminder" is read as an unmissable contract string, not a non-zero exit, because the just-shipped change satisfies the unarchived predicate by construction and four standing authorities forbid a drift-derived gate (`docs/14-evals.md:53-57`, `lib/drift.mjs:27-36`, `bin/interlock:1536`, `test/spine/cli.test.mjs:2102`).
- **Run identity in the receipt.** The summary prints `run: <runId>` (or `run: none — the run halted before a plan was adopted` when no plan was adopted), `project: <slug>` and `cwd: <absolute root>`, where the slug is the `~/.claude/projects` directory form of the root the close ran in — every character outside `[A-Za-z0-9]` becomes `-` — computed by a new pure `lib/project-slug.mjs`. Nothing is added to the receipt JSON or the outcome record.
- **Permission allowlist.** The untracked `.claude/settings.json` that already holds the doctor's six suggested rules is committed, and gains `Bash(test:*)`, `Bash(printenv:*)` and `Bash(mkdir:*)`. `REQUIRED_COMMANDS` in `lib/doctor.mjs` gains `test`, `printenv` and `mkdir` with their `why` — the environment probe (`workflows/ship.js:368-382`) instructs all three, and the host's built-in read-only set (which covers `echo` and `pwd`) does not include them. Two new tests pin the claim: a repo-fact test that this repository's settings cover the derived required set, and a drift test that every literal shell command in `workflows/ship.js` and `lib/prompts/*.mjs` is covered by `REQUIRED_COMMANDS ∪ profileCommands ∪ HOST_READ_ONLY`, the last a dated mirror of the host's auto-approved set. Consumer repositories missing the three rules will see the doctor go red, with the fix string naming them.
- **Spec checkpoint push** (pending D6). `skills/spec/SKILL.md` §6 calls `interlock notify checkpoint <change>` next to its `GOAL MET` line, pinned by token in `test/skills.test.mjs`. Remove task 3.4 if D6 is answered "ship-only".
- **Docs.** `docs/04-when-it-stops.md` gains `ARCHIVE PENDING`, `PUSH FAILED` and the run-identity lines, and its "if you do not have the run id handy" paragraph points at the summary; `docs/03-openspec-vs-interlock.md:47` names ship close as a third drift surface; `docs/10:445` is marked done; `README.md` documents the env vars and the network exception; `CHANGELOG.md` gains an entry.

No **BREAKING** changes. Every existing summary assertion in the suite matches by regex, and the default path — no topic configured — posts nothing.

## Capabilities

### New Capabilities

- `ship/close-notification`: how a terminal close reaches a person who is not watching — the `interlock notify` transport, the `--notify` flag on `run close` and both drivers passing it, configuration through `INTERLOCK_NTFY_TOPIC` / `INTERLOCK_NTFY_URL`, what the message carries and what it never carries, the spoken outcome (summary row, `PUSH FAILED` banner, doctor row), the timeout cap, and the no-network default.
- `ship/close-summary`: what the terminal summary carries beyond its degradation block — the run identity lines (`run:`, `project:`, `cwd:`) and the archive reminder — and the invariant that neither changes the exit code.

### Modified Capabilities

- `hooks/session-preflight`: the required-command set the preflight checks SHALL cover every command the run's drivers and briefings literally instruct that the host does not auto-approve, asserted against the driver and briefing text; and the preflight SHALL report push configuration as an advisory row.
- `ship/run-program`: the closing step SHALL accept `--notify` and both drivers SHALL pass it, so the push is one implementation interpreted by two hosts rather than two implementations.

- **Dependencies**: none. `fetch` is global on Node >= 18, the floor `package.json` already declares.
- **Compatibility**: unchanged when `INTERLOCK_NTFY_TOPIC` is unset. The summary gains lines; no test compares the whole text. `interlock doctor` may report `permissions: fail` on a consumer repository until it adds the three new rules, which is the doctor doing its job. The ntfy topic is a capability (anyone who knows it reads every message), so it is env-only and never written to the tree, the summary, the receipt or the trajectory.
