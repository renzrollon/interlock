## Why

A ship run still cannot say three things about itself. On the default host it cannot say what its agents cost or which model served them: `ASSUMED_CAPABILITIES` declares `cacheAccounting: false` for the Workflow runtime, every `/interlock:ship` run prints `CACHE ACCOUNTING NOT REPORTED`, and the trajectory's `agent-spawn` records the routed model as if it were the model that ran, although `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`, a fallback chain and an organization default model can all replace it. Mid-run permission prompts and auto-mode denials, the one interruption `docs/04` says the runtime cannot prevent, go unnamed. On the runner host it cannot say why a lane failed: `readClaudeEnvelope` keeps two fields of the `claude -p` envelope, a non-zero exit returns `null` before stdout is read, a `success` envelope without `structured_output` (the open bug anthropics/claude-code#82258, which this adapter's configuration triggers) and a lane a guard denied look exactly like a lane that did nothing, and the lane's resumable session id is dropped. And in a linked worktree, now the ordinary shape of parallel work on this host (`claude --bg`, `--worktree`, Desktop worktree sessions, Remote Control `--spawn worktree`), a run starts without its test profile and graph, then writes its fatal trajectory, its outcome line, its metrics and its resume card into a directory that goes away with the worktree, and `interlock report` in the main checkout never sees those runs and never says it is missing them. That breaks "degradation is spoken" three times over. Source: `briefs/claude-code-teams-and-orchestration-briefs.md`, Briefs 4, 5 and 6, read with the 2026-10-05 addendum. Briefs 1, 2 and 3 have landed, so the recorder file, the launch ledger, the `claude --version` probe and the snapshot base this change builds on all exist.

## What Changes

- **The recorder gains four reporting branches** (Brief 4). `hooks/recorder.mjs` is registered on `SubagentStart` and `SubagentStop` with the anchored matcher `^workflow-subagent$` (the type the host reports for every Workflow `agent()` spawn whatever `type` it named, task 1.1), and on `PermissionDenied` and `PermissionRequest`. Each branch acts only while a live stage marker exists and the run manifest carries a run id, and otherwise exits before any filesystem access. `SubagentStop` reads the agent's transcript, sums each assistant turn's input, output, cache-read and cache-creation tokens (a turn being one assistant message, however many lines the host wrote for it) (split by lifetime tier where the transcript carries the split, total only where it does not), collects the distinct models that served it, pulls the briefing sha256 out of the bootstrap text as the join key, and writes one small file per agent under `.claude/ship/agent-usage/<runId>/`. `SubagentStart` records the spawn time once per agent id. The permission branches write one file per event naming the tool, the agent id and the reason. Nothing here can block: every branch exits 0, returns no decision, and an unparseable transcript is unrecorded, never zero.
- **The close joins what the recorder wrote and names the model that ran.** `run close` matches each recorded agent to a dispatched spawn by briefing sha. A wave where every spawn joined gets recorded cache figures and the manifest's observed `cacheAccounting` becomes `hook`, a new registry value no adapter may declare; one missing agent makes the wave unknown under the existing unknown-not-zero rule and banners `CACHE ACCOUNTING PARTIAL: <n> of <m> agents unrecorded`. A served model that is not the routed model, compared through one matcher in `lib/host/model-map.mjs` so an alias against its full id raises nothing, banners `MODEL SUBSTITUTED: <label> routed <slug>, ran <ids>`; one verdict reads turn-scoped models (an agent's own transcript) where it has them and the session-scoped per-model breakdown, which also lists host-internal calls, only as a weaker fallback. The permission files banner `PERMISSION PROMPTS DURING RUN: <n>` and `AUTO MODE DENIED <n> TOOL CALLS`, counts the reader interprets, never a verdict.
- **The claude adapter reads the whole envelope, whatever the exit code** (Brief 5). `readClaudeEnvelope` returns a host record beside `result` and `usage`: subtype, error flag, bounded errors, permission denials with their tool names, session id, turn count, the session-scoped models from the per-model breakdown, the turn-scoped models read from the lane's own session transcript, and the client-side cost estimate kept apart from `MODEL_PRICES` dollars. The runner forwards host records to the CLI on their own channel, `--host-records`, beside the agents' own results, and the CLI decides at the record paths: `LANE STOPPED BY HOST: <label> <subtype>`, `SCHEMA RESULT MISSING (claude): <label> — success without structured_output (anthropics/claude-code#82258)`, `TOOLS DENIED IN LANE: <label> <n> (<tools>)`, and the same `MODEL SUBSTITUTED` with the same words.
- **A new trajectory event, `agent-result`**, records what the host observed about a spawn after it returned: on the runner from the host record, on the Workflow host from the join at close. It is written on the CLI's existing record paths, so it inherits the fatal class of every other trajectory append.
- **The resume card lists each failed lane's session id** with `claude --resume <id> --fork-session`, saying the transcript may be gone after the host's retention period or because the session was deleted.
- **Bare-proofing and the prompts the runner must never wait on.** The adapter passes `--permission-prompts none` when the permission mode is not `bypassPermissions` and the one-time `--help` probe lists the flag; a pinned test asserts it never passes `--no-session-persistence` and always passes `--plugin-dir` when the checkout is the plugin; `interlock doctor` gains a `claude-bare` row that reports, as advice and never as a failure, whether a bare `-p` would have a credential to run on. The agents-file workaround for #82258 is a probe, adopted only if it returns `structured_output`; the probe could not be run in the implementing session, so it is not adopted.
- **Corpora live in the state home** (Brief 6). New `lib/state-home.mjs` resolves the main checkout from `git rev-parse --git-common-dir` when the working root is a linked worktree, ignores Interlock's own lane worktrees, falls back to the root with `STATE HOME UNRESOLVED: <reason>` on any git failure, and is overridden by an explicit `--state-home <dir>` or `INTERLOCK_STATE_HOME`. Append-only corpora keyed by run go there: trajectories, outcome lines, review metrics, resume cards, interrupted-run notes and the autonomy ledger. Per-run working state stays in the working root: the manifest, the wave state, briefings, spill, the stage marker, the launch ledger and the agent-usage sidecar. Loss semantics are kept exactly: a failed trajectory append in the state home still exits 1; an outcome or metrics write failure still only reports.
- **Inputs read through, and the drivers stop probing them.** `run start` locates the test profile and the graph in the working root first and the state home second, banners `TEST PROFILE FROM MAIN CHECKOUT` and `GRAPH FROM MAIN CHECKOUT` (the graph banner says it may be stale for this worktree), and records the resolved profile path on the manifest for every later reader, including the test guard. `interlock-graph` reads the state home's graph when the root has none and says so. The Workflow driver's validate ping loses its two `test -f` lines, so the CLI and the driver cannot disagree about whether a profile exists.
- **The run records its surface, and the report partitions by it.** `run start` records `surface` (`main`, `linked-worktree`, `lane-worktree` or `unknown`) and `stateHome` on the manifest, the `run-start` event and the receipt; the close summary prints a `state home:` row when it differs from `cwd`; `interlock report` reads every corpus from the state home, says how many runs in its window came from each surface, and counts the trajectories recorded in other linked worktrees that it did not read. `interlock doctor` gains a `state-home` row and probes each state directory where that directory now lives. A `cloud` surface waits on verification of `CLAUDE_CODE_REMOTE`.

No breaking change: every new manifest, trajectory and receipt field is additive, old records read as unrecorded, and a root that is a main checkout resolves to itself, which is today's behaviour byte for byte.

## Capabilities

### New Capabilities

- `hooks/agent-recorder`: the recorder's subagent and permission branches. What the `SubagentStart`, `SubagentStop`, `PermissionDenied` and `PermissionRequest` branches write, where, under which gate, with what join key, and the guarantees that they never block, never write the trajectory, and leave an unparseable transcript unrecorded rather than zero.
- `ship/agent-results`: what the run records about each agent after it returned. The `agent-result` trajectory event on both hosts, the briefing-sha join of recorded usage to dispatched spawns, the observed `hook` cache accounting and the `CACHE ACCOUNTING PARTIAL` rule, the one model matcher and the `MODEL SUBSTITUTED` banner, the runner's host-record channel and its three banners, the permission counts, and the receipt fields these add.
- `ship/state-home`: where corpora live when the working root is a linked worktree. The resolution rule and its fallback, the lane-worktree exclusion, the explicit override, the split of paths by kind, the read-through of the test profile and the graph with their banners, the recorded surface, the preserved per-corpus loss semantics, and the doctor row.

### Modified Capabilities

- `hooks/session-recorder`: modifies "The recorder SHALL never block, and SHALL be registered and tested as a process" so the registration and process tests cover all five events the one recorder file dispatches on, and so the interrupted-run note is written under the state home the manifest names.
- `run-host-adapters`: modifies "Cache accounting SHALL be a separately declared host capability" so the capability admits an observed `hook` value that `run close` alone may set; adds requirements that the claude adapter reads the whole envelope whatever the exit code and reports a host record, that the runner forwards host records on their own channel, that `--permission-prompts none` is passed only behind the help probe and outside bypass mode, that `--no-session-persistence` is never passed and `--plugin-dir` always is when the checkout is the plugin, and that the agents-file workaround ships only on a passing probe.
- `ship-run`: modifies "Event types cover a reconstructable walk" to add `agent-result` with its fields; modifies "A host without cache accounting SHALL record unknown, not zero" to cover hook-observed accounting and partial coverage; adds that the `run-start` event and the receipt record the surface, the state home and the working directory.
- `ship/run-program`: adds that `run start` locates the test profile and the graph through the state home, banners each read-through, and that no driver probes them; adds that a `run` subcommand reads its corpora from the state home the manifest recorded, and that a missing manifest is named beside the state home's manifest when one exists there.
- `ship/halt-resume-card`: modifies "The card SHALL carry what a reader with no context needs, and SHALL state each absence" to add the failed lanes' session ids with the resume command and the two reasons a transcript may be gone; modifies "A halted close SHALL write exactly one resume card" so the handoff directory is the state home's.
- `ship/close-summary`: modifies "The summary SHALL name the run and where it closed" to add a `state home:` row whenever it differs from the `cwd:` row.
- `report/indicators`: modifies "Corpus coverage is reported before any indicator" to add the per-surface run counts and the count of trajectories left unread in other linked worktrees.
- `report/corpus-reading`: adds that the reader resolves every corpus through the state home and reports the resolution it used.
- `hooks/session-preflight`: adds the `state-home` doctor row, the `claude-bare` doctor row (advice, `ok` or `skip`, never `fail`), that the state-directory probe follows each directory to the home it now lives in, and that the preflight reads interrupted-run notes from the state home the doctor resolved.
- `hooks/tool-guards`: adds that the test guard reads the test profile the run manifest names when the working root has none, so a linked-worktree run keeps its profile-derived test roots.
