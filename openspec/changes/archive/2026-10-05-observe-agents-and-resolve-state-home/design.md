## Goals / Non-Goals

**Goals:**

- Make the Workflow host's cache figures and served models observable through hooks, with the join and every verdict in the CLI, and keep the settings-hook form replaceable by a mod without changing the join.
- Give every runner lane failure a name the CLI decides from what the host reported, and record the host's own observation as a trajectory event on both hosts.
- Put every append-only corpus of a linked-worktree run where `interlock report` in the main checkout reads it, leave every per-run working file where the run is, and say which is which on every surface that prints a path.
- Settle the one model matcher, the one state-home resolver and the one host-record channel so neither host grows a second copy.

**Non-Goals:**

- Attributing the Workflow runtime's output-token counter per agent; the runtime's figure stays the wave's aggregate and the transcript's output tokens are recorded per agent beside it, not substituted for it.
- Resuming a lane, capping spend, or reading the stream-json form of the envelope; each is a later change that reads what this one records.
- Writing anything settings-class into the main checkout; the state home receives corpora only, and the test profile and graph are read through, never copied.
- Classifying cloud sessions; `surface` has no `cloud` value until `CLAUDE_CODE_REMOTE` is verified.

## Decisions

### D1 — Four recorder branches behind one gate, with no subprocess

`hooks/recorder.mjs` gains `SubagentStart`, `SubagentStop`, `PermissionDenied` and `PermissionRequest` branches in its existing `BRANCHES` table. All four share one gate, evaluated in this order and exiting before any write when it fails: `readStage({ root })` returns a live marker (the pid liveness rule the guards use); `.claude/ship/run.json` parses and carries a string `runId`; for the two subagent events, `event.agent_type` is exactly `workflow-subagent`, re-checked in the hook although the registration carries the anchored matcher `^workflow-subagent$`, because an internal agent reports the session's `--agent` name or an empty type and must write nothing. The permission branches are registered without a matcher and take the same gate.

*Amended by task 1.1.* The brief and the first draft of this decision anchored on `^interlock:(worker|ping)$`. The probe shows the host reports `workflow-subagent` for every agent a workflow script spawns, whatever `type` the script named: a real `/interlock:ship` ping spawned with `type: 'interlock:ping'` on the 2.1.289 Desktop engine recorded `SubagentStart:workflow-subagent` and `agentType: "workflow-subagent"` in its metadata, and an untyped `agent()` on the 2.1.274 CLI sent `agent_type: "workflow-subagent"` on all three captured payloads. The plugin-type matcher would never have fired on the host the sidecar exists for. A plugin agent type reaches a subagent event only as an internal agent of a `claude --agent interlock:worker` session, which is exactly the case the re-check excludes; the runner's lanes report through their envelope and transcript (D7) instead. The wider matcher admits every workflow agent in the root while a run is live, the relay pings and any unrelated workflow included; the join (D5) is what decides which of them belong to a briefed spawn, and the rest are counted, never attributed. No branch spawns a process, runs git, or reads the trajectory. Each performs at most one `mkdirSync` and one `writeFileSync`, swallows its own throw to a stderr line, prints nothing on stdout and exits 0.

*Alternative considered.* A `PreToolUse(Read)` hook that binds the briefing to the agent id at the moment it reads its briefing file: rejected by the brief, because it would run a node process on every Read in every session with the plugin installed.

### D2 — The sidecar is one small file per key, set-shaped, outcome-class, in the working root

`lib/agent-usage.mjs` (new) owns the sidecar: `AGENT_USAGE_DIR = .claude/ship/agent-usage`, `agentFilePath(root, runId, agentId)`, `permissionFilePath(root, runId, kind, at, pid, seq)`, `writeAgentStart`, `writeAgentStop`, `writePermissionEvent`, `readAgentUsage(root, runId)` → `{ agents, permissions, unreadable }`, every function collapsing failure to a value. An agent file at `<root>/.claude/ship/agent-usage/<runId>/<agentId>.json` carries `{ schema: 'interlock.agent-usage/1', agentId, agentType, startedAt, stoppedAt, briefingSha, models, turns, usage, transcript: { path, parsed, reason } }`, where `usage` is `null` or `{ inputTokens, outputTokens, cacheReadInputTokens, cacheCreationInputTokens }` and the last is `{ ephemeral_5m, ephemeral_1h }` when the transcript split the tiers, `{ total }` when it carried only a total, or `null`. A permission file at `<root>/.claude/ship/agent-usage/<runId>/permission-<denied|request>-<stamp>-<pid>-<seq>.json` carries `{ schema, kind, at, agentId, tool, reason }`, each field copied by name and bounded to the trajectory's text bound, never the tool input and never the host's permission suggestions. `reason` is `null` when the event carries none: the captured `PermissionRequest` (task 1.1) carries `tool_name`, `tool_input`, `permission_suggestions`, `permission_mode`, `agent_id` and `agent_type` and no reason, and the documented `PermissionDenied` carries one. The agent id and the run id are admitted as path segments only when they pass the trajectory's safe-id rule.

Whole-file writes, never a JSONL append, so that the Brief 9 mod, whose `$.fs.write` replaces a file and cannot append atomically, can write the same files and the join below does not change. `SubagentStart` writes only when the file is absent, which is the dedup across the resume and teammate-message firings the host documents; `SubagentStop` replaces the file with the summed figures. The directory lives in the working root because it is per-run working state read back by `run close` in the same root, like `state.json`; it is never deleted, like the interrupted notes, and `STATE_DIRS` names it as non-fatal in the root. A failed write is a stderr line, never an exit code.

### D3 — Transcript summing, the model list and the join key

`summarizeTranscript(text)` in `lib/agent-usage.mjs` is pure and reads the transcript as JSON Lines, skipping any line that does not parse and reporting the count skipped. A turn is one assistant message, not one line: the host writes one `assistant` line per content block (thinking, text, each tool call) and repeats the request's `message.usage` on every one of them, with the final output count only on the last (task 1.1: three lines of one `message.id` carried input 12657 and cache creation 76248 each, and output 7, 7 and 255). So assistant lines whose `message.usage` is an object are grouped by `message.id`, else `requestId`, else the line itself, and the last line of each group is that turn's usage. Each turn contributes `input_tokens`, `output_tokens` and `cache_read_input_tokens` as finite non-negative numbers, and cache creation as `cache_creation.ephemeral_5m_input_tokens` and `cache_creation.ephemeral_1h_input_tokens` when `cache_creation` is an object, else `cache_creation_input_tokens` into `{ total }` with the tier split unknown. A field one turn omits makes that figure `null` for the agent, never zero, the same rule `foldCacheUsage` holds one level up. A transcript with no contributing turn yields `usage: null` with a reason. `turns` is the number of groups. Models are the distinct `message.model` strings over the turns, excluding the host's `<synthetic>` placeholder, bounded to eight. The join key is the last match of `/Expected sha256: ([0-9a-f]{64})/` in the `user` lines that precede the first `assistant` line, read from string content or from text blocks, `null` when absent, which is every ping. Last and not first, and every pre-assistant user line and not only the first, because the 2.1.289 engine relays the user's own request as a first harness turn and puts the computed task, indented, in a second; the bootstrap's sha line is the last line it writes. Tool results are `user` lines too, which is why the search stops at the first assistant line: an agent that reads a file carrying the bootstrap text must not rejoin itself to another spawn. A test pins the pattern against `test/fixtures/prompts/bootstrap.txt`, so a reword of the bootstrap text that moves the sha fails the recorder's test rather than silently unjoining every agent. The line shape is pinned by the real transcript captured in task 1.1 and scrubbed, and by a hand-built variant of the 2.1.289 harness wrapping.

The same function summarizes a runner lane's own session transcript (D7), so one reader of the transcript format exists in the codebase, not two.

### D4 — Dispatched spawns are the join table

`finishStep(ctx, manifest, step)` pushes `{ wave, label, kind, model, sha }` onto `manifest.dispatched` for every spawn on the step it finishes, lane spawns included, with `wave` from the step and `sha` the spawn's `promptSha256`. It is the one place every step passes through, and `logSpawns` already walks the same list there. The list is bounded by the published step cap times the batch width, so it needs no cap of its own. Relay pings are driver plumbing with no briefing and never appear in it.

### D5 — The join at close, the partial rule, and the observed `hook` value

At `run close`, when `<root>/.claude/ship/agent-usage/<runId>/` exists, the close reads it and joins each agent file whose `briefingSha` equals a dispatched spawn's `sha`. Per wave, the denominator is the dispatched spawns of that wave that carry a sha. A wave where every one joined with a non-null usage gets `cacheReadInputTokens` and `cacheCreationInputTokens` summed over its agents under the unknown-contagious rule (a tier one agent reports as `{ total }` makes the wave's tiers unknown and its total known); one spawn with no joined file, or a joined file with `usage: null`, leaves that wave's cache figures `null`. The close banners `CACHE ACCOUNTING PARTIAL: <n> of <m> agents unrecorded` when at least one dispatched, briefed spawn did not join, and notes `AGENT USAGE UNJOINED: <k> recorded agents matched no dispatched spawn (<p> without a briefing key, <q> with a key no spawn dispatched)` for files with no sha at all (the relay pings, and any other workflow the matcher of D1 admitted) or a sha nobody dispatched, which are then counted nowhere. The split is in the text because the two halves mean different things: the first is expected on every Workflow run, the second is an anomaly. When the directory is absent the close says `CACHE ACCOUNTING NOT REPORTED` exactly as today.

Precedence per wave: a cache figure the host observed through `--host-observed` wins where present (the Workflow driver reports none today), then the join, then the figures `recordUsage` counted off the results. Output tokens are untouched by the join: the runtime's counter sees the orchestrator's turns, and the receipt's caveat already says the output figure is the wave's aggregate. The agents' own output tokens travel on the `agent-result` events (D8) for a later per-agent reader.

`CAPABILITY_VALUES.cacheAccounting` becomes `[true, false, 'hook']`, with the comment that `hook` is observed only: no adapter may declare it, `test/spine/host-registry.test.mjs` asserts both the widened set and that every `HOSTS` entry still declares a boolean, and `run close` sets `manifest.host.cacheAccounting = 'hook'` only when the declared value is `false` and every briefed spawn of every wave joined with a usage. The `CACHE ACCOUNTING NOT REPORTED` condition stays `=== false` and adds one clause, that no joined agent recorded usage: a complete join silences it through the refinement, a partial join silences it because its text — every wave's figures unknown — would be false where some waves have figures, and `CACHE ACCOUNTING PARTIAL` speaks instead; a sidecar with no usable agent keeps it. The cache half of the join applies only to a host that declared `false`: on a host that reports its own figures a lane is a top-level session no subagent hook sees, and a sidecar holding only a permission file must not read as every lane unrecorded. `hostBlock.cacheAccounting` in `lib/run-log.mjs` coerces to `true`, `false`, `'hook'` or `null`, so an old receipt's boolean reads exactly as before and a reader partitions "figures obtainable" as `true` or `'hook'`.

*Alternatives considered.* A boolean `cacheAccounting` beside a separate `cacheAccountingSource` field: two fields for one fact, and every reader of `hostCapability(manifest, 'cacheAccounting')` would need the second lookup. Joining at each record path instead of at close: the sidecar for a lane is complete only after its `SubagentStop`, which may land after the record path has run, and a close that reads everything once is simpler to make fatal-correct.

### D6 — One model matcher, and every reader of it

`modelMatches(routed, served)` in `lib/host/model-map.mjs` is the only comparison of a routed model against a served one. It lowercases both, splits each on runs of non-alphanumerics, drops every token before the first `claude` token (a provider prefix such as `bedrock.`), drops a trailing token of exactly eight digits (a date stamp), and then: when the routed value is a bare tier slug (`haiku`, `sonnet`, `opus`), it matches when the served token list contains that token; otherwise it matches only when the two token lists are equal. An empty served list is `null`, a comparison that could not be made, and raises nothing. So `sonnet` matches `bedrock.claude-sonnet-5-5` and `claude-sonnet-4-5-20250929`, `claude-sonnet-5-5` matches `claude-sonnet-5-5-20261001`, `claude-sonnet-5` does not match `claude-sonnet-5-5`, and `sonnet` does not match `claude-opus-5-5`.

**Two observations, one verdict.** The matcher compares; what it is fed decides what a mismatch means, and the two sources do not mean the same thing (task 1.1). An agent's own transcript names the model of every assistant turn it took: a *turn-scoped* observation, `servedModels`. The `claude -p` envelope's per-model breakdown, `modelUsage`, names every model the session called, and every captured envelope listed a host-internal haiku call (about 1.2k input and 14 output tokens, on a one-turn run that used no tool) beside the session's own model: a *session-scoped* observation, recorded as `sessionModels`. Comparing session-scoped models with "any unmatched raises" would banner every runner lane not routed to haiku.

So `modelSubstitution(routed, { servedModels, sessionModels })` in `lib/run.mjs` is the one verdict, and it reads the strongest observation present: with `servedModels` known, the spawn is substituted when any served model fails the match, because a fallback that served one turn is still a model the plan did not choose (Brief 5 decision 6); with only `sessionModels` known, it is substituted when none of them matches the routed model, because a host-internal call and a partial fallback cannot be told apart there, and only a lane the routed model never served is established; with neither, or no routed model, it returns `null` and raises nothing. It returns `{ substituted, scope: 'turns' | 'session' | null, ran }`, `ran` being the ids the banner lists: every served id on the turn scope, every session id on the session scope.

This is an invariant with more than one reader, so the readers are enumerated here and asserted: (1) `run close` on the Workflow host, comparing each joined spawn's dispatched `model` against the transcript's models, always turn-scoped; (2) the record paths on the runner host, comparing each host record's `modelRouted` (the value the adapter sent after the map, carried on the record) against the lane's `servedModels` when the adapter read the lane's transcript and its `sessionModels` otherwise; (3) nothing else compares models, and `test/spine/host-adapters.test.mjs` sweeps `lib/` and `bin/` for a second comparison by asserting `modelMatches` is called only from `modelSubstitution` and `modelSubstitution` only from the two sites named. Both readers raise one text, `MODEL_SUBSTITUTED(label, routed, ran)` in `lib/run.mjs`, so the two hosts print the same words. A spawn with no model (the planner, a ping) is compared against nothing. The `agent-result` event carries `servedModels`, `sessionModels` and the verdict's scope, so a reader can always see which evidence a banner stood on, and every id the session called, not only the ones that decided.

*Alternatives considered.* Plain equality: a false banner on every lane, because the adapter routes `sonnet` and the host serves `claude-sonnet-5-5`. A prefix match: misses the provider prefix. A fuzzy match: a guess, and a wrong model that ran would be invisible, which is the failure the banner exists to name.

### D7 — The runner's host record travels on its own channel

`readClaudeEnvelope(stdout, { exitCode, timedOut })` returns `{ result, usage, host }`, and `host` is always an object: `{ parsed, subtype, isError, terminalReason, errors, permissionDenials: { count, tools }, sessionId, numTurns, sessionModels, servedModels, hostCostUsd, exitCode, timedOut, resultMissing }`, each field copied by name from the envelope and bounded (`errors` to `MAX_AGENT_ERRORS = 10` entries of the trajectory's text bound, a record-shape bound kept in `lib/run-log.mjs` beside `MAX_PATH_SET` for the reason stated there, not a policy cap). `sessionModels` is the key list of the envelope's per-model breakdown, `modelUsage` (keys like `bedrock.claude-sonnet-5`, pinned by the task-1.1 captures), absent when the envelope omits the breakdown; `hostCostUsd` is `total_cost_usd`, labelled a client-side estimate and never added to `MODEL_PRICES` dollars, which no code path in the ship loop reads. The non-zero exit path in `spawn()` now parses stdout before returning `null`, and both `spawn-done` and `spawn-failed` carry `host`. `resultMissing` is `subtype === 'success'` with exit 0 and no `structured_output`.

`servedModels` is filled by the adapter, not the envelope: after the process exits, `readLaneTranscript({ cwd, sessionId, env })` reads the lane session's own transcript at `<config>/projects/<projectSlug(realpath(cwd))>/<sessionId>.jsonl`, where `<config>` is `CLAUDE_CONFIG_DIR` when set and `$HOME/.claude` otherwise, and summarizes it with `summarizeTranscript` (D3). `servedModels` is that summary's models, turn-scoped (D6); it is `null` with `transcriptReason` when the session id is not a safe path segment, the file is absent, or it holds no assistant turn. The location is the one the 2.1.274 probe observed (`transcript_path` on all three captured payloads), the slug is `lib/project-slug.mjs`'s, which the close summary already prints, and the file exists because the adapter never passes `--no-session-persistence` (D10). The read is observation only, never a verdict, and a lane whose transcript cannot be read still has its `sessionModels`, so the verdict degrades to the session scope rather than to nothing.

`bin/interlock-run` collects `{ label, ...host }` from those events per step into `${WORK}/host-records.json` and passes `--host-records <file>` on every continuation argv beside `--results`; `bin/interlock` reads it with `readInput` on the same subcommands that read `--results` and hands `hostRecords` to the run function. The Workflow driver passes none. Results and host records stay apart on purpose: a result is the agent's report and a host record is the host's observation, the provenance split `ship/outcome-provenance` already draws for the receipt, and a `null` result still means what it means today.

*Alternatives considered.* Returning `{ host, result: null }` from a failed spawn: `laneOutcomes` would fail every task with "lane result carried no per-task outcomes" instead of the host's reason, and the spawn result's schema would carry a field that is not the agent's. Spreading `host` into a successful result beside `usage`: the same provenance mix, and a strict consumer of the step's schema could refuse it.

### D8 — The `agent-result` event, on both hosts, in the fatal class

`RUN_LOG_TYPES` gains `agent-result` with `TYPE_FIELDS`: `label`, `kind`, `agentId`, `source` (`envelope` | `transcript`), `subtype`, `isError` (tri-state), `terminalReason`, `errors`, `permissionDenials` (`{ count, tools }`, counts nullable), `sessionId`, `numTurns`, `modelRouted`, `servedModels`, `sessionModels`, `modelScope` (`turns` | `session` | null, D6), `substituted` (tri-state), `resultMissing` (tri-state), `usage` (the four figures, nullable, tiers kept apart), `hostCostUsd` (nullable). On the runner host the CLI appends one per host record on the record path that received it, before the tick, through `appendRunLogEvent`, and a failed append halts that step exactly as a failed `agent-spawn` append does. On the Workflow host the close appends one per joined agent before the receipt, and a failed append sets `trajectoryComplete = false` and the exit code exactly as a failed receipt append does. `RUN_LOG_SCHEMA` stays `interlock.ship-run/1`: the type is additive, the readers skip what they do not know, and `test/spine/run-log.test.mjs` pins that a pre-change trajectory still lists, checks and renders.

The receipt gains six nullable counts, copied by name: `lanesStoppedByHost`, `schemaResultsMissing`, `toolsDeniedInLanes`, `modelSubstitutions`, `permissionPrompts`, `autoModeDenials`, plus `surface` and `stateHome` from D14. Each is `null` when no host record and no sidecar was ever seen, and a measured zero otherwise.

### D9 — The CLI decides the runner's banners at the record path

`recordSpawnObservations(ctx, manifest, { results, hostRecords, wave })` replaces the bare `recordUsage` call at every record path and does both. For each host record it pushes onto `manifest.banners`: `LANE STOPPED BY HOST: <label> <subtype>` when the exit was non-zero or `isError` is true, with the subtype or `exit <code>` when the envelope named none; `SCHEMA RESULT MISSING (claude): <label> — success without structured_output (anthropics/claude-code#82258)` when `resultMissing`; `TOOLS DENIED IN LANE: <label> <n> (<tools>)` when the denial count is positive; `MODEL SUBSTITUTED` through D6. It stores `manifest.laneSessions.push({ label, sessionId, outcome })` for the resume card and increments the receipt counts. `manifest.banners` already carries to the close, so a halted run prints them too. A lane with no host record (another host, a Workflow run) raises nothing and counts nothing: absence stays unknown.

### D10 — Flags behind the probe, and the two pins

`probeEffortFlag` becomes `probeHelpFlags`, one `--help` run answering `{ effort, permissionPrompts }` with the same option-line test (`^[ \t]*(?:-x,[ \t]*)?--permission-prompts(?=[\s=<[]|$)`), so the adapter's one-time probe stays one spawn. `claudeArgs` takes `permissionPrompts: 'flag' | 'unsupported'` and pushes `--permission-prompts none` only when it is `flag` and the permission mode is not `bypassPermissions`; the default mode is bypass, so the ordinary unattended run passes nothing new. When the mode is not bypass and the flag is unsupported, the host banners once, `PERMISSION PROMPTS NOT SUPPRESSED (claude): the installed CLI does not list --permission-prompts, so a lane that needs a person waits`, folded into the close through `--host-banners`. ### D13 — The state home resolver

`lib/state-home.mjs` (new) exports `SURFACES = ['main', 'linked-worktree', 'lane-worktree', 'unknown']`, `STATE_HOME_ENV = 'INTERLOCK_STATE_HOME'`, `LANE_WORKTREE_SEGMENTS` derived from `LANE_WORKTREES_DIR` and `resolveStateHome(root, { explicit, env, exec, realpath })` → `{ home, surface, reason, resolvedFrom: 'explicit' | 'git' | 'lane' | 'fallback' }`. In order:

1. `root` is made absolute and passed through `realpathSync` when it exists (macOS keeps `/tmp` behind a symlink, and git reports realpaths); a root that does not exist resolves to itself with surface `unknown` and a reason.
2. If the root's path segments contain the sequence `.claude`, `ship`, `worktrees`, the root is one of Interlock's own lane worktrees: `home` is the root, surface `lane-worktree`, no git call. A path-segment test rather than a marker file, because `laneWorktreePath` is the one derivation of that path and a lane that lost a marker would otherwise be misread as a session.
3. `git rev-parse --path-format=absolute --git-dir --git-common-dir` through `execFileSync` with `stdio: ['ignore', 'pipe', 'ignore']` and a ten-second timeout, retried without `--path-format=absolute` and resolved against the root when git rejects the option (git before 2.31). If the two paths are equal the root is a main checkout: `home` is the root, surface `main`. If they differ, the candidate home is the common directory's parent; it is accepted only when `git -C <candidate> rev-parse --is-inside-work-tree` prints `true` (a bare repository's common directory has no checkout beside it) and the candidate is not itself under the root. Then `home` is the candidate, surface `linked-worktree`.
4. Any failure, a missing git, a directory that is not a repository, a timeout or a candidate that fails the check collapses to `home` = root, surface `unknown`, with the reason, and the caller banners `STATE HOME UNRESOLVED: <reason>`.
5. An `explicit` value (the `--state-home` flag, else `INTERLOCK_STATE_HOME`) replaces `home` after the surface is known, so the surface still describes the session; `resolvedFrom` says `explicit`.

`exec` and `realpath` are injectable so the failure branches are tested without a real failure; the happy paths are tested against real `git worktree add` fixtures under a temporary directory. Nothing is written by the resolver.

### D14 — `--state-home` beside `--root`, resolved once per run, recorded everywhere a path is printed

`--root` keeps its meaning, the working tree the run operates on, and a new `--state-home <dir>` (env `INTERLOCK_STATE_HOME`) pins the corpora home. The brief proposed that an explicit `--root` disables resolution, but `bin/interlock-run` passes `--root .` on every call, so that rule would turn the resolver off on the host most likely to run in a worktree; a flag that names what it does costs one line of help and gives a user per-worktree corpora with `--state-home .`.

`run start` resolves once and records `manifest.stateHome` (absolute), `manifest.surface` and `manifest.stateHomeReason`; every later `run` subcommand reads `manifest.stateHome` and never resolves again, so one run uses one home even when git state changes under it, and a manifest without the field (a run started on the previous version) uses the root, which is that run's existing behaviour. Readers that have no manifest — `report`, `run-log`, `outcomes`, `review --metrics`, `evals capture`, `autonomy`, `doctor`, `interlock-graph` — resolve per invocation through one helper in `bin/interlock`, `corpusHome(root, flags)`, which prefers a manifest's recorded home at the root when one exists, then the explicit value, then the resolver. `wave-state` and `verify judge`, which append trajectory events from a lane's or a ping's shell, go through the same helper. `lib/run.mjs` reads the home through one accessor, `stateHomeOf(ctx, manifest)`, and every corpus call in it takes that value: `appendRunLogEvent`, `appendOutcome`, `writeResumeCard`, `readInterruptedNotes`, `markSpoken`, `checkRunLog`, `recordAutonomy`. `ctx.root` keeps naming the working tree for the manifest, the state, the briefings, the spill and the marker.

Printed and recorded: `run-start` gains `surface`, `stateHome` and `cwd` (the absolute working root, bounded like every other text field; the summary already prints `cwd`, so nothing new leaves the machine); the receipt gains `surface` and `stateHome`; the close summary prints `  state home: <path>` directly under `cwd:` whenever the two differ, and nothing when they are equal, so a main-checkout run's summary is byte-identical to today's; `run start` notes `CORPORA IN MAIN CHECKOUT: <home> — the trajectory, outcome line, metrics and resume card of this run are written there, not in this worktree` on a linked worktree, and `STATE HOME UNRESOLVED` on a fallback.

## Risks / Trade-offs

- [`SubagentStop` does not fire for Workflow `agent()` spawns, or fires with no readable transcript] → the usage half shrinks to the permission half (the proposal's scope decision), `CACHE ACCOUNTING NOT REPORTED` stands, and D3 to D5 are implemented only as far as the permission files and counts; task 1.1 decides this before any join code is written, and the result is recorded under Open Questions.
- [The transcript carries only a cache-creation total, not the tier split] → recorded as `{ total }`, the wave's tiers are unknown and its total is known, and the receipt prints it as such; nothing is invented.
- [A briefed spawn's transcript lacks the bootstrap text verbatim] → its file has no sha, the wave is partial and says so; the pin against `bootstrap.txt` catches the plugin's own reword, and the capture catches the host's.
- [The join runs at close, so a run that never closes records no `agent-result`] → the sidecar files stay on disk under the run id, and a later reader can join them; the interrupted-run note already names such a run.
- [An extra process per `SubagentStart`, `SubagentStop` and permission event in every session with the plugin installed] → each exits at the first gate check, before any filesystem write, when no live marker exists; the cost outside a ship run is one process start and one `readdir`.
- [The vendor's envelope field names differ from the docs] → the parser follows the task-1 capture, which is pinned as a fixture; the adapter's wire is a fixture, not a memory.
- [`--permission-prompts none` changes a lane's behaviour in a non-bypass mode] → it is exactly what an unattended run wants, and it is passed only when the operator chose a non-bypass mode and the CLI lists the flag; the brief's `PERMISSION PROMPTS NOT SUPPRESSED` banner covers the CLI that does not.
- [The agents-file probe passes on 2.1.274 and fails on a later CLI] → the adapter still passes `--plugin-dir` and the named failure stays the mitigation, so the worst case is today's behaviour with a name.
- [A linked worktree whose main checkout is read-only] → the fatal trajectory append fails at the first wave-state append and the run halts naming it, as a read-only checkout does today; `doctor` now probes the directory where it lives and says so before the run.
- [The resolver's realpath differs from the path the operator typed] → paths are recorded as resolved and the summary prints both `cwd` and `state home`; a test covers a symlinked root.
- [The state-home scan of other worktrees counts a stale worktree git still lists] → counts only, with the worktree path, and `git worktree prune` is the operator's remedy; nothing is opened or deleted.
- [Two sessions on two surfaces start the same change at once] → the marker, the manifest and the ledger are per root, the corpora are append-only, and the second run's trajectory file has its own run id; this was possible before this change too, in two clones.
- [`GRAPH FROM MAIN CHECKOUT` reads a graph built before this worktree's edits] → the banner says it may be stale, and a lane that wants a current graph builds one in the worktree, which the resolver then finds first.

## Migration Plan

Additive everywhere. The manifest gains `dispatched`, `laneSessions`, `stateHome`, `surface`, `stateHomeReason`, `testProfilePath`, `testProfileSource`, `graphPath` and `graphSource`; an older manifest reads them as undefined, resolves its corpora to the root and raises no new banner. `RUN_LOG_TYPES` gains a type and three event shapes gain fields, under the same schema id; old trajectories list, check and render as before, and `test/spine/run-log.test.mjs` pins that. `CAPABILITY_VALUES.cacheAccounting` gains a value no adapter declares. The `claude` adapter's argv changes only under a non-bypass permission mode on a CLI that lists the new flag, and the agents file only on a passing probe. A main-checkout run resolves its state home to itself, so every path it writes is the path it wrote yesterday. Rollback is reverting the commit; the only state a reverted version would not read is the sidecar directory and the new fields, which nothing depends on.
