# Design

## Context

See proposal.md for the findings. What shapes the approach:

- The directory's reader is not inspectable. The local `claude plugin validate` reader (2.1.319) is AST-based and follows `$` into nested closures, printing `$.ui.notify (via tell)` without objection; none of the nine finding codes is in the binary. The finding's own text is the only rule we have (`MOD_CAPABILITY_USE_NOT_PLAIN` in `claude-submissions.png`): `$` as `$.noun.method(…)` or passed whole to a function declared at the top of the file, nothing wrapped around its parts ("no parentheses, cast, `!`, `?.` or square brackets"), each `on("event", hook)` on its own line. The directory accepts `(await $.session.version()).version` at 2763, so parentheses around a whole call are not "around its parts".
- Four named closure bindings in `hooks/mod.mjs` read `$`: `send` in `tell` (654, v1.15.0), `hide` in the `drawBand` hook (1972, v1.3.0), `flush` in `drawBoardCards` (2400, v1.3.1), `guardLine` in `drawPane` (2534, v1.4.0). The last three sat in every scanned version from 1.5.1 to 1.15.1 unflagged; only `tell`'s reach is flagged. `send` alone is `async`, is invoked unawaited under `void`, and calls `$.noun.method` directly inside a closure inside a followed helper.
- `prompt.autocomplete` loads from Claude Code 2.1.292, which is already `MODS_LOAD_MIN_VERSION` (`lib/host/claude-env.mjs:51-56`). The mods reference ("as of v2.1.290", read 2026-11-09) documents it; the directory's list predates it, and its remedy is to report the version. So a fixture of the reference alone would pass the event today: what the 1.15.1 scan accepted is the second list the pin needs. That scan recorded one unknown-event hook, at 3065, so it accepted the other ten hooked events.
- Nothing shipped sets a registry. `LAUNCHER_REGISTRY_REDIRECT` is a parser that could not read a package-manager command; four shipped strings use a short verb, a short option, a floating tag or an unversioned launcher (`lib/openspec-cli.mjs:51`, `lib/doctor.mjs:769-788`, `lib/run.mjs:2899`, `cli/interlock:1285`, `README.md:187`).
- Two unarchived changes already carry deltas for `hooks/ship-meter` and `distribution/npm-package`; this change only ADDs there and MODIFIES only `openspec-cli`, whose two requirements no other delta touches.
- The repo's test conventions: zero dependencies, `node --test`, static pins written as regex-plus-brace scanners with self-tests (`renamedHookReach`, and `networkProblems` with its sibling shipped-text detectors in `test/spine/package.test.mjs`).

## Goals / Non-Goals

**Goals:**
- Each of the three validation findings has a unit test that fails on the 1.15.1 shape and passes after the fix, so a regression cannot ship unseen. Findings 1 and 3 clear on the next scan; finding 2 clears when the directory's event list holds `prompt.autocomplete`, which this change asks for and cannot force.
- The six policy refusals are replicated by a detector and held against a declared inventory, so their state is asserted and a later edition changes numbers, not code.
- No feature is removed and no runtime behaviour changes beyond printed strings.

**Non-Goals:**
- Satisfying the six policy refusals. Only a prose-only edition could, and D14 declines one for now.
- Reproducing the directory's reader. The pins encode the finding's stated rules and this repo's stricter in-house rule; the portal's Validate stays the verdict.
- Rewriting the lockfile's `resolved` URLs or the pin script (kept as the named fallback if finding 3 persists).

## Decisions

**D3 — `tell` becomes `async function tell($, fields)` with `send` inlined, rather than a hoisted `sendTell($, said)` helper.** Both remove the stored closure; only the inline form also removes the `void` call and keeps `ONE_CALL_SITES` (`'$.ui.notify('` inside `functionSource('tell')`, whose regex accepts `async`) and `ALLOWED_CALLS` unchanged. Behaviour holds: an async function runs synchronously to its first await, so the interactive check, the build, the once-check and the record happen before the engine is asked, and the four callers are expression statements that never await, which the notify "never settles" tests in `test/mod/interactive.test.ts` rely on. The doc comment's "never awaited" sentence is reworded to say the callers do not await.

**D4 — the `$`-shape pin refuses every named closure binding that reads `$`, with a frozen allow-list for `hide`, `flush` and `guardLine`.** Alternative: rewrite all four. Rejected for this change because the three have been accepted by the directory in twelve scanned versions, `flush` closes over five mutable locals and would need a state object, and the repro-first rule binds later tasks to the root cause. The allow-list carries the introducing version per entry and fails when an entry's binding no longer reads `$`, so it cannot go stale: an entry is stale when no `const|let|var` binding of that name exists, or when its brace-balanced body holds no `$` token. Fallback if the portal flags them: delete the entries and rewrite the three.

**Scanner shape.** A pure function over masked source (strings, template text, regex literals and comments blanked to spaces with offsets kept, the code inside `${…}` left readable): collect top-level function names from column-zero declarations; for each `$` token, accept `$` immediately followed by `.noun.method(` with nothing between the parts (no `?.`, `[`, `!` or `)`, so `($.ui).log(` is refused while `(await $.session.version()).version` passes), or `$` as a whole argument (newlines allowed) to a call whose callee is a top-level name, or `$` as a parameter of a column-zero declaration or as the first parameter of an `on(` hook in any of the module's forms (`async ($, e, next) =>`, `($, e, next) =>`, `async ($, e) =>`, `async function* ($, e, next)`); refuse everything else, `...$` and `const api = $` included; refuse any `const|let|var name = (async)? function|arrow` whose brace-balanced body holds a `$` token unless allow-listed; require every `on(` to be the first code on its line. A prototype of exactly these rules, run before the artifacts were finalised, named `send` alone on today's module, nothing once `send` was inlined, and exactly `hide`, `flush` and `guardLine` with the allow-list emptied. A `/` opens a regex literal when the previous significant token is `(`, `,`, `=`, `:`, `[`, `!`, `&`, `|`, `?`, `{`, `}`, `;` or `return`, or when it starts a line, and is division otherwise; a self-test holds a division beside a `$` use and a regex ending in `$`. Self-tests prove the refusals and acceptances the delta spec lists. It pins a spelling rule, not the reader's semantics, and says so in its comment.

**D5 — keep `prompt.autocomplete`; pin the documented-or-floored rule; record 2.1.292 in `docs/13` as the version to report.** Alternative: remove the hook, which goes red-then-green against a fixture of the directory's older list but deletes the D18 suggestions shipped 2026-11-07 (`lib/prompt-rows.mjs`, its tests, the delta requirement) and buys no listing while the mod is refused by policy. The fixture holds two dated readings, not truths: the mods reference's event list (as of v2.1.290, read 2026-11-09), which every hooked event must be in, and the events the directory's 1.15.1 scan accepted, outside which an event needs a `MOD_EVENT_FLOORS` entry and a docs line. A fixture of the reference alone could not go red, because the reference lists `prompt.autocomplete`. The floors table must stay at or below `MODS_LOAD_MIN_VERSION`, which is what keeps the mod from loading where the event is refused, and each entry must name a hooked event, so removing the hook later cannot leave a stale floor. When a later scan accepts the event, the owner adds it to the accepted list; the floor may stay, since it is still the engine's.

**D6, D7, D9 — rewrite all four package-manager strings and the usage example in long form; `--location=global`, not `--global`; `tsc --noEmit` with no launcher; leave the lockfile alone.** Attribution (per file or per import closure) is unknown, so every candidate is rewritten and the answer stops mattering. `--location=global` is the literal form of the remedy's `=` example and works on every npm shipped with Node 18 and later; `--global` is a bare boolean the remedy does not illustrate. `parseArgs` in `cli/interlock` has no `--key=value` form, so `=` joining applies to the package-manager commands only; the usage example keeps its meaning by dropping the launcher. The lockfile's `resolved` URLs name the default registry and do not match the remedy's wording; dropping them (`--omit-lockfile-registry-resolved`, `scripts/pin-openspec.mjs:122-124,213`, `test/spine/openspec-pin.test.mjs:46,91,125,145`) is the named fallback.

**D8 — `OPENSPEC_INSTALL` renders `OPENSPEC_PIN.version`, so the three skills, `README.md:44` and `docs/01-first-hour.md:24` change at each pin regeneration.** `test/skills.test.mjs` already imports the constant and requires the skills to contain it verbatim; a new package pin requires the README and first-hour quotes to equal the constant, so a regeneration cannot leave either stale. That pin passes today and keeps passing; it guards staleness, it does not reproduce the finding. D12: `README.md:187` names the package version, held by a new README CLI-line pin built from `package.json` (the one-version test reads only the three manifests). A version bump therefore also edits that README line, and `npm test` names it when a bump forgets.

**D10 — findings 4–9 are a detector plus a declared inventory, not `todo` tests.** A reported-but-passing red reads like the silent prose the repo warns against; an inventory asserts today's state and names drift with its code, and an edition empties it. The inventory is counts for hooks, modules and workflows, and declared places and grant paths for file types and tool grants, rather than file counts: a new module under `lib/` changes no number, while a script in an undeclared place or a grant from an undeclared skill is named by code and path, and a declared place that empties is named as stale. The detector follows each refusal's own text: hooks of every type count ("changing the type won't help"); a grant with a `${…}` path, a `//` or `\\` path or a URL counts as beyond the four; non-UTF-8 text, a NUL byte and package-manager configuration files count as file types; and a UTF-8 license, readme or `.gitignore` without `#!` is allowed, so `LICENSE` is not a declared place. Agent `tools` lists are counted although the text names skills and commands only: over-counting costs an edition one declared path, under-counting would surprise it at the portal.

**D16 — the two package-side detectors stay in `test/spine/package.test.mjs`.** The artifact gate suggested a file of their own. They sit beside `networkProblems` and its sibling shipped-text detectors, which share `shippedFiles`, `shippedTexts` and the same `problems()`-plus-self-test shape; moving them would mean first extracting those helpers from a 972-line test file in the red wave, a refactor no finding needs. Docs that do not ship (`docs/*.md`) are spelled long-form with the version as `@<version>` and "the plugin's version", as `docs/16` already does, so no unpinned docs line goes stale at a release; `docs/01-first-hour.md:24` is the exception, quoting `OPENSPEC_INSTALL` under the README pin.

**D13 — comment-only launcher mentions are reworded, not exempted.** The detector runs over every shipped text; an exception list is its weakest part, and the comments carry no behaviour. Each reword drops the launcher (`lib/doctor.mjs:1688` names `vitest run`, not `pnpm exec vitest run`). Test fixtures that spell `npm i -g` or `npx tsc` do not ship and stay.

**Where the command detector reads.** Only code: backtick spans (in Markdown and in comments), fenced block lines, and string or template literals in modules. A manager word followed by none of its commands or aliases is prose, and a launcher with no package token inside its span is bare. Read this way, prose such as "the npm install stays as the user's own route" (`lib/doctor.mjs:865`) and "npm users" is never a command, and no exception list is needed. A prototype of these rules over today's shipped set named exactly the files 1.2 lists.

**One install-command helper.** `cliInstallCommand(version)` in `lib/doctor.mjs` renders `npm install --location=global @renzrollon/interlock@<version>` for the doctor and the run program, so the spelling has one owner and the detector's dynamic-pin allow-list has one template for it.

**Pins that quote the old strings** (`test/spine/openspec-cli.test.mjs:96,388`, `test/spine/doctor.test.mjs:2060,2268`, `test/spine/run.test.mjs:9364`, the comment at `test/skills.test.mjs:606`) are updated in the task that changes the string they pin, never in remediation; each update names the requirement it now pins. Pins not listed here that break follow the same rule.

**D1, D2, D11, D14, D15** are recorded in `decisions.md`: Opus investigators at the owner's request over the routed model; scope is findings 1–3 fixed and 4–9 detected; "evals" means unit tests here, since no model behaviour is involved; no prose-only edition now; the owner sends the one message to the directory's maintainers after the portal confirms findings 1 and 3 cleared.

## Risks / Trade-offs

- [The directory's trigger for finding 1 is unproven: closure, `void`, unawaited async, or direct call in a nested closure] → the fix removes all four at once; the portal's Validate on a `npm run scan-pack` branch is the owner's by-hand step after the run; the fallback order is hoist `sendTell`, then drop the allow-list.
- [The allow-list is wrong and the directory flags `hide`, `flush` or `guardLine` next] → the pin already refuses them; the fix is deleting three entries and rewriting three closures, with `flush` needing a state object.
- [The events fixture and the engine disagree (`prompt.change`, `prompt.paint` engine-only; `ui.ask` docs-only)] → the fixture is dated and the pin tests membership of hooked events only, never equality of the lists.
- [Finding 3 persists after the rewrite] → the next candidate is the lockfile's `resolved` URLs; the change does not touch them.
- [Finding 2 stays on the portal after this change] → expected: keeping the hook is the decision (D5), and only the directory's list clears it. The owner's message (D15) asks for that; the pin keeps the floor and the docs line honest until then.
- [Exact pins in shipped prose go stale at a version bump or an OpenSpec pin regeneration] → each is asserted against its source (`OPENSPEC_INSTALL`, `package.json`), so `npm test` names the stale line; the bump-release sweep greps JSON only and will not edit `README.md:187` by itself.
- [The `tell` rewrite's behavioural checks live in `test/mod/*.test.ts`, which `npm test` never collects] → the Node pins cover the shape; the owner runs `claude plugin test` before release as today.
- [Rewording `OPENSPEC_INSTALL` changes a shipped skill instruction] → the three skills quote the constant and the skills test pins the quote; the instruction's meaning (how to install OpenSpec yourself) is unchanged.
