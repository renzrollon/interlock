## Why

`interlock merge-confidence` (E1) can judge a change, but three of its inputs have no producer and the review that feeds it reads nothing it should be judged against. Coverage has a signal and a file schema, and nothing in the repository reads an lcov report, so `verify.coverage` is unobserved on every pull request. `REVIEW.md` is read from the working tree, so a pull request can add its own paths to `## Do Not Report` and quiet the review of exactly those paths; `policy.humanPaths` reads unobserved because no section declares those paths. No reviewer, skeptic or checklist reads a living spec, so a diff that breaks a requirement already in `openspec/specs/` is caught only if a reviewer happens to remember it. And the question "do these specs carry enough contract to be reviewed against?" has no instrument at all: the hand audit in the epic (§4) could not be repeated, and several of its figures do not reproduce on the commit it audited.

This change lands four briefs of `briefs/merge-confidence-gate-epic.md` together: E8 (coverage baseline), E4 (policy from the base ref), E5 (the `domain` review dimension) and E7 (`spec-audit`). Each depends only on E1, which is archived, and none depends on another; they share two readers (the living-spec requirement parser and the reliable spec-to-file edges) that are built once here instead of four times.

## What Changes

- **Coverage figures the CLI can compute (E8).** A pure lcov reader produces a project total and changed-line coverage on canonical repository paths. `interlock verify baseline` records `{ schema, sha, ref, totalPct, generatedAt }` from a report on the current commit and refuses without a total. `interlock verify coverage --base <ref>` emits exactly the coverage input E1 defined (`configured`, `headTotalPct`, `baseTotalPct`, `baseSha`, `baseIsAncestor`, `diffPct`, `changedLines`), checking the baseline with `git merge-base --is-ancestor`; with `--compute-base` it measures the merge-base in a temporary worktree that is always removed. A profile with no coverage command yields `configured: false`. This departs from the brief's `verify exec coverage --write-baseline`: `verify exec` is a pinned pass-through and stays one.
- **Policy read from the base (E4).** `REVIEW.md` gains `## Always Human Review`, parsed with the `## Do Not Report` grammar and enforced only by the merge verdict. `interlock review` and `interlock review-policy` gain `--base <ref>`: the two enforced path lists are read from the ref, the advice prose from the working tree, and a difference is reported. A ship run records the commit it started on and reads the lists from it, raising `POLICY DIFFERS FROM BASE` when the working copy differs. `merge-confidence --base` makes `policy.humanPaths` observable: a touched listed path, or any edit to `REVIEW.md` itself, is amber and needs a person. A threshold-shaped list item is now rejected in both path sections.
- **A `domain` review dimension (E5).** A seventh rubric whose reviewer is handed the living requirements in force for the capabilities a change touches, selected by rule from reliable spec-to-file edges and from the capabilities the change's own delta specs modify, bounded by a new `LIMITS.maxDomainSpecChars` at a requirement boundary and quoted as data. A finding may cite `requirement: openspec/specs/<cap>/spec.md#<heading>`; the CLI checks the citation's shape against the spec at the base and reports a failed check without dropping the finding. A skip for want of a graph is a banner and the `domain-skipped` flag on `review.ran`. `interlock domain-context` serves the same block to the review skill.
- **`interlock spec-audit` (E7).** A non-gating report, in the `drift` family, of how much domain contract each living capability carries: requirements, scenarios without a `GIVEN`, failure and edge-case scenarios by the corpus's title convention, bound-or-prohibition lines, numeric literals in requirement prose for a person to classify, broken file links, and coverable source no spec names. The suite pins the structural invariants on this repository's own corpus and exact counts on a fixture corpus, never exact counts on the live corpus, which every archive changes.
- **Docs.** `docs/15-merge-confidence.md` is created here with the baseline recipe and the spec-audit reading guide (E3 later adds labels and platform recipes); `docs/04`, `docs/06`, `docs/07`, `docs/10`, `docs/12`, `shared/TEST-PROFILE.md`, `README.md` and `CHANGELOG.md` are updated.
- **Not in this change.** Writing the verdict at close and carrying the dimension record onto `review.json` (E2), so `domain-skipped` reaches a verdict only through a caller-supplied review file until then; labels and the `mr` skill (E3); living conformance and `spec.coverage` (E6), so the verdict still cannot read `MERGE` until E6 lands; editing any living spec to fix what the audit reports.

## Capabilities

### New Capabilities

- `review/domain-review`: when the `domain` dimension runs, what its reviewer is given, how the given text is bounded and framed, how a requirement citation is checked, and how a skip is spoken, in a run and from the CLI.
- `spec/spec-audit`: the per-capability measures of domain contract, how they are defined, what the audit does when the corpus or the graph is absent, and the invariants this repository's own corpus must keep.

### Modified Capabilities

- `verify`: the coverage report reader, the coverage baseline, and the coverage input the merge verdict reads.
- `review/policy-file`: the always-human-review section, reading the enforced lists from a base reference and from a run's start commit, and threshold-shaped list items.
- `review/merge-confidence`: the human-paths signal becomes observable from the base policy; the `domain-skipped` flag on the review-ran signal; two signals, not three, remain without a producer.
- `ship/run-program`: dimension selection adds `domain` by rule and records a domain skip.
