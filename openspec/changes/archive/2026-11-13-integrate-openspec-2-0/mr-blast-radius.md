### ↩️ Rollback

A revert is safe for Interlock's own state: it writes no new on-disk format, and the trajectory, corpora and `.claude/ship` files are untouched. After a revert, the pin reads 1.15.0 again and a provisioned `<data>/openspec/2.0.0/` sits unused next to any old `1.15.0/`. Neither is deleted. **One exception:** projects bootstrapped while 2.0.0 was pinned keep the `.agents/skills` layout and links, and a 1.15.0 CLI does not remove them. They are inert for Interlock, which reads none of them, but they stay in the user's repo until removed by hand. A user who followed the `@2.0.0` own-install line keeps 2.0.0 on PATH, which the doctor accepts (≥ `OPENSPEC_MIN_VERSION` 1.8.0).

### ✅ Manual checks for UAT

1. **Provision on the new floor (B1):** on Node ≥ 22.12, with no `openspec` on PATH and an empty data dir, run `interlock openspec provision`. Then, in a new session, run `openspec --version` and `interlock openspec which`. Expected: `<data>/openspec/2.0.0/openspec` exists, `--version` prints `2.0.0`, and `which` prints `pin: 2.0.0 (Node 22.12.0 or newer)` with source `provisioned`.
2. **Stranded copy and refusal (B1):** on Node 20.19 to 22.11, with `<data>/openspec/1.15.0/` provisioned before the upgrade, run `interlock doctor` and `interlock openspec provision`. Expected: the openspec row says `source: none (… none provisioned for pin 2.0.0)`. Provision exits non-zero with `below 22.12.0, which OpenSpec 2.0.0 needs` and `Nothing was installed`. The `1.15.0/` directory is unchanged.
3. **Node row per resolved CLI (B2):** with a global `@fission-ai/openspec@1.15.0` on PATH and Node 20.19.x, run `interlock doctor`. Expected: the node row is ok, says `OpenSpec requires 20.19.0+`, and does not name 22.12.0. Then put 2.0.0 on PATH: expected warn, naming 22.12.0 and the CLI's path.
4. **Transitive engines (B3):** on Node 22.12.x (and once on 24.14 or 25.x), run `interlock openspec provision`, then `openspec init --tools claude` in a scratch dir and `openspec list --json` in this repo. Expected: provision succeeds, with any EBADENGINE lines only as warnings. Both commands exit 0, and `list --json` task counts match `interlock validate`.
5. **Bootstrap layout (B4):** run `/interlock:bootstrap` in a fresh repo with the provisioned 2.0.0. Expected: `openspec/config.yaml` exists, `.agents/skills/openspec-*/SKILL.md` exist, `.claude/skills/openspec-*` are links into `.agents/skills`, and there is no `.claude/commands/`. Bootstrap reaches `openspec validate` without asking for a `/opsx:*` command.
6. **Lows (B5–B8):** on a real Windows machine with `openspec.cmd` on PATH, `interlock openspec which` resolves it, and `interlock doctor` lists `git` and `interlock`. Run `node scripts/pin-openspec.mjs` with no argument and expect `(e.g. 2.0.0)`.
