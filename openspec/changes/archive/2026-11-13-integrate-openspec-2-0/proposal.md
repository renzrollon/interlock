# Proposal

## Why

OpenSpec 2.0.0 was published on 2026-11-11, and Interlock still pins 1.15.0. A user's own `openspec` on PATH wins over the provisioned pin, the site says to install `@latest`, and `.github/workflows/copilot-setup-steps.yml` installs unpinned, so 2.0.0 already runs under Interlock today. Measured on the published tarballs, every command the skills run answers the same on 2.0.0 as on 1.15.0. What moved is around the CLI: OpenSpec's Node floor rose from 20.19.0 to 22.12.0 in 1.16.0, and 2.0.0 writes its stock skills to `.agents/skills/` and no longer writes `/opsx:*` command files. Interlock states the old floor as a literal in the doctor, three skills, the docs and the living spec, and its docs describe the old stock layout.

## What Changes

- The pin moves to OpenSpec 2.0.0. `lib/openspec-pin.mjs` is regenerated by `scripts/pin-openspec.mjs`, so its Node floor becomes 22.12.0 and its lockfile becomes 2.0.0's.
- **BREAKING**: `interlock openspec provision` needs Node.js 22.12.0 or newer. On Node 20.19 to 22.11 it now refuses, as it already does below any pin's floor. A user's own `openspec` on PATH keeps working on the Node it supports.
- `interlock doctor` holds no OpenSpec Node floor of its own. For the provisioned copy it reads the pin's. For a script on PATH it reads the minimum that CLI's own package declares, and when it cannot read one it uses the pin's and says so. Today the doctor would tell a user whose own 1.15.0 runs on Node 20.19 that their CLI needs 22.12.0.
- The spec, bootstrap and dispatch skills stop spelling the Node floor. Where they name a Node that is too old as the likely cause, they point at `interlock doctor`.
- `scripts/openspec-contract.mjs` also runs `openspec list --json` and `openspec validate --specs`, which the skills run and the script skipped, and checks the skill layout `openspec init --tools claude` writes; it compares the task counts OpenSpec reports with the counts Interlock's reader gives for the same `tasks.md`. Task-line agreement is then measured at each pin bump instead of asserted against one version's source.
- The docs say what 2.0.0 installs: stock skills in `.agents/skills/`, linked from `.claude/skills/`, and no `/opsx:*` commands. `README.md`, `docs/01-first-hour.md`, `docs/07-cli-and-configuration.md` and the two design prompts the site is built from name the new Node floor, and a test holds them to the pin.
- `.gitignore` ignores `.agents/`, as it already ignores the other directories `openspec init` and `openspec update` generate.

Not in this change, each a follow-up: reading a wrapped task's continuation lines the way 2.0.0's `instructions apply` now does; reading section headings with a closing `#` run in `lib/spec-text.mjs`; the bare `openspec status --json` in `skills/explain-code/SKILL.md`; bootstrap's `openspec init --tools claude` in a session that cannot write `.claude/skills`; a scheduled contract run against the newest OpenSpec; and the `site/` export, which is regenerated at release from the corrected design prompt.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `openspec-cli`: where the doctor's OpenSpec Node floor comes from, that no skill restates it, that the contract check covers `list --json`, `validate --specs` and task-count agreement, and that the task reader's agreement is with the pinned release instead of with 1.15.0 by name.

## Impact

- Code: `lib/openspec-pin.mjs` (generated), `lib/openspec-node-floor.mjs` (new), `lib/doctor.mjs`, `lib/artifacts.mjs` (comments only), `scripts/pin-openspec.mjs`, `scripts/openspec-contract.mjs`.
- Skills: `skills/spec/SKILL.md`, `skills/bootstrap/SKILL.md`, `skills/dispatch/SKILL.md`.
- Docs: `README.md`, `docs/01-first-hour.md`, `docs/03-openspec-vs-interlock.md`, `docs/07-cli-and-configuration.md`, `docs/10-agentic-workflow-ship-and-spec.md`, `CHANGELOG.md`, `CONTRIBUTING.md`, `site/DESIGN-PROMPT.md`, `docs/assets/DESIGN-PROMPT.md`.
- Tests: `test/spine/openspec-node-floor.test.mjs` (new), `test/spine/doctor.test.mjs`, `test/spine/openspec-pin.test.mjs`, `test/spine/openspec-cli.test.mjs`, `test/spine/package.test.mjs`, `test/spine/artifacts.test.mjs`, `test/skills.test.mjs`.
- Repository: `.gitignore`.
- Users: anyone provisioning on Node 20.19 to 22.11 has to move to Node 22.12.0 or newer, or install OpenSpec their own way. Nobody has to run `openspec update`; a project that does gets 2.0.0's layout.
- No runtime dependency is added. The pinned lockfile stays development data that `npm ci` reads at provisioning time.
