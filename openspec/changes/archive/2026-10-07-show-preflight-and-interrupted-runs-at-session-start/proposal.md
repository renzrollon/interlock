## Why

Two facts are established at every session start and reach the model, never the person. `hooks/preflight.mjs` runs `interlock doctor --json` (`hooks/preflight.mjs:49-54`) and folds its verdict into the session as `hookSpecificOutput.additionalContext` (`:159-167`): one line, `interlock preflight OK (1 warning).` (`:93`), or the failing checks with their `fix:` strings (`:96-105`). The same hook reads every interrupted-run note not yet spoken from the state home the doctor resolved and from the working directory (`:128-152`; `lib/interrupted.mjs:100-132`) and adds `PREVIOUS RUN INTERRUPTED: <change> run <id> ended at stage <stage> — no resume card was written; interlock run-log show <id>` (`lib/interrupted.mjs:154-162`). Both go into the context the model reads. Nothing draws them: the doctor "exits 1 when something would stop an unattended run" (`docs/04-when-it-stops.md:40`), and a person at the prompt learns that only if the model chooses to relay it. The halt resume card has the same gap from the other side: `run close --halt` writes it to the state home's `.claude/handoff/ship-<change>-<runId>.md` (`lib/run.mjs:3999-4016`; `lib/resume-card.mjs:121-123, 388-402`), the summary names it on a `resume card:` row, and "the terminal that printed the summary is usually gone by the time anyone reads it" (`docs/04-when-it-stops.md:55`). The next session starts with the card on disk and no sign of it anywhere on screen.

The ship meter (`hooks/mod.mjs`) is the plugin's one surface that reaches a person on the terminal and the Desktop Code tab, and it reads nothing from disk by design: its allow-list in `test/spine/mod-pins.test.mjs:31-49` has no `$.fs` call, `$.fs.write` is a forbidden token (`:76-89`), and the `draw-the-ship-run-live` design rejected "Reading the trajectory with `$.fs.read`: a 4 MiB whole-file read with no tail" (`briefs/claude-code-teams-and-orchestration-briefs.md:1359`). That rejection is about the trajectory. Brief 7's own allow-list anticipated `$.fs.read` and `$.fs.exists` for exactly one case, "a value only the stage marker has" (`briefs/…:1090`), and the two facts above live in small, set-shaped, schema-stamped files the Node side already writes or can write: the interrupted note (`interlock.interrupted/1`), the card (`interlock.resume-card/1`, stamped on its first line, `lib/resume-card.mjs:164`), and the doctor report the preflight already holds parsed in memory (`hooks/preflight.mjs:73-88`). This change is the first to put `$.fs.read` on the module's allow-list, for those files and nothing else.

The notes also have a marking gap this change has to settle. `interlock run start` marks a note spoken (`lib/run.mjs:2287-2300`); the preflight "marks nothing: the next `interlock run start`, where the reader is about to spend agents, is the moment that marks a note spoken" (`hooks/preflight.mjs:18-19`; `docs/04-when-it-stops.md:461`; `test/hooks.test.mjs:636`). That was the right rule while the preflight's output reached only the model. Once a band draws the note for the person, a session start is a real speaking, and a band that reappears at every session start for a note nobody clears is the noise the meter's inert-outside-a-run rule exists to prevent. The module cannot mark anything (it never writes), `$.state` is emptied at `/clear` and `$.store` is forbidden, so the mark has to be the Node side's, at the same session start, before the module reads.

## What Changes

- **The preflight leaves its report in one file, and the hooks module reads it.** `hooks/preflight.mjs` additionally writes the report it already computed to `.claude/ship/preflight.json` in the working root, schema `interlock.preflight/1`: the time, the root, the state home and surface the doctor resolved, the message it folded into the session, the doctor's `ok`, `counts` and every check's `id`, `status`, `detail` and `fix`, the interrupted-run notes it spoke this session and the halt resume cards it found for changes still open. It writes only in a project where a ship run can start (an `openspec/` directory in the working root); in any other repository it writes nothing and creates no directory, as the recorder does outside a live run. The write is outcome-class: a failure is one stderr line and the hook exits 0 as it does on every path today. The previous session's file is removed before the new one is written, so a write that fails leaves no file rather than a stale one.
- **The preflight marks the notes it speaks.** Each interrupted-run note the preflight adds to the session's context is marked spoken at that moment, through the same `markSpoken` the run program uses, and the file records which notes were spoken this session and whether each mark landed. A note that could not be marked is said so and spoken again at the next session start and the next `run start`, which is the direction to fail in. `interlock run start` is unchanged: it still marks whatever it finds unspoken, which is how a note reaches a runner-host run that no session start preceded.
- **The preflight lists the halt resume cards of open changes.** It reads the stamp on the first line of each `ship-*.md` under the state home's `.claude/handoff/` (and the working root's when the two differ, as it reads notes), keeps the cards whose change still has a directory under `openspec/changes/`, counts the rest, and records each kept card's absolute path, change, run id and modification time. The card is still a record and never a trigger: nothing decides anything from it, and `ship/halt-resume-card`'s requirement is reworded to say which readers may show it.
- **At session start the module draws a band from that file, and nothing else.** At each prompt a person submits (and after the classic session-start event, where the engine raises one to a module: the kit does, 2.1.291 does not), `hooks/mod.mjs` reads the file, holds the newest report by its written time, and, when it carries a failing or warning check, a preflight that could not run or be parsed, a note spoken this session, or a card, draws the `AbovePrompt` band on both surfaces: the preflight's own first line, one line per check whose status is `fail` or `warn` in the doctor's `status`, `id` and `detail`, each note's banner line verbatim, each card's path with its change, run id and written time, and the time of the report. A `Hide` button collapses it for the session; a report written by a later startup, `/clear` or `/resume` shows its band again, and one written for a compaction keeps it hidden. The band appears at the first prompt, since nothing reaches a module between the preflight's write and that prompt (design D5). An all-ok report with no note and no card draws nothing; an absent or unreadable file draws nothing and is named once on the debug log. The module decides nothing and names no cause: every word on the band is the doctor's, the hook's or the card's. It stays inert in a non-interactive session and in a repository with no file.
- **Two commands open two panes.** `/interlock-preflight` opens a pane with the full report: the message verbatim, every check row with its fix lines, the notes spoken this session with whether each was marked, the cards and the count of older cards for archived changes, and any note the hook could not read. `/interlock-handoff` opens a pane that renders each listed card through the `Markdown` element, newest first, each clamped to a published character cap with a visible truncation note naming the file, because the element refuses a longer text and the engine would draw its own in place of the pane. A card that cannot be read is named with the reason. The meter's own pane and command are unchanged.
- **The 10,000-character bound is a published cap, not a literal in the module.** `interlock limits` prints `handoff pane chars`, a `lib/limits.mjs` key read by a new Node-free module under `lib/`, pinned by `test/spine/limits.test.mjs` as the quiet-time caps are; the hooks module restates no number.
- **The pins move by exactly one call.** `ALLOWED_CALLS` in `test/spine/mod-pins.test.mjs` gains `$.fs.read`. `HOOKED_EVENTS` is unchanged: the band and the two panes are new matchers on `ui.render` and `command.run`, which the module already hooks, and the read sits in the existing `prompt.submit` and `classic.SessionStart` hooks. `$.fs.write` stays forbidden; `$.fs.list` and `$.fs.exists` are not added, because the hook does the listing and the existence checks in Node. No `$.state` key is added: the hide flag and the facts held are module state, reset with the session boundary the module already observes. `claude plugin validate --strict` records the new `hooks:` and `calls:` lines in the design.
- **A fixture discrepancy is resolved from the code.** `test/fixtures/mod/steps.mjs:61` names the card as `.claude/ship/resume/<change>.md`; `runClose` writes it under `.claude/handoff/ship-<change>-<runId>.md` (`lib/resume-card.mjs:121-123`; `docs/04-when-it-stops.md:55`; `docs/11-the-indicators.md:26-28`). The fixture and the kit assertion that reads it move to the real path; the assertion stays as strict as it is.
- **Docs and the changelog.** `docs/13-the-guards.md` updates the preflight's row and the module's row and section (what draws outside a run, from which file, and why `$.fs.read` is allowed for it); `docs/04-when-it-stops.md` updates the preflight section, the `PREVIOUS RUN INTERRUPTED` section (the preflight now marks) and the resume-card section (`/interlock-handoff` shows it; nothing reads it to decide); `docs/07-cli-and-configuration.md` adds the two commands beside `/interlock-meter`; `CHANGELOG.md` Unreleased carries the change; `briefs/claude-code-teams-and-orchestration-briefs.md` gains a dated note that Brief 7's anticipated `$.fs.read` is taken up for schema-stamped files while the trajectory rejection stands.
- **Probes come first, and two can move the design.** (1) The order of `session.start` and the classic session-start event at startup, and whether the settings hooks have run when the module's `classic.SessionStart` `next(e)` resolves, which the declaration's chain order states and the folded `additionalContext` on the result shows. (2) Whether the kit mounts `AbovePrompt` on both surfaces and with which props, and how a test answers `$.fs.read`. (3) How `$.fs.read` resolves a relative path in a terminal and a Desktop session. Each has a named fallback in the design.
- **Serialization.** This change lands after `speak-lane-turn-ends-and-session-cost` and `speak-permission-prompts-and-guard-denials`, which touch the same `hooks/mod.mjs`, `test/mod/`, `test/spine/mod-pins.test.mjs`, `docs/13-the-guards.md`, `docs/04-when-it-stops.md` and `CHANGELOG.md`; its validate lines are diffed against theirs. Any later change touching those files (`draw-the-wave-board-in-the-meter-pane`, `observe-the-spec-run-live`) lands after it. It also touches `hooks/preflight.mjs` and `test/hooks.test.mjs`, which no sibling touches.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `hooks/session-preflight`: the two interrupted-note requirements change from "marks nothing" to "marks each note it speaks"; two new requirements: the report file the hook writes (where, when, what, outcome-class) and the listing of the halt resume cards of open changes.
- `hooks/ship-meter`: the inertness requirement is amended precisely (what the module draws outside a run, from which file, and that everything else stays inert); the observe-only requirement's recorded calls gain `$.fs.read`; two new requirements: the session-start band with `/interlock-preflight`, and `/interlock-handoff` rendering a card verbatim and bounded.
- `ship/halt-resume-card`: the record-not-trigger requirement is reworded so a display read (the preflight's listing, the meter's `/interlock-handoff`, a person's editor) is named and distinguished from a reader that decides; nothing decides from the card, as before.

`hooks/session-recorder` is untouched: its note shape, its writer and its "one text, never an exit code" rule do not change, and the scenario in which a note that cannot be marked is spoken again still holds for the run program and now for the preflight too.
