## Why

When the main session runs a frontier model at high effort, every subagent that `/interlock:spec` and `/interlock:settle` reach is spawned at that same model and effort, because none of the five spawn sites names either: explore's investigators (`skills/explore/SKILL.md:89`), review-code's dimension reviewers and skeptics (`skills/review-code/SKILL.md:50`, `:96`), and settle's fixer and conformance worker (`skills/settle/SKILL.md:226`, `:357`). Ship does not have this problem — `lib/waves.mjs` clamps a lane's model and `EFFORT` in `lib/limits.mjs` fixes the effort, `interlock limits` publishes both, and the drivers banner an environment override — but nothing of that reaches a prose skill. The result is that a Fable session pays frontier prices for a read-only investigator that returns a JSON locator list, and the skeptic effort ship pins at one published value is whatever the session happens to be set to when settle runs the same skeptic.

Routing lowers the price of each agent. It does not lower the number of agents a `settle --review` pass spawns, or the number of times it spawns them, and that count is where the last pass's cost came from. The records of the pass on PR #24 (`.claude/ship/settle/review-r0.json`, `dimensions-r0.json`, `dimensions-r1.json`, `remediate-r1.json`) show the shape: each review ran six dimension reviewers and then two skeptics for each of eleven blockers and warnings, twenty-two skeptic agents; those eleven findings sat at seven `file:line` locations, and four of them were one blocker at `test/retired-names.test.mjs:153` raised once by each of four personas; across the three reviews on that change the skeptics refuted none of the forty-nine findings they were given; the first fix round re-ran all six dimensions over the whole seventy-one-file diff although only four findings had been fixed; and seven of the eleven findings lay in a protected test path the fixer may not edit, so a second round would have briefed a fixer on findings it had already declined for a reason that cannot change. Every one of those is a decision the loop makes by policy, not by judgement, and none of it is published anywhere a reader could choose otherwise.

## What Changes

- **A published role table.** `SPAWN_ROUTING` sits beside `EFFORT` in `lib/limits.mjs`: one row per prose spawn role — `explore-investigator`, `review-dimension`, `review-skeptic`, `settle-fixer`, `settle-conformance` — each a `{ model, effort }` pair where `null` means "omit the parameter, inherit the host's default", the meaning `EFFORT.byTier` already gives it. `review-skeptic` reads `EFFORT.skeptic` by reference, so a skeptic runs at one published effort on the ship path and the settle path alike. The `review-dimension` row carries a `strict` override, so a strict review's dimension reviewers run on the inherited model. `interlock limits` prints the rows and `limits --json` emits the table.
- **A published depth table.** `REVIEW_DEPTH` sits beside it: the default depth, and for each of `lean` and `strict` the dimensions that always run and the skeptic shape. Lean, the default, always runs `language` and `technical-lead` and gives every blocker and warning two per-review skeptics; strict always runs `language`, `architecture`, `qa` and `technical-lead` and gives every blocker and warning its own two skeptics, who run the check a finding claims before they vote. The conditional dimensions — `devops`, `security`, `domain`, `blast-radius` — keep their own triggers at both depths. `interlock limits` prints the table and `limits --json` emits it under `reviewDepth`.
- **A one-role query that knows the depth.** `interlock routing [role] [--depth lean|strict] [--json]` resolves a role to the `model` and `effort` a spawn passes, and names in `banners` any environment override that makes them not in effect (`CLAUDE_CODE_EFFORT_LEVEL`, `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`), in the words ship already prints. An unknown role or depth exits non-zero and names the known ones. With no role it prints the whole table at the depth, and its JSON also carries `depth` and `review` — that depth's always-on dimensions and skeptic shape — so one call tells a review pass everything it needs. The resolver lives in a new `lib/routing.mjs`; the `bin/interlock` case is a few lines.
- **`--strict` on settle and on review-code, lean by default.** Mirrors ship: the default is whatever the CLI publishes, the skill never names it, and `--strict` selects the strict depth. Review-code prints `REVIEW DEPTH: <depth>` from the routing it read; settle passes `--strict` through to every review-code pass of the loop and prints the same line once. A review's dimension record gains `depth`, `interlock review` records it, and the merge verdict's ran-signal evidence names it, so a `MERGE` from a lean review says it was one.
- **The spawn sites read it.** Before fanning out, explore runs `interlock routing explore-investigator --json` once and passes its `model` and `effort` on every investigator call; review-code runs `interlock routing --json` once (`--depth strict` under `--strict`) and reads its two roles, the dimension set and the skeptic shape from that one answer; settle runs it for `settle-fixer` and `settle-conformance`. Each site prints the banners verbatim, and when the command exits non-zero prints `ROUTING UNAVAILABLE: <first line>` and spawns at the session defaults — for review-code that means the strict dimension set and per-finding skeptics, the review this skill ran before this change. No skill names a model, a level, a dimension count or a skeptic count. Explore's `allowed-tools` gains `Bash(interlock *)`.
- **Per-review skeptics at the lean depth.** Two skeptic agents, not two per finding: each reads every blocker and warning of the review grouped by file, returns one verdict per finding id, and is told that findings naming one file and overlapping lines are one issue to be judged once and answered under each id. The evidence rule does not change: a dismissal still cites a `file:line` span in the diff, and every blocker and warning still carries two verdicts, which is the floor the merge verdict's adversarial signal reads.
- **A re-review scoped to what was fixed, with the rest carried.** `interlock settle remediate-brief --json` exposes the planner's `reReviewDimensions`, the dimensions whose findings this round fixes. The round's review-code pass runs with `--dimensions <those>` and `--carry .claude/ship/settle/review-r<r-1>.json`; `interlock review --carry <file>` copies forward the surviving findings of every dimension this review did not run, each marked `carried` with the head it came from, counts them under `counts.carried`, and keeps them out of the metrics. The reply table marks such a finding `open (carried)`. Ship's strict tail already re-reviews only `reReviewDimensions`; settle now does the same, and a reader of the record still sees the whole pull request's state.
- **Two deferrals before a fixer is spawned.** `remediate-brief` defers, before the planner runs, every finding whose file the test guard protects — the paths it already computes to tell the fixer what not to edit — with a reason naming the path and the guard, and, given `--previous <remediate-r<r-1>.json>`, every finding that round's fixer listed under `notFixed`, with the fixer's own reason. The deferred list is printed in the briefing. When every fixable finding is deferred, the command exits with `STOP: nothing fixable remains` naming how many sit in protected paths and how many the fixer declined; those findings stay `open` in the reply table and stay blockers in the verdict, for a person.
- **Spec says where its spawns come from.** `skills/spec/SKILL.md` §1b states that spec spawns nothing itself and that explore's investigators are routed by role, so a reader of spec finds the policy without opening explore.
- **The discipline is shared.** `shared/TOOL-ECONOMY.md` gains a rule: a prose spawn names its model and effort from `interlock routing`, never by omission and never by a literal in prose, and a review names its depth from the same place.
- **The host floor is reported.** `interlock doctor` reports whether the installed Claude Code applies a per-call effort (2.1.292 and later) beside the subagent-model lines it already prints.
- **Pinned, not promised.** `test/skills.test.mjs` asserts each site's tokens, the `--strict` rows, the `REVIEW DEPTH` line, the lean skeptic paragraph and the round's `--dimensions`/`--carry` line; `test/spine/limits.test.mjs`, `test/spine/routing.test.mjs`, `test/spine/cli.test.mjs`, `test/spine/settle-cli.test.mjs` and `test/spine/merge-confidence.test.mjs` cover the tables, the command, the carry, the deferrals and the evidence line; `docs/01`, `docs/07`, `docs/10` §5 and `docs/15` describe the two depths; CHANGELOG `## [Unreleased]` gets an entry.

Out of scope, deliberately: ship's run program, `lib/waves.mjs`, `lib/lane.mjs` and the plan's tier routing (the owner judged them fine), including ship's strict tail, which already scopes its re-review; `LIMITS.remediationRounds`, which stays one cap for both loops; the conformance worker, which runs at both depths because the delta-conformance and living-conformance signals read nothing else; choosing the depth from the risk class or the diff size, which is a follow-up once the two depths have run on real pull requests; `review-artifacts`, which runs its two reviewers inline and spawns nothing; the spec meter's investigator line, which already reads the served model and can show it in a follow-up.

## Capabilities

### New Capabilities
- `spawn-routing`: how a prose skill's subagent spawn gets its model and effort — a table published by the CLI, a one-role query that resolves it and speaks overrides, spawn sites that read it before spawning and say when they could not, and a host-floor report in the doctor.
- `review/review-depth`: the two published review depths — which dimensions always run and how the skeptics are shaped at each — how `--strict` selects one, how the review record and the verdict say which one ran, and how the skills read it without naming it.

### Modified Capabilities
- `review/settle-loop`: the round's re-review is scoped to the planner's `reReviewDimensions` with the rest carried; `interlock review` gains `--carry` and records `depth`; `remediate-brief` defers protected-path findings and previously declined findings before the planner runs and stops when nothing fixable remains; `replies` marks a carried finding. This capability is ADDED by the open change `close-the-merge-request-loop`, so this change archives after it.
- `review/merge-confidence`: one ADDED requirement — the ran signal's evidence names the depth the record carries. The requirement the open change MODIFIES is untouched.
