## 💥 Blast radius review — business logic changes (run-without-a-user-installed-openspec)

> **Scope of this comment:** this is a separate, specific **blast radius** review. It does **not** cover the feature's own plumbing: `lib/openspec-pin.mjs`, the lockfile, `scripts/pin-openspec.mjs`, `scripts/openspec-contract.mjs`, the `interlock openspec which` leaf, the `bin/` → `cli/` path renames in comments, docs and tests, or the new package pins. It looks only at the **business logic changes** this PR makes to existing behaviour (how a session finds `interlock`, what the authoring skills do when `openspec` is missing, what the doctor reports, what a review must cite) and at which existing features they can affect. The general review findings are in the round 0 comment (`F-…` ids). This comment points to them and does not repeat them.

Scope: `7b1091b...66700d8` (2 commits, 124 files). Static analysis only. Nothing was run, and no DB was touched.

⚠️ **Important:** the host side of the PATH handoff has never run in a test. `test/hooks.test.mjs` runs `hooks/preflight.mjs` against a temp `CLAUDE_ENV_FILE` and asserts the line it writes. No test has a host source that file before a Bash command, a Workflow worker, or a `!` command. The only evidence is one manual probe on Claude Code 2.1.314. CI's floor engine is 2.1.287, and `claude plugin validate` starts no session there. Provisioning has never run `npm ci` in a test either: `test/spine/openspec-cli.test.mjs` injects `fakeSpawn`, so npm and the registry are stubbed. `scripts/openspec-contract.mjs` is opt-in. **The first session started after this merges is the first real run of both.**

**Sub-repos: no sub-repos. External consumers: impact — see B5.**
- Marketplace `release` branch (`plugin-bundle.yml`): it is built from the npm tarball, and `package.json#files` now lists `cli`, so the bundle carries `cli/`. No `bin/` path appears in the workflow.
- npm global install: the `bin` map points under `cli/`, and `npm i -g` relinks the same four names. The `<prefix>/bin/` symlinks used by `ci.yml:153-253` keep their names.
- `~/IdeaProjects/kettle` (demo repo): `git grep bin/interlock` finds nothing outside `takes/`.
- Users' own scripts, aliases and `settings.json` allow rules that name `<plugin root>/bin/<name>`: not in any repo I can read, so not checked. CHANGELOG names the break.

### ↩️ Rollback

Reverting is safe for repository data. Nothing in `openspec/`, `.claude/ship/` or the corpora gains a field the old code cannot read. The manifest `cli.path` is a string the old code only prints. **Three exceptions, all outside the repo:**
- (a) Provisioned trees in `<data>/openspec/<pin>/` and `~/.cache/interlock/openspec/` stay on disk, along with any orphaned `.partial-*` directories. The old code never reads them and never removes them. The user would delete them by hand.
- (b) Sessions started on this release keep `export PATH=…/cli…` and `INTERLOCK_PLUGIN_DATA` lines in their env file. After a revert the `cli/` entry points at a directory the old release does not have. That is harmless, because the host's own `bin/` injection comes back.
- (c) A user who rewrote a wrapper or allow rule to `cli/<name>` must change it back.
