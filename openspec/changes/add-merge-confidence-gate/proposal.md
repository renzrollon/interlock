## Why

After a ship run, the only machine facts about whether the result can be merged are "no blocker survived" and "the unit suite is green". Everything else a merge decision needs is already computed somewhere and never combined: surviving warnings (`lib/receipt.mjs:217-220`), the risk class (`lib/risk.mjs`, re-run nowhere over the paths the run actually touched), skipped and cap-exhausted verifications, unconfirmed conformance scenarios, open decision-ledger rows, run degradations, diff size (computed nowhere), and the platform's own pipeline result (read nowhere). The one surface that does pronounce on mergeability is prose: `skills/mr/SKILL.md` §4 asks the model to write `## High Risk Changes` and warns it that "an inflated confidence level is worse than no assessment, because it is the section a reviewer uses to decide how hard to look". That is a threshold a model re-argues on every run, which is the one thing `.claude/CLAUDE.md` forbids everywhere else.

This is brief E1 of `briefs/merge-confidence-gate-epic.md`, the first of eight. It lands alone and first because every later brief (the receipt, the `mr` skill labels, the base-ref policy, the `domain` dimension, the living conformance list) reads the output shape this one defines.

## What Changes

- **A pure decision module, `lib/merge-confidence.mjs`.** `assessMergeConfidence(input, { bands, allowedClasses })` takes a plain object of observed facts and returns a verdict (`MERGE`, `HUMAN`, `BLOCK`), a score from 0 to 100, and one entry per signal with its band (`green`, `amber`, `red`, `unobserved`), its flags, and the evidence that produced it. The verdict is the worst band over every gating signal; `unobserved` ranks as amber; a flag never moves a band. The score is bounded by the worst band's ceiling and positioned inside the band by the share of signals that are green and unflagged, so a red can never score above the red ceiling and two PRs in the same band sort by how much they left unflagged. No filesystem, git, network, agent or clock.
- **A signal registry, not a formula that names signals.** The module exports a frozen `SIGNALS` array (`{ id, family, gating, read }`) and a frozen `FLAGS` list. Seventeen gating signals and one informational signal (`plan.fidelity`) are declared, including three that no caller can yet observe (`conformance.living`, `spec.coverage`, `policy.humanPaths`); those resolve `unobserved` with the reason that their producer has not landed, so the signal table is complete from the first release and a later brief adds nothing silently.
- **Every number in `lib/limits.mjs`.** A new `MERGE_BANDS` export (band ceilings, warning cap, verdict floor per finding, coverage decline tolerance, patch-coverage floor, small-diff floor, diff size caps) and a new `MERGE_ALLOWED_CLASSES` in `lib/risk.mjs` beside `CONTINUITY_ALLOWED_CLASSES`. The domain-spec text cap the epic lists arrives with its reader in E5, because a printed cap with no reader fails the cap-authority sweep. `interlock limits` prints the group and `--json` publishes it as `mergeBands`; the cap-authority sweep covers it, so a band printed by the CLI and read by nothing fails the suite.
- **One subcommand, `interlock merge-confidence`.** `[change] --changed <files> [--review <file>] [--verify <file>] [--handoff <file>] [--pipeline <file>] [--coverage <file>] [--base <ref>] [--require-merge] [--json]`. The command reads the change's artifacts and ledger, runs the risk classifier over the changed paths, runs drift, reads `git diff --numstat` for the diff shape, and treats every input not supplied as `unobserved` with its reason. It never calls `gh`, `glab` or the network. Exit 1 iff the verdict is `BLOCK`; with `--require-merge`, exit 1 unless `MERGE`. `HUMAN` exits 0 because a PR that needs a person is not a failed command.
- **Two input schemas defined here and produced later.** The pipeline file `{ sha, checks: [{ name, state, required }] }` (produced by the `mr` skill in E3) and the coverage file `{ configured, headTotalPct, baseTotalPct, baseSha, baseIsAncestor, diffPct, changedLines }` (produced by the baseline writer in E8). A pipeline file whose `sha` is not HEAD is `unobserved`; a coverage file with `configured: false` is green with the flag `no-coverage`.
- **Docs and the changelog.** `docs/07-cli-and-configuration.md` gains the subcommand and the limits rows; `CHANGELOG.md` Unreleased carries it.
- **Not in this change.** Writing the verdict at `run close` and onto the receipt (E2); labels and the description block in the `mr` skill (E3); reading `REVIEW.md` from the base ref and the `## Always Human Review` section (E4); the `domain` dimension (E5); living conformance and the two spec signals (E6); `spec-audit` (E7); the coverage baseline writer (E8). `interlock report` reads nothing new.

## Capabilities

### New Capabilities

- `review/merge-confidence`: the merge verdict and score. What a signal is, how bands compose into a verdict, how flags and `unobserved` differ, how the score is bounded, which facts each signal reads, and the subcommand's contract (inputs, offline, exit codes).

### Modified Capabilities

- `ship/cap-authority`: the merge-band group joins the caps the limits surface publishes and the reader sweep enforces, as a nested group beside the lane-cap table rather than an entry of the iteration-count limits.
