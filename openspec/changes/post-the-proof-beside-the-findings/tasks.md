# Tasks

An assertion that pins a meaning the delta specs change is updated in the task that changes that meaning, never during a remediation stage, and the update names the assertion and the requirement it now pins. The pins named below are the known ones, not a complete list.

Record shapes, reason strings, the fixed prefixes and marks (`RESULT DISAGREES:`, `RE-RUN:`, `CONFIRMATION NOT CITED:`, `CUT:`, `Excluded by the caller:`, `session-recorded`, `as the session read them`, `not posted`, `latest`, `No gap is recorded in these records.`), the comment's skeleton, the summary's three lines and the module layout are the ones in `design.md` under "Shapes the tests and the implementation share". Tests and implementation both read them from there. Tests pin headings, prefixes and order, never the sentences between them.

The comment's bound is read from `LIMITS.maxValidationCommentChars`, never written as a number in a test or a skill.

The owner answered the four held ledger rows on 2026-11-23, and the tasks are written to those answers: a person uploads images by default (D5), the comment is posted on every `--review` pass (D7), the bound was left to the spec and is 20,000 characters (D15), and what counts as a screen is the existing surface classifier's answer, which serves other projects with no setup (D6).

A second artifact review on 2026-11-23 added ledger rows D25 to D28, and the tasks are written to them: the comment is posted in a new §6d, before the description is composed (D25); two passes on one commit leave two comments and `- Proof:` names the latest (D26); a pass renders only from records it wrote (D27); a check the caller excluded is named apart and listed as a gap (D28).
