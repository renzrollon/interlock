# Tasks

Decision ids are `design.md`'s. Requirements are named by capability and title in the delta specs under `specs/`.

**Existing test pins.** The pins this change is known to move are named in the task that moves them. An assertion that pins a meaning the delta specs change, and is not named here, is updated in the task that changes that meaning, never during a remediation stage (the test guard denies test edits there), and the update names the assertion and the requirement it now pins.

**Engine facts.** The calls and event shapes below are the ones probed on 2.1.295 and 2.1.318 (explore brief F1-F6): `$.ui.notify(text, { title })` answers `{ isSent, reason }`; `$.ui.copy({ text })` answers `{ isCopied }`; `$.prompt.read()` answers `{ text, cursor }`; `$.prompt.fill({ text })` answers `{ isFilled }`; `prompt.autocomplete` carries `{ text, cursor, token, start }` and is answered `{ suggestions: [{ text, label, description }] }`. In a kit test the call-shaped stubs answer `{ value: … }`, the `prompt.fill` stub answers `{ isFilled: true }` directly, and an `Svg` is found with `find({ type: 'Svg' })`, not by key.
