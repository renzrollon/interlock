Reduce both the change name and the run id to a filename-safe segment — non-`[A-Za-z0-9._-]` to `-`, any run of two or more dots collapsed, leading and trailing dots and dashes stripped, length truncated — so a card can never be written outside the handoff directory and no segment carries a literal `..`. Fall back to the `no-run-id` literal, not a timestamp, when the run halted before a plan was adopted.

- [x] 1.2 Write `formatResumeCard` as a pure function of its arguments — no disk access, nothing inferred. It renders: the halt reason (clamped with a visible `(truncated)` marker, and a sentence when the halt recorded no reason at all); the record-not-a-trigger paragraph naming the stored plan fingerprint as what actually decides reuse, ending in `Do not start another ship run unless the user asks.`; a "Where this run stopped" section with change, run (or the stated absence), project slug, cwd, the trajectory path and the `interlock run-log show <runId>` / `interlock run-log query --run <id> --halted` commands, printed only when there is a run id to name; leftover task ids with a ready-to-paste `interlock tasks tick <change> --ids <ids>`; the plan section; the wave tallies; the degradation banners raised before the halt; and a "Picking it up" section ending in the statement that the wave cursor and the previous wave's handoff packets are not resumed because `.claude/ship/state.json` is replaced at wave 0.

- [x] 1.3 Report this run's own plan verdict and the stored state, never a prediction: `reused` / `rebuilt` with the manifest's status and reason, or that the run ended before the plan-reuse check reported when no verdict was recorded; then whether `.claude/ship/plan.json` and `.claude/ship/plan-fingerprint.json` name this change, and the reuse rule — ticking a box does not break the fingerprint, editing an artifact or adding, removing, reordering or rewording a task does, and so does a different `--solo` / `--waves` / `--tdd` shape. Do not state or imply what the next run will decide.

- [x] 1.4 Cap every list — leftover ids, wave tallies, banners — at `LIMITS.resumeCardListRows`, and follow a truncated list with a line naming how many rows were left out and where the whole list is (`openspec/changes/<change>/tasks.md`, `interlock run-log show <runId>`, the printed summary). State every absence as a sentence rather than leaving an empty section. Do not write the cap's value into the module's prose.

- [x] 1.5 Write `writeResumeCard(root, input)` as the one impure function: refuse an empty or non-existent root by name, create `.claude/handoff` beneath the root, write the formatted card, and return `{written, path, reason}` with the repo-relative path. Catch everything — it must never throw, so that losing the card cannot change how the run halted.
