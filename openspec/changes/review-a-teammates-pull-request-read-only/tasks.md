# Tasks

An assertion that pins a meaning the delta specs change is updated in the task that changes that meaning, never during a remediation stage, and the update names the assertion and the requirement it now pins. The pins named below are the known ones, not a complete list.

Export names, the target file's shape, the comment's fixed parts, the seven test-name prefixes and the lines the skill prints are the ones in `design.md` under "Shapes the tests and the implementation share". Tests and implementation both read them from there.

Three traps, each of which has cost a red suite before:

- **`test/retired-names.test.mjs`** fails a shipped file that spells GitLab's own name for a pull request (`design.md`, "Words in shipped files"). It scans tracked files only, so a new file passes until it is staged: after creating a file, run `git add -N <file>` and then `node --test test/retired-names.test.mjs`.
- **`cli/interlock` is about 3 KB under its size pin** (`test/spine/package.test.mjs:392-407`). Add usage lines there and nothing else; every handler and helper goes in `lib/`.
- **A test another task owns may be red in your task.** Run the tests your task names, by prefix, and leave the other prefixes alone.

Three runs against real pull requests are owed by the owner after this ships (`design.md`, "Migration Plan"). They need the network and a worktree outside the sandbox, so no task here performs them.
