02

When it stops

Two categories, and they are not the same thing. A loud halt stops the run, commits nothing, and reports what completed and what you need to decide. A soft continue keeps going with a documented default and prints a banner saying what it degraded. Almost everything is a soft continue. The halts are deliberately few. On any halt: nothing is committed, and it will not ask you a question. Every one is a non-zero exit from a CLI subcommand rather than a judgement call.

Where the rules live

The guards

Six hook scripts. Four can deny. All fail open.
HookEventWhat it does
preflight.mjssession startDenies nothing. Runs interlock doctor and surfaces each failing check with its fix, speaks any note an interrupted run left, and in an OpenSpec project leaves its report in .claude/ship/preflight.json. Advisory: it never blocks the session.
recorder.mjssession end, subagent start and stop, permission request, permission deniedDenies nothing and returns no decision. Records what a run cannot see about itself: a session that ended mid-run, what each Workflow agent spent and which model served it, each permission prompt and each call auto mode refused.
guard-tests.mjsbefore Edit or WriteDenies an edit to a test file while the stage is remediation or fix-tests. Test edits during implement are allowed: adding coverage for the feature you are building is the point, not a hazard.
guard-tasks.mjsbefore Edit or WriteDenies an edit that flips a checkbox in the active change's tasks.md. The tick is the CLI's job, keyed off recorded outcomes.
guard-commit.mjsbefore BashDenies a git commit unless the stage is commit.
guard-relaunch.mjsbefore and after Workflow; each human promptDenies a second ship launch in one session when no human prompt has arrived since the last one. A parent chat once relaunched over leftover checkboxes and spent another twenty agents; this is the guard for that.
mod.mjs, a hooks module (Claude Code 2.1.287+)engine eventsThe ship meter. It observes a run and draws it. Apart from the launch guard's one refusal it returns no deny.

The three stage guards read a stage marker at .claude/ship/<change>/stage.json carrying the stage, the change, a monotonic index and the writing process's pid. The agent performing each step publishes it; the run program clears it on every terminal path. The launch guard cannot use the marker, because the mistake it bounds happens after the close has cleared it, so it keeps its own small record per session.

When a guard cannot establish the facts, because the marker is absent, unreadable, malformed, stale, the process is gone, or the guard itself crashed, it allows. The asymmetry is argued rather than hidden: a lost marker during a real run silently disables the guard for that window; fail-closed would, on the same lost marker, brick every edit in the session.

Installing Interlock does not change how your own editing or committing behaves. The stage guards bind only agents inside a ship run and are inert outside one.

The hosts

What a host cannot do is declared, never discovered.

lib/host.mjs states the whole host contract as three operations: spawn one labelled agent, spawn a batch in parallel, and run interlock and hand back its exit code and stdout. A host may not decide wave order, judge a verify result, apply a cap or a gate; those live behind the CLI on purpose, so a second host cannot quietly grow a second copy of the rules. A non-zero exit is an answer, not an error: a host that threw on it would turn a halt into a crash.

An adapter under lib/host/ is a transport plus a declaration of eight capabilities. Every one describes a way a run on that host is weaker than the default, and the run program branches on the declaration, never on the host's name. /interlock:ship on the Workflow runtime is the supported path. The runner is experimental, no slash command starts it, and it refuses --host workflow from the other side.

04

You can watch it

On Claude Code 2.1.287 and later the plugin's hooks module draws the run as it goes: a status line that names the stage and stops at the checkpoint, a pane with every wave, lane and agent, and each degradation banner as a toast the moment the step that raised it prints. The pane observes; the CLI decides. On an older host the run is the same, without the pane.

status line
interlock: <change> · <action> · wave <w>, plus batch <j>/<k> where the step carries a batch position. Cleared at the close or a halt.
wave board
The same fields interlock waves --plan <file> --format board prints, as one bordered card per wave. Lanes are grouped by batch under a line with the time it was dispatched and N in parallel. The state words are ok, failed, current, pending, not reached and not recorded.
timeline
The run in the order it happened: one line per CLI step as it crossed, each with its local time, and the agents that step spawned indented beneath it.
guard denials
When a guard refuses a call, one toast repeats the guard's own sentence from its name on (guard-tests: …), and the pane counts guard denials: <n>. Before this a denial reached only the blocked agent.
quiet <n> min
How long the run has gone without activity, and nothing more. The word names no cause: a run waiting on a plan window looks exactly like a run that hung, which is why the pane lists the plan windows beside it.
at session start
When a doctor check failed or warned, an interrupted run was spoken, or a halted run left a resume card, a band above the prompt shows those lines in the doctor's own words. /interlock-preflight opens the whole report; /interlock-handoff renders each resume card.
  • The meter prices nothing. The session cost on the pane is the engine's own figure for the whole session, not the run's. The meter computes no dollar figure of its own.
  • The close summary and the receipt are the record. Every figure on the pane is live and display-only, and the pane says so.
  • It observes. It writes no file, calls no model and opens no connection, and a test reads the module as text and fails on any engine call outside the ones it is allowed. Nothing draws in a -p session, the SDK or a runner lane.
