# Changelog

All notable changes to this project are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and
this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **The ship meter says how long a run has been quiet.** A subscription run that reaches a plan window pauses instead of failing, and from the status line that pause looked exactly like a hang. While a run is live, `hooks/mod.mjs` now stamps the engine's time of each thing the run does: the launch, each step the CLI prints, each request a run agent starts and each answer it gets, each agent's turn end, each spawn. Once nothing has moved for `meter quiet after (ms)`, ` · quiet <n> min` follows the position on the status line and the spinner, and the pane gains a `last activity <time>` line with the word beside it. The next activity clears it. A lane thinking through one long request is not called quiet, because the request's start and its answer both count. The word names no cause: the plan windows stay beside it on the pane as the session reports them, with no threshold and no colour.
  - **Two caps, published, not restated.** `interlock limits` prints `meter quiet after (ms)` and `meter tick (ms)`. Both are keys in `lib/limits.mjs`, read by a new pure, Node-free `lib/meter-quiet.mjs` that the hooks module imports, and `test/spine/limits.test.mjs` fails if the module restates either.
  - **One timer, the host's own.** The figure is recomputed on `$.clock.every`, the engine's periodic dispatch, which the module starts at the launch and cancels at the close, a halt and the session boundary. A redraw happens only when the word changes. A sleep inside a hook would have been charged to that hook's own time budget, so `$.clock.sleep` joins the module's forbidden tokens. The pins' allow-list gains `$.clock.every` and nothing else.
  - **A time it cannot read is no figure.** A clock read that fails leaves the stamp as it was and the word absent, and is named once per run on the debug log. A run whose clock never answered reads `last activity unknown`. When the launch guard cannot read the clock, it now reports no time instead of zero, so the meter never stamps a launch at the epoch.
  - **The probes came first.** Under `claude plugin test`, `mock.clock().advance` drives a module's `$.clock.every` period by period, so the kit cases run the real interval; the clock-failure cases answer the clock themselves, because the kit takes one `clock.now` answer per test. In a `--plugin-dir` terminal session on 2.1.289, an interval a module started stopped at the module's hot reload and the reloaded module's own interval took over, so a reload leaves no orphan ticking.

- **Ship-run agents are shown with what they are doing, not just a task id.** A lane that was `1.1+5` in `/workflows`, the ship meter and `interlock-run`'s log is now `1.1+5 · Add the relaunch guard to…`: its label, then the first words of its first task, capped at 48 characters. A relay ping is `cli-12 · run next`. The title is display only: the briefing file, the lane worktree, the trajectory, `run record-batch` and every banner still name the lane by its label, so rewording a task changes nothing a run joins on. The title is a pure function of the lane, so a resumed run still cache-hits. Every spawn now carries `title`, and a spawn that is not a lane uses its label as its title.

- **The launch guard now also runs inside the engine, reading the prompt origin the engine stamps.** `guard-relaunch` tells a person from the host's completion wake by the prompt text's `<task-notification>` prefix. On a host that loads plugin mods (Claude Code 2.1.287 and later), `hooks/mod.mjs` now applies the same rule in process. A ship launch with no human prompt since the session's last is refused before the engine or the settings layer sees the call. The words are the same, and the model reads them as the Workflow tool's error text.

  - **What counts as a person is the engine's word, not a text prefix.** A `prompt.submit` whose `origin.kind` is `composer` (your own Enter, typed or queued), `bridge` (Remote Control) or `sdk` (a `claude -p` or Agent SDK turn) records a human prompt. A task notification, a scheduled trigger, a peer session, a channel, a coordinator, an observer, a plugin's own prompt and a missing origin count nothing. Each of those leaves one debug-log line naming its kind. The prompt is never rewritten or dropped. A ship launch is `workflows/ship.js`, `interlock:ship`, or a resume naming the run id or persisted script path this session recorded. A launch the engine refused or errored is not recorded. A relayed task notification at `session.receive` is named on the debug log and passed on, never consumed.
  - **The record is declared session state.** One key, `interlock.ledger`, holds the file ledger's shape and is declared in a new type contract, `types/index.d.ts`. It survives a reload of the module, `/clear`, `/resume` and `/branch` empty it (the next launch is allowed), and the machine-wide store is never read or written. Time comes from `$.clock.now()`, so the test kit can move it. A `-p` run has one `sdk` prompt and then a launch, so a second launch in the same run is refused there too.
  - **The two forms never refuse twice.** On a mods host the module's `tool.call` hook runs before the plugins' `PreToolUse` settings hooks. Its refusal ends the call, so `guard-relaunch.mjs` never starts and the model gets one reason. Its allow falls through to the settings form, which decides from its own file ledger. They read one thing differently, and it is named: a peer, scheduled-trigger or channel prompt re-arms the settings form and not the module, so on a mods host the stricter reading decides first. Below 2.1.287, and wherever user mods are stopped, the settings form is the only enforcement and is unchanged. Retiring its four registrations waits on the plugin's version floor. A prompt typed and queued during the run still re-arms one launch, and that hole is named, not closed, in both forms. See [the guards](docs/13-the-guards.md#two-forms-and-which-is-active).
  - **It fails open in process too.** A state or clock read that fails is read as an empty record and named on the debug log, so the launch reaches the settings form's own decision. A launch or prompt that cannot be recorded is named the same way, and never thrown out of a hook whose call already ran. A hook that throws is skipped by the engine.
  - **The probes came first, and one moved the design.** On 2.1.289, an interactive session with a logging mod saw the typed prompt as `origin: { kind: 'composer' }` and the completion wake as `origin: { kind: 'task-notification' }` with a `turnId`. The wake came through `prompt.submit` only: `session.receive` did not fire for it, so the debug line for a wake is written from `prompt.submit`. Both payloads are pinned, scrubbed, under `test/fixtures/mod/`. On 2.1.161, the manifest's `types` key draws `Unknown field 'types'. Claude Code ignores it at load time.`, and a headless session showed its `SessionStart` and `PreToolUse` settings hooks still running beside the key, so the key ships. Only `claude plugin validate --strict` fails there. On 2.1.274, a module that passes `$` into `read` or `update` imported from `claude-code` is refused, which would have unloaded the meter as well. The module therefore calls `$.state.get` and `$.state.set` directly and imports nothing from `claude-code`, and 2.1.274 passes `--strict` on the plugin.
  - **The table is repeated under the engine's kit.** `test/mod/relaunch.test.ts` runs under `claude plugin test .`. It covers the first launch and the second without a prompt (in a `-p` and an interactive session), every human and non-human origin between two launches, the resume by run id and by script, another workflow, a refused and an errored launch, the relayed notification, the aged launch, and an unreadable state.

- **A ship run is now drawn while it runs, in the terminal and the Desktop Code tab.** Every soft continue used to surface at close: for the twenty minutes before that, someone watching saw a spinner. The plugin gains a hooks module, `hooks/mod.mjs`, which Claude Code 2.1.287 and later load inside the engine. It reads each step the CLI prints off the ping's Bash result and shows it: a status line (`interlock: <change> · <action> · wave <w>`), one toast per degradation banner the moment the step raising it crosses, a spinner suffix, and `/interlock-meter`, a pane of waves (routed beside served model), per-agent requests and tokens, the session's plan windows with no threshold, every banner so far, and after the close the summary verbatim, resume card row included. The pane says that its figures are live and the close summary and receipt are the record.
  - **It observes, and that is pinned twice.** No hook returns a deny or a substitute result (the in-process launch guard's one refusal, above, is the single exception the pin allows), there is no catch handler, and the module calls no model, prompt, message, process, network, file write or permission check. `test/spine/mod-pins.test.mjs` reads the module as text and fails on any engine call outside nine allowed ones or any forbidden token, and walks its imports so nothing it reaches loads `node:`. `claude plugin validate . --strict` lists the same hooks and calls. It is inert outside a live ship run and in any non-interactive session (`-p`, the SDK, a runner lane).
  - **The settings hooks are untouched, on every host.** `hooks/hooks.json` is `{ "hooks": {}, "modules": ["./mod.mjs"] }`. The probe came first: on this machine 2.1.161, inside the plugin's v2.1.154+ floor, refused a `modules`-only file (`hooks: Invalid input: expected record, received undefined`), because it reads that path as its settings-hooks file. The dual shape passes `--strict` on 2.1.161, 2.1.274 and 2.1.289. A `--plugin-dir` session on 2.1.161 still ran the manifest's `SessionStart` hook and its `PreToolUse` deny. `test/hooks.test.mjs` pins every inline registration and the empty record.
  - **The engine probe set the meter's shape.** On 2.1.289, `tool.call` fired for the ping's Bash inside a Workflow agent with `agentId` set, and its `text` was the CLI's whole stdout. `turn.step` and `turn.complete` carried the same agent id. `agent.spawn` did not fire for a Workflow `agent()`, so an agent row reads `lane unknown` unless a host raises it. On the Workflow host the relayed step drops the batch fields, so the status line shows the wave alone there. The captured records are pinned under `test/fixtures/mod/`.
  - **`banners` is a field on every step that raised one.** A banner the run pushed onto the manifest (a lane the host stopped, an isolation warning) used to reach only the close summary. `finishStep` now carries every banner raised since the last step onto the next one, in the summary's order and once each. The close's `--json` record already carried `{ action, exitCode, summary, banners }`, and that is now a stated contract of `ship/run-program`.
  - **`interlock doctor` gains a `mods` row**, advice and never a failure: `ok` from `MODS_MIN_HOST_VERSION` (2.1.287, beside the other host floors in `lib/host/claude-env.mjs`), `skip` below it or with the version unknown. It names the binary it probed, because the engine behind a Desktop session is not the `claude` on PATH; the meter logs the engine it loaded in.
  - **The one `.test.ts` in the repository.** `test/mod/meter.test.ts` runs under `claude plugin test .` against the engine's own kit, each UI case on both surfaces. `npm test` collects `*.test.mjs` only, which a pin asserts. CI's `validate-plugin` job runs the kit after the strict validate, and runs it even when that validate is red: from 2.1.289 it fails this checkout over the root `CLAUDE.md` warning, a pre-existing condition with its own fix. `CLAUDE.md` says both conventions.
  - **Brief 9's premise inverted.** It paired the meter with a second measurement route, on the assumption that the transcript probe would fail. That probe passed, and the CLI already records per-agent usage and substitutions, so the meter takes Brief 9's display half only. It writes nothing and joins nothing.
  - **`scripts/host-probe.mjs`, development only and never shipped.** One allow-listed entry point for host probes (`validate`, a headless `--plugin-dir` session, a tmux TTY session), run in a clean login environment so a Desktop session's gateway variables never reach the child.

- **A ship run now says what its agents cost, which model ran them, and why a lane failed, on both hosts.** On the Workflow host every `/interlock:ship` printed `CACHE ACCOUNTING NOT REPORTED`, the trajectory recorded the routed model as if it were the one that ran, and a mid-run permission prompt went unnamed. On the runner a lane that hit its turn cap, a `success` without `structured_output` (anthropics/claude-code#82258) and a lane whose tools were denied all read like a lane that did nothing, and its resumable session id was dropped.

  - **The probe came first, and it moved the design.** On CLI 2.1.274, a headless session with a logging hook captured the `SubagentStart`, `SubagentStop` and `PermissionRequest` payloads and a real subagent transcript, pinned scrubbed under `test/fixtures/hooks/` and `test/fixtures/transcripts/`. The host reports `agent_type: "workflow-subagent"` for every Workflow `agent()`, whatever `type` the script named (a real 2.1.289 ship ping spawned as `interlock:ping` showed the same), so the recorder matches `^workflow-subagent$` and not the plugin agent names the brief assumed. The transcript writes one line per content block and repeats the request's usage on each, so usage is summed once per assistant message. Every `claude -p` envelope listed a host-internal haiku call in `modelUsage` beside the session's own model.
  - **Four recorder branches, which report and never decide.** `hooks/recorder.mjs` joins `SessionEnd` with `SubagentStart` and `SubagentStop` (matcher `^workflow-subagent$`) and `PermissionDenied` and `PermissionRequest`. Behind one gate (a live stage marker and a manifest carrying a run id) the stop sums the agent's transcript and pulls the briefing sha out of its bootstrap. The start records the agent once. Each permission event is one file naming its kind, agent, tool and reason, never the tool input. All of it goes to an outcome-class sidecar under the working root's `.claude/ship/agent-usage/<runId>/` (`lib/agent-usage.mjs`), one small file per key, so a later mod can write the same files. No branch starts a process, reads the trajectory or exits non-zero.
  - **The close joins the sidecar to the spawns it dispatched.** `run close` matches agents to spawns by briefing sha. A wave where every briefed spawn joined gets its cache figures, and a complete join records the observed cache accounting `hook`, a value no adapter may declare. One spawn missing banners `CACHE ACCOUNTING PARTIAL: <n> of <m> agents unrecorded`. Relay pings and other unbriefed agents are counted in `AGENT USAGE UNJOINED` and attributed nowhere. The permission files banner `PERMISSION PROMPTS DURING RUN: <n>` and `AUTO MODE DENIED <n> TOOL CALLS (<tools>)`: counts the reader interprets, never a verdict.
  - **One matcher, one verdict, two observations.** `modelMatches` in `lib/host/model-map.mjs` is the only comparison of a routed model against a served one. It ignores a provider prefix and a date stamp, and a tier alias matches any id carrying that tier. `modelSubstitution` in `lib/run.mjs` reads the strongest evidence present. Turn-scoped models come from an agent's own transcript, and there any unmatched id banners `MODEL SUBSTITUTED: <label> routed <slug>, ran <ids>`. Session-scoped models come from the envelope's breakdown, which includes host-internal calls, so there it banners only a lane the routed model never served. Both hosts print the same words.
  - **The claude adapter reads the whole envelope, whatever the exit code, and the lane's own transcript.** `readClaudeEnvelope` returns a host record beside `result` and `usage`: subtype, error flag, bounded errors, permission denials, session id, turns, `sessionModels` and the client-side cost estimate, kept apart from `MODEL_PRICES`. The adapter reads the lane session's transcript for turn-scoped `servedModels`, which exists because the adapter never passes `--no-session-persistence`. `bin/interlock-run` forwards host records on their own channel, `--host-records`, never inside `results.json`. The CLI decides `LANE STOPPED BY HOST`, `SCHEMA RESULT MISSING (claude)` and `TOOLS DENIED IN LANE` at the record path.
  - **A new trajectory event, `agent-result`,** records what the host observed about each spawn: from the envelope on the runner, from the join at close on the Workflow host. It inherits the trajectory's fatal class, and the schema id is unchanged. The receipt gains six nullable counts (`lanesStoppedByHost`, `schemaResultsMissing`, `toolsDeniedInLanes`, `modelSubstitutions`, `permissionPrompts`, `autoModeDenials`). Each is absent when nothing was observed. The resume card lists every lane with a recorded session and its `claude --resume <id> --fork-session` command, saying the transcript may be gone after the host's retention period or a deleted session.
  - **Bare-proofing.** The adapter passes `--permission-prompts none` only outside `bypassPermissions` and only when the one-time `--help` probe lists the flag, and otherwise banners `PERMISSION PROMPTS NOT SUPPRESSED (claude)`. A pinned test fails on any argv or source line carrying `--no-session-persistence`. `interlock doctor` gains a `claude-bare` row, advice and never a failure, on whether a bare `-p` would have a credential. The agents-file workaround for #82258 was not adopted: its probe could not be run, and adoption requires a passing one.

- **Corpora of a linked-worktree run now land where `interlock report` reads them.** In a `claude --worktree`, `--bg` or Desktop worktree session a run used to start without its test profile and graph. It then wrote its fatal trajectory, outcome line, metrics and resume card into a directory that goes away with the worktree, and the report in the main checkout never knew. `lib/state-home.mjs` resolves the main checkout from `git rev-parse --git-common-dir`. Interlock's own lane worktrees resolve to themselves. Any git failure falls back to the root with `STATE HOME UNRESOLVED: <reason>`, and `--state-home <dir>` or `INTERLOCK_STATE_HOME` overrides the resolution.

  - **Append-only corpora go to the state home; per-run working state stays put.** Trajectories, outcome lines, review metrics, resume cards, interrupted-run notes and the autonomy ledger are written under the home. The manifest, wave state, briefings, spill, stage marker, launch ledger and agent-usage sidecar stay in the working root. `run start` resolves once and records the home on the manifest, and every later subcommand uses that record. Loss semantics are unchanged: a failed trajectory append in the home still exits 1, and an outcome or metrics write failure still only reports. **A main-checkout run resolves to itself, so every path it writes is the path it wrote before.**
  - **Inputs read through, and the drivers stop probing them.** `run start` finds the test profile and the graph in the root first and the state home second. It banners `TEST PROFILE FROM MAIN CHECKOUT` and `GRAPH FROM MAIN CHECKOUT`, and the latter says the graph may be stale for this worktree. The resolved profile path goes on the manifest for every later reader, the test guard included. `interlock-graph` query commands read the main checkout's graph in a worktree that has none and say so on stderr. Nothing is copied into the main checkout.
  - **The run records where it ran.** The manifest, the `run-start` event and the receipt carry `surface` (`main`, `linked-worktree`, `lane-worktree` or `unknown`) and the state home, and `run-start` also carries `cwd`. The close summary prints `state home:` under `cwd:` when they differ. A worktree run notes `CORPORA IN MAIN CHECKOUT`. `interlock report` reads every corpus from the home and partitions its scanned runs by surface. It also counts the trajectories stranded in other linked worktrees, without opening any. `interlock doctor` gains a `state-home` row and probes each state directory where it now lives. A subcommand that finds no manifest names the home's when one exists there.

- **A session that ends mid-run now leaves a note, and three readers speak it.** A session that ended while its own ship run was live stopped the background workflow before `run close`. That covers closing the terminal, quitting the app, `/exit`, and possibly the Desktop's "Send now" interrupt. The run got no receipt, no resume card and no terminal trajectory event, in exactly the place a reader most needs one. A new recorder hook, `hooks/recorder.mjs`, registered on `SessionEnd`, writes one small note at `.claude/ship/interrupted/<runId>.json`. It carries the run id, the change, the session, the host's end reason (verbatim, bounded), the stage the marker held and the time. `interlock run start` prints `PREVIOUS RUN INTERRUPTED: <change> run <id> ended at stage <stage> — no resume card was written; interlock run-log show <id>` for every unspoken note, whatever change it names, and marks it spoken. The SessionStart preflight surfaces the same line and marks nothing. `interlock report` splits runs without a terminal event into *interrupted* and *unexplained*, each over the scanned runs.

  - **It writes only for the session that owns a live run.** The recorder acts when a live stage marker exists and the run manifest's `sessionId`, now stored at plan adoption beside the `run-start` event that already recorded it, equals the ending session. In every other session and repository it creates no file and no directory. It returns no decision, prints nothing on stdout, and exits 0 on every path. It is the one recorder file later reporting branches join. `hooks/_shared.mjs` is unchanged.
  - **The note is outcome-class, and that is stated beside the trajectory's rule.** A failed write is a stderr line from the hook. An unreadable note is `INTERRUPTED NOTE UNREADABLE` on the manifest, and one that cannot be marked spoken is `INTERRUPTED NOTE NOT MARKED` and is spoken again next time. None of these moves an exit code. The trajectory stays fatal-class, and no hook writes it. [The guards page](docs/13-the-guards.md) names the two classes side by side so nobody makes them consistent. `interlock doctor` lists `.claude/ship/interrupted` as a non-fatal state directory.
  - **The runner closes on SIGINT and SIGTERM.** `bin/interlock-run` traps both and routes them through its existing `stop()` once, so a killed runner leaves a `run-halt` naming the signal, a receipt and a resume card like any other halt. A second signal, or a signal during a close already under way, starts no second close. A signal that lands before `run start` has answered is handled at the runner's first await, and the close reports that no manifest exists.

- **The Workflow runtime's concurrency is observed and printed, never used to resize a plan.** `interlock run start --host workflow` records `manifest.runtimeSlots`: the `CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS` override when it is an integer from 1 to 256, otherwise the vendor default beside the machine's CPU count, because the runtime may run fewer on a small machine. An override outside that range is recorded with its raw text, noted as `RUNTIME SLOTS OVERRIDE IGNORED`, and read as unset. When an adopted plan's widest batch holds more lanes than an observed override, the run banners `WAVE WIDER THAN RUNTIME SLOTS: the widest batch has <w> lanes and CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS=<n> — <w − n> lanes queue for a slot; the plan is not resized`. The vendor default raises nothing, because the reduction it may apply has no published number and inventing one would be a threshold in prose. `interlock limits` prints the observed value beside the vendor default, and its JSON carries `runtime.observed`.

- **`interlock doctor` gains a `claude-env` row.** It shows the installed Claude Code version, or `unknown`. It shows each of `CLAUDE_CODE_SUBAGENT_MODEL`, `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`, `CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS` and `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` with its value or as unset. It gives the version-aware reading of the plain model variable and says that FORCE forces one model, that the teams variable does not affect Workflow agents, whether a Bedrock variable is set (by name only), and the CPU count beside the vendor default. It is `ok` only when none of the four is set and the version was read, otherwise `skip`, and never `fail`. It costs the preflight one `claude --version` spawn, bounded by the probe's own timeout.

- **A second ship launch with no human message since the last one is now denied by a hook, not only by a sentence.** The most expensive mistake on record was a parent chat calling Workflow again over leftover checkboxes, which cost another 20+ agents including a full review cycle. `skills/ship/SKILL.md` forbade it, `test/skills.test.mjs` pinned the sentence and `evals/trampoline-launch` measured whether the model obeyed. Nothing stopped a model that did not. `hooks/guard-relaunch.mjs` is one script registered on four events: `PreToolUse` and `PostToolUse` with a `Workflow` matcher, `UserPromptSubmit` and `UserPromptExpansion`. Its `PreToolUse` branch denies a ship launch when the session already launched one and no human prompt has arrived since. The deny goes through the existing `deny()`, quotes the skill's sentence verbatim and names the remedy: send a new message asking to ship the leftovers, or type `/interlock:ship` again.

  - **The payloads were captured before the deny was written.** Two scratch sessions on CLI 2.1.274, with a logging hook on the four events, settled what the design could not assume. The captures are pinned under `test/fixtures/hooks/`. A typed `/interlock:ship` fires both prompt events and reaches the plugin's workflow command as `Workflow({ name: "interlock:ship", args })`. An accepted launch answers `status: 'async_launched'` with `taskId` and `runId`. The completion wake fires `UserPromptSubmit` with a `<task-notification>` prompt, so the guard does not count it as a person. Counted, it would have reset the clock in the very turn the relaunch happens in. The wake's own diagnostics suggest a resume through the persisted script and `resumeFromRunId`, so a call matching a run the session recorded counts as a launch too.
  - **The ledger is per session and only an accepted launch creates it.** `.claude/ship/launch-ledger/<session_id>.json` holds the launches the runtime accepted and the time of the last human prompt, written by `lib/launch-ledger.mjs`, which holds the rule with no reference to the hook protocol. `PostToolUse` creates it only for a response whose status says the workflow launched. A launch the engine refused never reaches the hook at all, which the capture showed. A prompt makes one existence check and writes nothing when the session has no ledger, so a prompt in a repository that never shipped creates no file and no directory.
  - **Its lifetime is a published cap.** `LIMITS.launchLedgerMaxAgeMs`, 24 hours, printed by `interlock limits` as `launch ledger max age (ms)` and read in `lib/`, where the cap-authority sweep finds it. A ledger whose newest launch is older reads as absent, and every launch write sweeps sibling ledgers past it. The bound can only widen the allow direction: ageing out turns a deny into an allow, never the reverse.
  - **Every unknown allows.** No session id or an unsafe one, a ledger that is missing, unreadable, malformed or stale, a tool input it does not recognise as a ship launch, another workflow, a tool that is not Workflow, and the guard's own crash all allow. An unreadable ledger and a crash are named on stderr. The recorder branches print no decision on any path. A false deny costs one typed message, and that is still a denial, so the capture gated the deny branch.
  - **The prose and the eval are unchanged.** The skill sentence and its token pin stay, and the deny quotes that sentence, so a reword of the skill now fails `test/hooks.test.mjs` too. The eval measures whether the model obeys; the hook bounds what happens when it does not. With hooks disabled, enforcement is the prose and the eval again. A prompt typed and queued during the run still re-arms one launch, and that hole is named, not closed. When the host can load plugin mods, an in-process guard replaces these four registrations. See [the guards](docs/13-the-guards.md#the-launch-ledger).

- **A cost-per-task sweep records what this repository's fixtures cost by model and effort, and changes no routing default.** `node evals/ship/matrix.mjs` crosses every committed outcome fixture with the API model ids `claude-opus-5-5` and `claude-sonnet-5-5` and the effort levels `low`, `medium`, `high` and `xhigh`. Each cell runs the control-arm procedure — the committed eval agent prompted once per task at that cell's model and effort, then the fixture's unit command and graders — in a scratch root outside the repository, and is priced by the outcome eval's own `priceUsage`. Each cell that ran appends one row to `evals/history/cost-per-task.jsonl` under schema `interlock.cost-per-task/1`: fixture, model, effort, judge pass or fail, token and cache-tier counts, dollars with the price-table id or the reason there are none, and wall clock. No transcript, prompt or diff is kept.

  - **It is not the outcome eval.** It is a separate command writing a separate file. It never appends to `ship-outcomes.jsonl`, its rows are not promotion trials, no pull-request workflow starts it, and it runs no wave loop, planner or verify step. A red grader is a field on a row and exits zero. A failed append, or a scratch root inside the repository, fails the sweep.
  - **A model the price table does not contain is not run.** The cell is recorded as not run with a reason naming the table id, and no request is made. The comparison is exact, so `claude-opus-5-5 ` with a trailing space is not a grid model.
  - **It is bounded by a new published ceiling, `EVAL_CAPS.matrixCostUsd`.** `interlock limits` prints it, and the sweep reads it from `interlock limits --json`. It is checked between cells only, so a started cell is never killed. An unpriced row adds nothing to the total. A sweep stopped there is partial, not failed. It gates nothing.
  - **The eval model client takes an optional effort.** When a cell passes one, every Messages request carries `output_config.effort`. The outcome eval passes none, so its requests have no `output_config`, and an `INTERLOCK_EVAL_EFFORT` exported in the operator's shell is stripped before it reaches an outcome-eval agent. The outcome eval's default model is unchanged.
  - **No routing default moved by the sweep.** It edits neither `EFFORT` nor `LANE_CAPS.opusMinTier`. The opus floor is a separate change in this release, under Changed. The rows are evidence that a later limits edit may cite, and this change does not make that edit. See [evals](docs/14-evals.md#cost-per-task--model--effort).

- **A halted ship run now leaves one file behind for the reader who was not watching.** Everything a halt records is machine-shaped and scattered: the trajectory under `.claude/ship/runs/`, the plan and its fingerprint under `.claude/ship/`, the unticked boxes in `openspec/changes/<change>/tasks.md`, and the reason itself in a summary printed to a terminal nobody was reading. Someone coming back in a new session, with none of that conversation in context, had to reassemble it from four places before they could do anything at all. `interlock run close` now does that reassembly once, at the halt, in prose: `lib/resume-card.mjs` writes `.claude/handoff/ship-<change>-<runId>.md`, and the terminal summary gains a `resume card: <path>` row — printed only when a card was actually written, so the row is never a pointer at a file that is not there. A run that halted before a plan was adopted has no run id and gets `ship-<change>-no-run-id.md`; the card states that absence in words rather than leaving the field blank, because "no trajectory was opened" is the fact a reader most needs out of that particular halt.

  The card carries the halt reason; where the run stopped (change, run id, project slug, cwd, trajectory path, and the `run-log show` / `run-log query --halted` commands that print the walk which led there); the leftover task ids beside an `interlock tasks tick <change> --ids <…>` whose id list is a placeholder you fill in, never the whole list — a halt leaves both done-but-unmarked work and work never attempted, and `tasks tick` flips a marker without verifying anything, so a paste-ready command over every leftover would tick unimplemented work and delete the only record of what is left; this run's own `PLAN REUSED` / `PLAN REBUILT` verdict and whether a plan and a fingerprint are stored for this change; the wave tallies; the degradation banners raised before the halt; and how to pick it up. It is written last in the close, so the banners it lists include the ones that close itself raised.

  - **It never predicts whether the next ship will reuse the plan.** The card states what is stored *now* — whether a plan and a fingerprint on disk name this change — and what the reuse rule is: the next `run start` recomputes the fingerprint from the current artifacts and skips the wave classifier only if it still matches. It does not say what that recomputation will decide, because the artifacts can change between the halt and the next run, and a card that guessed would be wrong in exactly the case where a reader leaned on it.
  - **Nothing reads it back, and the card says that about itself.** Plan reuse still decides from the stored fingerprint alone, so a card that was never written, or one that was hand-edited, cannot change what a later run does. That sentence is in the file rather than only in a header comment, because a markdown artifact called a "resume" is precisely the thing a reader assumes is wired into something. It is also not a mid-run resume: the wave cursor and the previous wave's handoff packets are not restored — `.claude/ship/state.json` is replaced at wave 0 by the next run — so work that was written but never ticked can be dispatched a second time. That is why the `tasks tick` command sits in the card's body instead of a footnote.
  - **Losing the card is a banner, never an exit code.** A failed write raises `RESUME CARD NOT WRITTEN: <reason>` and the close's exit code does not move. That is the outcome-corpus class of this repository's deliberately different per-corpus loss semantics, not the trajectory's: the card is a pointer to records that were written either way, and a read-only checkout or a full disk must not change *how* a run halted.
  - **Every list is bounded, and the bound is published rather than restated.** Leftover task ids, wave tallies and degradation banners are each capped by a new `LIMITS.resumeCardListRows`, printed by `interlock limits` as `resume card list rows (per list)`. The card is a pointer somebody reads in one sitting, not a second copy of the trajectory — but a silent head would make it lie, so it always says how many rows it left out and names the command that prints them all.
  - **The suite cannot drop a card into your live tree.** `test/spine/root-isolation.test.mjs` now guards `.claude/handoff/` alongside `.claude/ship/` and `.claude/metrics/`, so a test that reaches the binary without a pinned root fails there rather than leaving a card in the developer's checkout for a later read to mistake for a real halt's.

  See [when it stops](docs/04-when-it-stops.md) for where the card sits in the halt path, and `interlock limits` for the cap every one of its lists is printed under.

- **Prompt-cache cost is named, measured, and fixed where it was ours to fix.** A ship run repeatedly re-writes prefixes it could have read back, and until now nothing in Interlock could see it: the trajectory recorded exactly one token field (`outputTokens`) and nothing on the input side, so a cache miss was invisible by construction. Wave gaps measured in this repository's own trajectory are **363s and 1017s**, both past the short default lifetime, and each boundary re-writes its ~30–40k spawn prefix cold.

  A plugin cannot set either prompt-cache lifetime — the component model has no settings component — so this does the three things that *are* Interlock's:

  - **`interlock doctor` gains a `prompt-cache` row.** It names both settings keys (`promptCacheTtl` for the main conversation, `subagentPromptCacheTtl` for subagents and workflows — the bucket wave agents fall in), reports which scopes configure each, names the detected authentication mode, and carries the **v2.1.242** floor below which both are accepted and silently ignored. `ok` or `skip`, **never `fail`**, on `checkNotify`'s posture exactly: an unset lifetime costs money and never costs correctness. It reports **configuration only** — nothing exposes to a hook or a command the lifetime a session is actually running under, so the row never claims one, and an undetectable auth mode is named as undetected rather than guessed.
  - **A run records its cache tokens, not just its output tokens.** Cache reads and cache creation are recorded per wave and for the run, with creation split by the lifetime tier the host reported it under — **never summed**, because a five-minute write and a one-hour write are different prices and the flattening cannot be undone. The figures come from the host's own usage envelope, never estimated and never derived by subtraction, under the same unknown-not-zero rule already governing output-token spend: one spawn whose host reported nothing makes its whole span unknown rather than a lower bound wearing the shape of a total.
  - **Cache accounting is a declared host capability, bannered where absent.** It is *not* implied by `usage` — `codex` reports token usage and no decomposition, and the Workflow runtime exposes one cumulative spend scalar — so adapters declare `cacheAccounting` separately, the run program branches on the declaration rather than on a host's name, and a run that cannot report says `CACHE ACCOUNTING NOT REPORTED` in its summary. The receipt records the declaration beside the figures, so a reader can partition a corpus instead of averaging a measured figure against an absent one.
  - **A run records the host session identifier.** `run-start` carries the session the run executed under, so a trajectory joins to its transcript by a key rather than by overlapping wall clocks. Read by `interlock run start` from its own environment — never carried by a driver — and recorded absent on the runner, whose agents are separate vendor processes with sessions of their own. Verified before it was recorded at all: a subagent's shell reports the *parent* session's identifier, and that identifier names the parent's transcript file, so the value observed inside the Workflow host's ping subagent is the run's. No substitute is ever synthesised from the run id, the pid or the timestamp, and an absent one changes neither reconstructability nor the exit code.

  `lib/limits.mjs` gains cache-tier multipliers — 1.25x base input for a five-minute write, 2x for an hour, 0.1x for a read — under a **new price-table id** (`anthropic-list-2026-09b`) rather than an edit in place, so rows written under the old id stay attributable to the table that priced them. They are published by `interlock limits` beside the base rates and have no reader yet: this change records the data so a dollar figure becomes computable, and stops there.

  See [when it stops](docs/04-when-it-stops.md#two-different-caches-and-only-one-of-them-is-on-this-page), which now separates the two things this repository had been calling "cache" — the Workflow **replay** cache (keyed on exact prompt text, what makes a resumed run skip completed agents) from the Anthropic **prompt** cache (keyed on the request prefix, expiring on idleness) — and [why it works §4.4](docs/06-why-it-works.md), where the token-economy argument now reaches prefix *lifetime* and not only prefix *size*.

Plugin users move only when a release does. The same branch is what Anthropic's plugin directory tracks, and the bundle fits the directory's limits (138 files, none over 256 KiB) where the checkout raised two review holds.
  - **The tarball is the whole plugin now, so a test says so.** `test/spine/package.test.mjs` walks every path the plugin reaches at runtime: the component directories, the manifest's `workflows` and `types`, each `${CLAUDE_PLUGIN_ROOT}/…` that a hook command, skill, agent, shared contract, workflow or briefing names, and the import closure of every script among them. It fails on any path that no `files` entry ships or that does not exist. It also pins the marketplace entry's source, the bundle workflow's trigger, package and branch, and that both release workflows stay tracked past `.gitignore`.

  - **The branch is seeded, and rolled back, by hand.** Dispatch the workflow with a version already on npm. Re-running it for a version the branch already holds commits nothing.

- **The launch rule moved into one Node-free module that both forms of the guard import.** `lib/launch-rule.mjs` holds what a ship launch is, what a human prompt is, the decision and its words, and three record transforms, `emptyRecord`, `withLaunch` and `withPrompt`. It imports only `./limits.mjs`. `lib/launch-ledger.mjs` keeps the file and re-exports every rule name unchanged, so `hooks/guard-relaunch.mjs` and `test/hooks.test.mjs` import what they imported before. `recordLaunch` and `recordPrompt` now apply `withLaunch` and `withPrompt`, so the file and the session record change by the same functions. One visible effect: a launch written to a ledger now drops earlier launches past the published age, which never changed a verdict. `test/spine/launch-ledger.test.mjs` pins that each re-exported name is the rule module's own object, that the rule names no `node:` import, and that `decideLaunch` over a plain record and over the same facts read from a file returns the same verdict and reason.

- **The hooks module's observe-only pin now allows exactly one refusal instead of none.** `test/spine/mod-pins.test.mjs` no longer forbids the token `deny` outright. It allows one line, `if (launch && verdict.decision === 'deny') return { deny: verdict.reason }`, with `verdict` assigned once from `decideLaunch` imported from `lib/launch-rule.mjs`, and fails naming any other. The allow-list grows by exactly `$.clock.now`, `$.state.get` and `$.state.set`. The module's session-state keys must equal the contract's, and its hooked events are pinned, `prompt.submit` and `session.receive` included.

- **The manifest names a type contract, and the package ships it.** `.claude-plugin/plugin.json` gains `"types": "./types/index.d.ts"`, and `package.json`'s `files` gains `types`. `test/spine/package.test.mjs` fails naming a contract the manifest names that `files` would leave out, and asserts nothing for a manifest without one. `claude plugin validate . --strict` on 2.1.289 now prints `state reads: interlock.ledger` and `state writes: interlock.ledger`. It still fails this checkout on the pre-existing root `CLAUDE.md` warning, and on nothing this change adds.

- **The Workflow driver no longer probes for the graph or the test profile; `run start` does.** The validate ping lost its two `test -f` lines and the `hasGraph`, `graphReason` and `hasTestProfile` fields, and `GRAPH UNAVAILABLE` and `NO TEST PROFILE` are raised by the CLI, root first and then the state home, on both hosts. Two probes of one file in two places is how a driver and the CLI would have disagreed about whether it exists. The implementer briefing's graph line no longer gates on a file in the working root: it reads `Run interlock-graph query / consumers before grep; if it reports no graph, grep.`, because the graph CLI now answers from the state home's graph when the lane's worktree has none.

- **The model-override policy moved out of the Workflow driver and into `run start`, and it now reads the host's version.** `workflows/ship.js` used to ask its validate ping to `printenv CLAUDE_CODE_SUBAGENT_MODEL` and the Bedrock variables. It raised `MODEL ROUTING OVERRIDDEN` whenever the model variable was set and withheld the haiku pin from every control-plane ping. Since Claude Code 2.1.251 that variable sets only the *default* subagent model, and a model a spawn names wins. On a current host the banner was false, and the pings ran on the override model, often opus, for the whole run. `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`, which does replace every agent's model (2.1.257), was probed by nothing. `interlock run start --host workflow` now reads all of these from its own environment, the way it already reads the session id, and asks `claude --version` beside the existing `--help` effort probe. It then decides the banners and the ping model once, and puts `pingModel` on the step. The driver sets `pingExtra.model` from that field alone, and the relay whitelist carries it.

  - **On 2.1.251 or later**, a plain `CLAUDE_CODE_SUBAGENT_MODEL` raises no banner, the pings keep haiku, and a `MODEL ROUTING NOTE` says the variable sets only the default on this host. **On an older host, or when the version cannot be read**, the old banner and the old withholding stand, with ` (host version unknown)` appended when the version was unreadable.
  - **FORCE is bannered by name** (`MODEL ROUTING OVERRIDDEN: CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1 — every agent runs on one model`) on 2.1.257 or later, or when the version cannot be read. The Workflow host's observed `modelSelect` is refined to a new registry value, `forced`. This is the same downward refinement the effort probe already performs. No adapter may declare `forced`, and a run that declared its own model selection keeps it. On an older host FORCE is inert, and a note says so.
  - **A Bedrock variable now says why the pings inherit the session model.** The driver used to withhold the model silently. The run notes `PING MODEL INHERITED` instead.
  - **Both version floors are named constants** in `lib/host/claude-env.mjs`, the module that reads them. If the probe recorded in the change's design shows a spawn-time model does not win on a current host, the default-only floor becomes `null`, a one-constant revert.
  - **The `CLAUDE_CODE_EFFORT_LEVEL` probe stays where it was.** The validate ping still runs `printenv CLAUDE_CODE_EFFORT_LEVEL`, and `EFFORT ROUTING OVERRIDDEN` is unchanged. The doctor's `printenv` allowlist reason now names that variable only.

- **A null agent result is no longer reported as an unacknowledged briefing.** On the Workflow host, `agent()` returns nothing when the runtime stops an agent, when the API fails unrecoverably, or when a usage limit ends it outside an interactive subscription session. `spawnOne` reported all three as `BRIEFING NOT ACKNOWLEDGED: <label> reported (nothing)`, which sent the reader to the briefing when the host was the cause. It now banners `AGENT RETURNED NO RESULT: <label> — the runtime stopped it, the API failed, or a usage limit ended it; the step is recorded as failed`. `BRIEFING NOT ACKNOWLEDGED` is kept for a present result whose hash is missing or wrong. Either way the lane is recorded as failed. The runner's `spawnOne` is unchanged, because its adapters already name a failed spawn.

- **The outcome eval prices the Claude 5.5 list, cache terms included, under a new price-table id.** `MODEL_PRICES` is now `anthropic-list-2026-10`: `claude-opus-5-5` at $4 / $20 per million input / output tokens, `claude-sonnet-5-5` at $2 / $10 and `claude-haiku-4-5` at $1 / $5, as published on 2026-10-02. `claude-opus-5` and `claude-sonnet-5` are not in it, so a usage that still names them is unpriced under the new id with a reason naming that id, never priced at a rate guessed from the name. Rows already recorded under `anthropic-list-2026-09b` (or `anthropic-list-2026-09`) were **not rewritten** and keep the id that priced them; no number under either old id was edited.

  - **The cache-read multiplier is per model.** `cacheMultipliers.read` is keyed by the same model ids as the base rates — 0.05x for Opus 5.5, 0.1x for Sonnet 5.5 and Haiku 4.5 — and a listed model with no read multiplier is unpriced rather than priced at another model's rate. The write multipliers stay shared and per lifetime tier, `ephemeral_5m` and `ephemeral_1h`, never summed. `interlock limits` prints one read-multiplier row per model, and `--json` carries the per-model map.
  - **`priceUsage` now reads them.** The outcome eval's dollar figure is uncached input, output, cache reads at the model's own read multiplier and each cache-write tier at its own write multiplier. An absent input, output, cache-read count or cache-write record withholds the whole figure with a reason naming the field; a measured zero still prices. The model lookup is the exact string, so `Claude-Sonnet-5-5` or ` claude-opus-5-5` is unpriced. This is a behaviour change: a usage that carries input and output but no cache fields used to price on those two alone and is now unpriced.
  - **The eval agent records cache writes by lifetime tier.** `addUsage` turns a response's `usage` block into `{ ephemeral_5m, ephemeral_1h }` — copying the `cache_creation` split when the API sends it, and attributing a bare `cache_creation_input_tokens` to `ephemeral_5m` because the agent's breakpoint is the five-minute tier — and the usage record (`interlock.ship-eval-agent-usage/3`) stores that object. A usage line that still carries the old single write total makes the summed write record absent, not a zero write.
  - **The outcome eval's default model is `claude-opus-5-5`**, a key in the new table. `INTERLOCK_EVAL_MODEL` still overrides it, is recorded exactly as given, and is priced only when it is an exact key.

  The figure is still an outcome-eval estimate checked against `evals.shipEvalCostUsd`, never a bill and never a gate. The ship loop does not read the table, a missing price changes no exit code, and neither the ship receipt nor `interlock report` shows dollars.

- **Verify agents now run at the published verify effort, and that moves spend.** Both verify checks — the inter-wave check, with each of its retries, and the final check — used to be spawned with no effort, so they ran at whatever the host defaulted to while `interlock limits` printed a verify effort that nothing read. They now carry it. No value in the effort table changed; the `interlock limits` row is relabelled `effort: verify step (inter-wave and final)` because it now governs both checks, and its `--json` field is unchanged. The replan ping, the planner, the handoff and the commit spawn still carry no effort, on purpose, and a test fails on any new spawn kind that is placed in neither set.

  - **The runner forwards the effort, too.** `interlock-run` used to drop a spawn's effort before it reached the adapter, so `--host claude` lanes ran at the CLI's default. It now forwards it exactly as the Workflow driver does: when the step names one, and as no key at all when it does not. Neither driver derives or names an effort level; the run program is the one place an effort is decided.
  - **Effort is a declared host capability, recorded in the receipt.** Each adapter declares `effort` as `flag` (`claude`, with `--effort`), `negotiated` (`acp`, with `session/set_config_option` when the agent advertises an effort option whose flat values include the level exactly) or `unsupported` (`codex`, whose channel is not routed, and `qwen`, which has none). The Workflow host records the `claude --help` probe taken at `run start` (`flag` when the flag is listed, `unsupported` when it is not). The receipt's host block records the declaration; a receipt written before this reads as not recorded.
  - **Three banners say what landed.** The runner prints `effort routing: applied on N/N spawns` when every named effort was applied, or `EFFORT ROUTING UNAVAILABLE (<host>)` with one line per spawn that missed, naming the level it requested and a reason true of that host. Both drivers print `EFFORT ROUTING OVERRIDDEN` when `CLAUDE_CODE_EFFORT_LEVEL` is set — the runner on `--host claude` and on `--host acp` when the command is the Claude binary or `claude-agent-acp` / `claude-code-acp` — and neither strips the variable. A missed effort never fails a spawn. A spawn is counted only once its process has started; one that never starts is reported as a failed spawn, and is in neither count. See [when it stops](docs/04-when-it-stops.md#effort-routing-unavailable-host).
  - **`--host claude` reads the CLI's help once.** When the host is created, the adapter checks `--help` for the `--effort` flag. A CLI without it, or one whose help cannot be read, is declared `unsupported` for the run and is passed no flag, because a CLI that does not know the flag rejects the whole invocation. Only an option line that declares `--effort` counts. Help text that merely mentions it does not.
  - **The planner/runtime mirror requirement is removed.** It guarded a second copy of the effort derivation in `workflows/ship.js` that no longer exists. A forward-only requirement replaces it: each driver passes the step's effort through and derives none.

- **Multi-task lanes below the hard band run on sonnet.** With Claude Sonnet 5.5 nearly matching Opus 5.5 on agentic coding benchmarks while staying half the list price, a lane of two or more tasks no longer defaults to opus. `laneModel` now dispatches on opus only when the lane's hardest tier is at or above `LANE_CAPS.opusMinTier` (4), or when every task already carries opus (solo promotion / pure tier-5). Cohesion packs and low-tier chains — the bulk of multi-task implementer work — run on sonnet; cross-file and architectural multi-task lanes, solo, and single-task tier-5 keep opus. Effort stays derived from tier alone. The floor is published by `interlock limits` beside the cohesion ceiling; the classifier prompt is unchanged (it still must not be told the dispatch rule).

  - **Stored plans are rebuilt, not reused under the new rule.** The plan format is bumped to `interlock.ship-plan/5`, and the floor is part of the plan fingerprint. A stored `/4` plan has a lane report naming opus for every multi-task lane. It now reads `PLAN REBUILT (plan-format-changed)` instead of `PLAN REUSED`, so the classifier runs once more on the first ship of an in-flight change. A later change to the floor re-plans too, and `PLAN REBUILT (inputs-changed)` now names the cap that moved rather than reporting an artifact edit nobody made. A reused plan's lane report is re-derived from the narrowed lanes, so it names the model each lane will dispatch on.

- **A lane's model follows whether it can run in parallel.** A lane of two or more tasks — a path collision, a cohesion pack, or a chain — used to dispatch on opus unconditionally. That absolute rule is superseded by the opus floor above. A lane of one task still keeps that task's clamped model: haiku or sonnet below tier 5, opus only on a tier-5 task. The task's recorded model is not rewritten to match the dispatch, and effort stays derived from the hardest task's tier. A host that maps slugs (`INTERLOCK_MODEL_MAP`) has to map `opus` as well as `sonnet`, because hard multi-task lanes and solo still ask for it.

  **Chain lanes.** After cohesion and the singleton fold, consecutive batches of one wave that each hold a single lane are fused into one agent, in that batch order, under the same `LANE_CAPS.byTier` entry as the chain's hardest tier. A batch of two or more lanes is left parallel, and a chain never crosses a wave — including the red/next boundary and the implementation/test boundary. Solo plans are not fused. The "effectively serial" warning still counts lanes before fusion; the projected agent bill counts the lanes that dispatch after it. The plan format is bumped to `interlock.ship-plan/4`: a stored `/3` plan is rebuilt, because reusing one would dispatch the old shape.

  **One lost agent is one failure.** A multi-task lane whose agent returns no result marks the first task failed and the rest not-attempted, so the failure budget charges one failure for one lost agent. An omitted per-task outcome still fails every task in the lane.

### Fixed

- **`claude plugin validate . --strict` passes on this repository again.** From Claude Code 2.1.289 the validator rejects a `CLAUDE.md` at the plugin root, which is also this repository's root, because a plugin cannot ship context that way. CI's `validate-plugin` job was red on every push. The instructions moved to `.claude/CLAUDE.md`, which Claude Code loads as project instructions the same way, and a test now fails if a root `CLAUDE.md` comes back. `/interlock:fix-tests` mirrors its `## Testing` block into the first instruction file that exists (`CLAUDE.md`, then `.claude/CLAUDE.md`, then `AGENTS.md`), so it no longer recreates a root file in a plugin repository. The file was never in the npm package.

- **`/clear`, `/resume` and `/branch` now end the run the ship meter holds.** `session.start` does not fire at those boundaries, and the meter reset its run only there and on an accepted launch. So after a `/clear` mid-run the status line kept naming a run the conversation no longer held, while the launch guard's record in session state, which the engine does empty at that boundary, already allowed the next launch. The module now hooks `classic.SessionStart`: a `clear`, `resume` or `fork` source cancels the meter's interval, starts a fresh run record, clears the status line and redraws the pane to `no ship run is live in this session`. A compaction (`compact`) keeps the session and its run, and is passed through untouched, as are `startup` and a source the module cannot read. The pane is not closed, since the module has no call to close it and its no-run text is true. The first step from the earlier run that crosses afterwards is named once on the debug log. The built-in `diff` mod resets on the same boundary; the meter resets on the event that also covers `/branch`, and not on the typed command, so leaving the `/resume` picker resets nothing. The repro, a kit case per source, failed against the previous module.

- **A runner lane reaches the CLI that wrote its briefing.** Briefings call `interlock` by name, and the runner was handing the lane the session's PATH. Claude Code appends plugin `bin/` directories, so an older copy already on that PATH could answer the name and reject a subcommand the briefing was written against. A lane's PATH now starts with the directory of the `interlock` the runner itself runs, and a later copy of that directory is dropped. Nothing else in the environment changes.

- **`--isolate-waves` no longer reverts an earlier batch's edit and reports success.** Every isolated batch forked its lane worktrees from `git rev-parse HEAD`, and HEAD never moves during a run, because the ship commit is the run's last step. So a batch deferred for sharing a file with an earlier one edited a stale copy of that file, and its whole-file fold overwrote the earlier batch's edit with exit 0 and no collision. A wave-2 lane could not see a file a wave-1 lane had created. The run reported success and the code was wrong. Reproduced against the real `merge-lanes` binary: batch 2, forked from the unchanged pre-run HEAD, dropped batch 1's appended line.

  - **The merge base is a snapshot of the shared tree, not HEAD.** Before an isolated batch is dispatched, the CLI builds a commit of the shared tree as it stands, through a temporary index and git plumbing only. It holds every tracked edit and deletion and every untracked file `.gitignore` does not exclude, so it holds every earlier fold. It leaves out Interlock's own run state under `.claude/ship/` and any linked worktree inside the root, which would otherwise be staged as an embedded repository that a lane's fold reads as a deletion. No ref moves, the index and the working tree are untouched, the capture neither needs nor writes a git identity, and the commit is left to git's own expiry once the batch folds. Untracked, non-ignored files now reach lane trees, which is the fix for wave 2. An ignored generated file stays absent, as before.
  - **A clean tree forks from HEAD itself.** When the snapshot's tree equals HEAD's, HEAD is the base and no object is written. That is the first isolated batch of a run started on a clean tree.
  - **A lane forked from the wrong base halts, on every host.** `run record-batch` now reads each lane worktree's HEAD from git before anything folds, never from the lane's own report, and halts with `LANE BASE MISMATCH: <lane> forked from <sha>, expected <snapshot>` when it is not the stored base. No lane of that batch is folded, and every surviving worktree is named. A lane that reported no writes and whose worktree is gone is an empty-write lane, not a mismatch.
  - **The Workflow host's limit is spoken.** Its runtime forks lane worktrees from `worktree.baseRef`, which a plugin can neither read nor set. `run start` with `--isolate-waves` there raises `ISOLATION BASE NOT CONTROLLED (workflow)`, and a mismatch on that host adds that `worktree.baseRef` chose the base and that `--isolate-waves` there needs the follow-up change that creates lane worktrees from the CLI. Until then an isolated run on that host halts after its first fold rather than folding wrongly.
  - **A batch without `--isolate-waves` is byte-for-byte unchanged.** It still carries `mergeBase: null` and captures nothing.

  See [when it stops](docs/04-when-it-stops.md#lane-base-mismatch).

- **A Claude ACP adapter is recognised as Claude, and the Workflow host records the effort it probed.** `claude-agent-acp` and `claude-code-acp` now raise `SUBSCRIPTION PATH` and `EFFORT ROUTING OVERRIDDEN` the way `claude` and `claude-code` already did. They still do not get `--agent`, and they still print `HOOKS NOT IN FORCE`, because those hooks load only in the Claude binary. A command named `npx` is still not recognised. `/interlock:ship` reads `claude --help` once at `run start` and records that verdict: `flag` when the flag is listed, `unsupported` with `EFFORT ROUTING UNAVAILABLE (workflow)` when it is not or the probe cannot be read. The script still passes each step's effort to `agent()`. A caller that already declared the capability keeps it.

- **The Workflow host's relay no longer retypes a whole program.** On `/interlock:ship`, every `interlock run` call is made by a relay, a small model that copies the CLI's stdout back into the script. A step carried each implementer's briefing inline plus the wave's carried state (`remainingBatches`, `previousHandoffs`, `changed`). The script reads none of it: briefings reach workers by path and hash, and the next `run` call reads the wave state from `state.json`. In a real run, a 23 KB step was retyped with a duplicated key run and two dropped brackets, did not parse, and halted a healthy run at wave 6. `interlock run` now prints a slim step for the Workflow host (`relayStep` in `lib/run.mjs`). It is a whitelist of the fields the interpreter reads, with no spawn `prompt`, and a typical batch step drops to a few KB. Runner hosts (`bin/interlock-run`) still get the full step, because they send the briefing inline. A test scans `workflows/ship.js` for the fields it reads, so the whitelist cannot starve it later.

- **A relay whose copy does not parse halts with the reason, not just the fact.** The halt used to read only `the CLI relay could not be read`. It now names the relay, the subcommand, how many characters were copied and the parser's own message (usually with the failing position), raises a `RELAY UNREADABLE` banner, and points at `.claude/ship/last-step.json`. Every `run` call except the close now writes the exact bytes it printed to that file, so a reader can compare the CLI's output with the relay's copy without digging through a transcript. The halt does not auto-retry: a stale copy could replay a batch past the sequence guard and record it twice.

- **The trajectory logs the implementer lanes each batch actually dispatches.** On the `run` path, lane spawns were logged a whole wave at a time at its first batch. A run that halted before a later batch therefore had spawn events for agents that never ran. A wave entered through `run judge` (inter-wave), `run replan` or `run next` logged no lane spawns at all. Each of those sites now logs exactly the lanes of the batch it emits, at every batch index, and a failed append halts before dispatch just as it already did at `run start` and `record-batch`. The `wave-state` subcommands keep their own protocol unchanged.

- **The inter-wave verify budget is charged the checks' own time.** The budget was clocked from a verify step's dispatch to its judgement, which also counts two relays and the verify agent's own turns. On a Workflow run, the first checkpoint spent the whole budget and every later checkpoint ran typecheck only. The new `interlock verify exec --kind <k> --command <cmd>` runs one planned check with its output and exit code passed through unchanged, and records its duration to `.claude/ship/verify-timings.jsonl`. The verify briefing now runs every planned step through it, and `run judge` charges the recorded durations. A checkpoint with no timing for a planned step falls back to the round trip and says so with `VERIFY BUDGET CLOCKED BY ROUND TRIP`. No threshold changed, and the per-run checkpoint cap and its placement are untouched.

- **A failed write to the run trajectory now halts the run it was recording, instead of warning and shipping anyway.** `.claude/ship/runs` has been `fatal: true` in `interlock doctor` since it existed, and `wave-state` and `verify judge` have always exited non-zero when their append did not land. The live `interlock run` path was the one writer that did not: it called `ctx.warn` and walked on — into the task tick, and into the commit. The outcome was precisely the artifact the corpus exists to prevent: a run that ticked its boxes, committed, and cannot be replayed. It now halts at every site that owes the trajectory a line — `run-start`, `wave-state create` / `record-batch` / `record-verify` / `replan`, `agent-spawn` (implementer lanes included, which go through the same writer `wave-state next` uses) and `cli-exit` — **before** any tick and before any commit, with the reason `trajectory append failed: <site>: <cause>`. The cause is the filesystem's own, threaded out of the writer rather than left on a stderr the Workflow host does not relay; a full disk now says so by name. See [when it stops](docs/04-when-it-stops.md#the-loud-halts).

  What this costs you: a run that previously finished green on a machine that could not write its own record now stops. That green finish was the bug. Nothing is ticked and nothing is committed, so the re-run starts from a truthful `tasks.md`. The close still runs, so the receipt, the outcome record and the halt resume card all still land wherever the filesystem allows.

  The split this repository deliberately keeps is unchanged and was not "made consistent": the trajectory is evidence and is fatal; `.claude/learning/outcomes.jsonl`, the review metrics and the resume card are pointers to evidence written elsewhere, so losing one is reported and never moves the exit code. One consequence is now documented rather than surprising — when the **close** cannot write its receipt or terminal line, the summary still reads `SHIP COMPLETE` (the run did complete and commit) while the exit code moves to `1` (it cannot be replayed), with a `TRAJECTORY APPEND FAILED` banner naming the lost line.

- **`merge-lanes` stopped treating a rename and an edit of the same file as disjoint work.** Under `--isolate-waves` each lane runs in its own git worktree and the folds are checked for collisions on the paths the lanes wrote. A rename was keyed on its **destination** only — so lane A renaming `lib/a.mjs` to `lib/b.mjs` and lane B editing `lib/a.mjs` looked like two lanes touching different files, and the fold then restored or deleted that source depending on which lane happened to apply last. Silent last-writer-wins, in the one mechanism whose entire purpose is to refuse it. Contention is now keyed on every path a fold will **mutate**: a rename contributes its destination *and* the source it deletes (`foldMutationPaths` in `lib/merge-lanes.mjs`). A copy's source is not a mutation — the fold does not delete it — and is deliberately excluded, so a genuinely disjoint batch is not halted for it.

  What this costs you: a batch that used to fold and silently lose one lane's edit now halts, names the contended source path and both lanes, and leaves both worktrees on disk to read. `mergeDecision` is unchanged — it is still a path-set intersection, and `canonicalizePath` is still the single normalization site. The reported `folds[].files` of a clean fold now include rename sources, which is accurate: they are paths the lane's fold mutates.

- **The outcome eval was reporting a cache tally it never asked for.** `evals/ship/agent/model.mjs` is the repository's only raw Messages API caller, and it sent **no `cache_control` block at all** while faithfully tallying `cache_read_input_tokens` — so it re-paid full base input on up to 60 turns of every loop and reported a permanent zero that read as "caching unavailable" rather than "no breakpoint sent". A cost bug and a measurement bug in one object.

  The loop now marks its stable prefix — `tools` then `system`, the portion byte-identical on every turn — with one breakpoint on the prefix's last block, computed once outside the loop so every turn sends the same bytes; a breakpoint inside the growing message list would re-write the entry each turn instead of reading it. The existing `emptyUsage()`/`addUsage()` tallies are untouched: they were always correct and were only ever reporting a structural zero.

  A zero has four causes and only one is a miss, so the eval now records which: `unrequested` (no breakpoint sent), `unmeasured` (a breakpoint sent and the provider still wrote nothing — a prefix below the minimum cacheable size, a fact about the apparatus rather than a finding), or `measured`, where a written-and-not-reused prefix is a real miss and is distinguishable from all of them. The agent identity and usage-record schema both bump to `/2`, because a change to the loop that moves a measurement must not be comparable against rows produced before it. The fix landed its failing assertion first, against a stub that models the provider's actual rule — an entry is written only where the request marks one — so the assertion could not pass against a loop that asks for nothing.

- **An unattended ship run that stops can now reach you.** Four independent "quick win" gaps closed at the one seam both hosts already pass through — `interlock run close`:

  - **Push on halt or completion.** With `INTERLOCK_NTFY_TOPIC` set, `run close --notify` — which both `workflows/ship.js` and `bin/interlock-run` now pass on every close — posts one [ntfy](https://ntfy.sh) message per terminal outcome: `high` priority on `SHIP HALTED`, default otherwise. The message carries the summary's first line, the change and the run id, and nothing that identifies the machine — never the topic, the cwd or the project slug. `INTERLOCK_NTFY_URL` selects a self-hosted server (default `https://ntfy.sh`); leaving the topic unset makes the default path, and the test suite, open no connection at all. A failed push prints `push: failed — <reason>` and a `PUSH FAILED: <reason>` degradation banner and never moves the exit code. `interlock notify` and the `interlock notify checkpoint <change>` sugar (used by `/interlock:spec`'s checkpoint) are also callable standalone.
  - **The summary names the run and where it closed.** Every terminal summary now carries `run: <runId>` (or `run: none — the run halted before a plan was adopted`), `project: <slug>` and `cwd: <absolute path>` rows, so a reader who was not watching can find the trajectory file and the checkout afterwards. `<slug>` is a pure function of the closing directory (`lib/project-slug.mjs`), matching the directory name Claude Code uses under `~/.claude/projects`.
  - **A clean completion reminds you to archive.** When every task is ticked and the run did not halt, the summary prints `ARCHIVE PENDING — <change>: after merge, run openspec archive <change>` — plus `also unarchived: <n> completed change(s) — run interlock drift` when other changes are also sitting there — right before the closing "do not start another run" line. It is a reminder, never a gate: the exit code never moves, because the shipped change satisfies the unarchived check by construction at every clean close.
  - **`interlock doctor` stops reporting green for a run whose first ping prompts.** `REQUIRED_COMMANDS` gains `test`, `printenv` and `mkdir` — the commands the environment probe actually shells out to — each with a `why`, and a new `notify` row (`ok` naming the server, `skip` naming `INTERLOCK_NTFY_TOPIC`, never the value). A repo-fact test now checks this repository's own `.claude/settings.json` against the derived list, and a drift test extracts every instructed command out of `workflows/ship.js` and `lib/prompts/*.mjs` and fails, naming the file and the command, the moment one falls outside `REQUIRED_COMMANDS`, the runner commands, or the documented host read-only set (`HOST_READ_ONLY`).

  All four are additive: unset `INTERLOCK_NTFY_TOPIC` and a run behaves exactly as before, plus the three new identity rows and, on a clean ship, the archive line. See [when it stops](docs/04-when-it-stops.md) for `ARCHIVE PENDING` and `PUSH FAILED`, and [push notifications](docs/07-cli-and-configuration.md#the-one-network-call-push-notifications) for the two environment variables.

- **The CLIs install without Claude Code.** `package.json` was `private: true`, so the only way onto a PATH was a git checkout or the plugin install — even though the policy engine, the graph and the runner are stdlib Node with no dependencies and each is useful outside a Claude Code session. The package publishes as **`@renzrollon/interlock`** (`npm i -g @renzrollon/interlock`, or `npx -p @renzrollon/interlock interlock ...`), and the plugin install path is untouched.

  What ships is a **whitelist**, not an ignore list: `files` names `bin`, `lib`, `workflows`, `skills`, `hooks`, `agents`, `shared`, `.claude-plugin` and the three root documents, so a new directory cannot ship by accident. The failure that whitelist invites is the opposite one — a reachable `lib/` file left out packs cleanly, installs cleanly, and dies at the user's first command — so `test/spine/package.test.mjs` walks the transitive relative-import closure of **every declared `bin` entry** (including the bare side-effect `import` that is how `bin/interlock-graph` reaches the whole graph CLI) and fails naming any reached file no `files` entry covers. It also asserts each `bin` entry exists, is executable and carries the node shebang, and that `package.json`, `.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json` carry **one** `MAJOR.MINOR.PATCH` version — the `bump-release` skill keeps bumping them together, and a partial bump is now a red build rather than a habit that held.

  CI's `cli-smoke` job packs the tarball, installs it into a throwaway prefix, and runs every binary the `bin` map names plus `interlock limits` from that prefix — the map is read with `node -e`, so a renamed binary cannot fall out of the smoke silently. Releases publish from a `v[0-9]*` tag through `.github/workflows/release.yml`: `npm test` first, then `npm publish --provenance --access public` over the workflow's OIDC identity. **No registry token is stored in this repository.** Trusted publishing is a one-time console step on the registry for this repository and that file name; until it exists the publish step fails with the registry's own error and the workflow is reported failed, never skipped.

- **The ACP driver became a runner, and a host is now one file plus a declaration.** `bin/interlock-ship-acp` spoke one protocol to one kind of agent. Once the loop moved into the CLI, everything left in that file was a transport — and a transport welded to one vendor is the reason "Interlock runs on Claude Code and nothing else" was a portability claim nobody could act on. It is **`bin/interlock-run`** now, with `--host claude | acp | codex | qwen` (or `$INTERLOCK_RUN_HOST`), and an adapter under `lib/host/` is a transport plus a declaration of what that host **cannot** do: `schemaEnforced`, `modelSelect`, `worktree`, `hooks`, `usage`, `billing`. The run program reads those declarations; nothing branches on a host's name.

  `bin/interlock-ship-acp` still works: it prints `interlock-ship-acp is now interlock-run --host acp` on stderr — never on stdout, which carries the summary a caller may be parsing — and execs the runner with your arguments and its exit status. **It is removed in the next minor version (0.3.0).**

  Every vendor flag was verified against the installed CLI rather than taken from a doc, and one had drifted: `codex exec` (0.145.0) rejects `--ask-for-approval` outright, so the adapter does not send it — `exec` is the non-interactive mode and never prompts. `--dangerously-bypass-approvals-and-sandbox` is deliberately not used in its place; `--sandbox workspace-write` is the posture a ship lane wants. The three fixture CLIs under `test/fixtures/hosts/` **refuse** a wrong invocation rather than accepting one, so a drifted flag fails a test instead of producing a green run that enforced no schema.

- **Lane isolation is closed on the runner, which was the gap blocked on the host.** Under `--isolate-waves` the run program emits one worktree path per lane and the batch's merge base; `bin/interlock-run` runs `git worktree add --detach` per lane, spawns it with that directory as its cwd (for ACP, the session's cwd), and `interlock run record-batch` folds the clean lanes, removes their worktrees, and **halts naming the path and both lanes** when two of them wrote the same file despite a disjoint prediction. The path is derived by the CLI and read back by the fold rather than reported by the agent, so the checkout and the fold cannot disagree about where a lane ran. Who creates the worktree is the host's declared `worktree` capability — `runtime` on the Workflow host, which is unchanged — not a branch on its id. `docs/08-harness-landscape.md` said this gap was "the strongest argument for the host port"; it now says the port paid off.

- **Model routing is one published map, read by every host.** `INTERLOCK_MODEL_MAP` is a JSON object keyed by host id, each entry mapping the planner's tier slugs to that host's model ids; a malformed one fails the invocation at startup rather than three waves in. `claude` accepts `haiku`/`sonnet`/`opus` unmapped; `acp` negotiates as before; `codex` and `qwen` require a mapping and, without one, get **no model flag at all** and are named in `MODEL ROUTING UNAVAILABLE (<host>)` with the reason `no mapping for <slug>` — never quietly run on the operator's default and reported as the tier the planner asked for. `INTERLOCK_ACP_MODEL_MAP` keeps working as an alias of the `acp` entry.

- **The runner says which billing path it is on, and the receipt records it.** `ACP HOST (experimental)` is replaced by `RUNNER HOST: <id> (experimental)`, and three new banners state what a green summary would otherwise hide: `SUBSCRIPTION PATH: programmatic (<host>)` for a run over the Claude binary directly or through ACP, `CHATGPT PLAN PATH (codex)` when neither `CODEX_API_KEY` nor `OPENAI_API_KEY` is set, and `HOOKS NOT IN FORCE (<host>)` on a host with no equivalent of this repository's `PreToolUse` guards. The receipt carries `host: { id, billing, hooks, usage }`.

  **The default host does not change, and the reason is written down.** `/interlock:ship` launches the Workflow runtime, no skill ever starts the runner, and the runner refuses `--host workflow` from the other side. Inside an interactive session the Workflow runtime is the path Anthropic exempted from its paused programmatic-use billing change; `claude -p`, the Agent SDK and ACP are the flagged usage. `docs/04-when-it-stops.md` carries that paragraph, and the `SUBSCRIPTION PATH` banner points at it, so there is one place to update if the policy settles.

  A live probe settled the one condition the design left open: a plugin `PreToolUse` hook returning `permissionDecision: "deny"` **still blocks** under `claude -p --permission-mode bypassPermissions` (the call was refused and recorded in `permission_denials`). So `bypassPermissions` stays the unattended default and the `claude` host declares `hooks: true`; the fallback to `dontAsk` plus `--allowedTools` was not needed. The adapter passes `--plugin-dir` naming this checkout, which is what makes `--agent interlock:worker` resolvable and that declaration honest — and when the checkout is not the plugin it passes no `--agent` and declares `hooks: false` rather than assuming.

- **Token usage reaches the receipt when the host reports it, and is `unknown` when it does not.** Each adapter attaches `usage` beside a spawn's result from the vendor's own envelope, and `run close` sums it per wave and per run. One spawn without usage makes its wave — and the run total — `unknown`, never a smaller number: a partial sum looks like a measurement and is a lower bound. A host that reports nothing at all (`qwen`, `acp`) says so once, in the summary, instead of leaving empty figures to be read as zero.

- **The ACP host routes models per session, and the banner it used to print unconditionally became conditional and specific.** `bin/interlock-ship-acp` printed `MODEL ROUTING UNAVAILABLE (ACP host)` on every run, because when the adapter was written ACP v1 had no per-prompt model selector: the planner's slug travelled only as an `_meta['interlock/model']` hint an agent was free to ignore. So the tier ladder — haiku pings, sonnet implementers, opus only at tier 5, which is most of the cost story — was not in effect on the second host at all. ACP has since standardised session configuration, and the gap closes inside the adapter with no change to the host contract or to the loop.

  After `session/new`, `lib/host/acp.mjs` reads the `configOptions` the agent advertised; when one is a model selector (id `model` or category `model`) it picks a value for the planner's slug and applies it with `session/set_config_option` before `session/prompt`, falling back once to the legacy `session/set_model` on any JSON-RPC error. An agent that advertises nothing still gets one `session/set_model` with the raw slug, since agents predating config options accept it. The `_meta` hint keeps travelling for agents that honour it.

  **A value is chosen by rule, never guessed.** `pickModelValue(slug, option, map)` takes an operator's map first, then an exact `value`, then the first advertised option whose `value` or display `name` contains the slug case-insensitively — and otherwise nothing, because a wrong model that ran is invisible in a summary and a banner is not. `INTERLOCK_ACP_MODEL_MAP` is a JSON object of slug → value for agents whose model ids share no text with `haiku`/`sonnet`/`opus`; a mapped value the agent does not advertise is refused rather than sent, and a malformed map fails `createAcpHost` at startup rather than three waves in.

  **The banner is now derived, not declared.** The adapter emits one `{ type: 'model-routing', label, requested, applied, via, value, reason }` event per spawn that carried a model, and `host.modelRoutingSupported: false` — whose meaning was "never" — is replaced by `host.modelRouting: 'negotiated'`. The driver aggregates the events and computes nothing itself: it prints `MODEL ROUTING UNAVAILABLE (ACP host)` (verbatim, unchanged) with one `— <label>: <reason>` line per unrouted spawn only when at least one spawn that asked for a model did not get it, and otherwise the note `model routing: applied on N/N spawns via ACP session config`. The three reasons a spawn can carry — `no model option advertised`, `slug not among advertised values`, `mapped value not advertised` — are documented in [`docs/04-when-it-stops.md`](docs/04-when-it-stops.md). The permission `mode` option is deliberately left alone: trading `hooks/guard-tests.mjs` for an unverified `bypassPermissions` shortcut is a follow-on with its own test.

  Every path is proven against `test/fixtures/acp/agent.mjs` without a live agent: it grew `--config-options`, `--set-model` and `--config-error` modes and echoes back what it actually received as `appliedModel` / `appliedVia`, so a test asserts what the agent saw rather than what the adapter said about itself. For a user: an ACP agent that advertises its models behaves as it did before, banner included, only now the banner tells you which spawns and why — and one env var fixes the two cases where it can.

- **The strict tail is emitted by the CLI, and the second host runs it.** Adversarial review, bounded remediation, the verdict and the handoff artifacts were the last loop text either driver held: they ran inline in `workflows/ship.js` behind a `host-tail` step, and `bin/interlock-ship-acp` exited `2` on `--strict`, `--review`, `--handoff` and `--conformance` rather than quietly shipping something smaller. So the guarantees that make a strict run worth paying for — evidence-gated dismissal, a round budget the model cannot argue with, rubric delivery on re-review — were Claude-Code-only. `lib/run.mjs` now emits the tail as steps like any other, both drivers interpret them like any other, and the no-policy sweep in `test/workflows.test.mjs` has **no allowance left**: the seam marker, the skip it bought, and the exit-2 refusal are all gone, and the tail's own tokens (`isReal`, `qualityScore`, `reReviewDimensions`, `roundCap`, `byFile`, `needsManualTestPlan`, `autonomy`, `xhigh`) are in the swept list so the deletion cannot be undone by accident.

  **Every judgement with a correct answer moved into the CLI.** `run reviewed` reads the `findings.json` and `verdicts.json` the review agent wrote and adjudicates them with `lib/review-core.mjs` — the same survival, evidence and band rules `interlock review` applies — against the run's **observed** changed paths rather than a list the agent reported about the diff it was reviewing, then writes `review.json` and the review metrics and asks `lib/remediate.mjs` for round one. `run remediated --round <n>` re-adjudicates the rewritten files, records fixed and deferred, and obtains the next round, the verdict or the halt. No agent runs `interlock review` or `interlock remediate` any more, and no driver copies `roundCap`: raising `LIMITS.remediationRounds` by one buys exactly one more fixing round and moves the verdict round with it, with nothing outside `lib/` edited.

  **Criteria and policy are inlined rather than fetched.** The review and remediation briefings carry each selected dimension's written criteria and the repository's `REVIEW.md` prose, read by the CLI before the briefing is assembled — so the rubric-delivery requirement holds on re-review by construction instead of by an instruction the agent had to follow. A dimension whose criteria cannot be read is named in the briefing ("works from the dimension name alone") and bannered `REVIEW RUBRIC UNAVAILABLE: <dimension>` on the step, rather than dispatched silently. The policy prose stays framed as quoted data, subordinate to the rubric and the evidence gate.

  **Dimension selection is a recorded rule.** `language`, `architecture`, `qa` and `technical-lead` always; `devops` when the observed changed paths include deploy, CI, configuration or infrastructure files; `security` when they include auth, input-handling or data-exposure files — by the same path classification the run already uses for risk, with a reason recorded per optional dimension. It was a judgement call in the prompt, which made the dimension set unreportable. The reviewer may still add a dimension with a one-line reason, and the addition is recorded on the manifest.

  **Two provenance leaks closed.** The handoff briefing no longer asks the agent to run `interlock surface` and `interlock conformance` with `--changed <files changed by this run>` — the CLI runs both in-process over its own observed paths and inlines whether a manual test plan is needed (with the reason when it is not) and the scenario checklist to answer. And the autonomy-ladder record is written by `run close` from the CLI's last adjudication, for a strict run that actually reviewed; it used to ride on a prompt, which handed an observed count to the party the record assesses.

  For a user: `interlock-ship-acp <change> --strict` now runs the whole thing, and exit `2` no longer means "flag refused" — it means the invocation could not be started at all. A strict run on either host produces the same steps, the same halts, the same banners and the same receipt fields, because there is one program.

- **The ship loop moved into the CLI; both drivers are now interpreters.** Interlock has run two drivers of one loop since the ACP host landed — `workflows/ship.js` on the Workflow runtime and `bin/interlock-ship-acp` over ACP — and each held its own copy of the branching and of every agent's briefing, sharing policy only by evaluating marked blocks of one driver's source through `new Function`. `lib/run.mjs` now emits the whole program as a versioned step (`interlock.run-step/1`): the agents to spawn — label, model, tools, result schema, briefing — and the exact `interlock` argv to call once they return. A driver's loop is *spawn everything in `spawns`, write the results, call `then.argv`, repeat until `then` is null*, and it branches on nothing — not a flag, a mode, a count, or a verdict; every one of those (apply-only, no-commit, skip-e2e, isolate-waves, replan, verify-skip, done) is taken inside `lib/run.mjs` from a run manifest (`.claude/ship/run.json`) and the wave state.

  A briefing is delivered by reference, not pasted through a ping: `run` writes it to `.claude/ship/briefings/<label>.md` with its own sha256 on line one, and the step carries the path, the hash, and the text. The ACP driver is ordinary Node and reads the text off the step; the Workflow script cannot hold several kilobytes of prompt without a ping copying it — which would either breach the result-field cap or invite a silent under-instructed run on a relay miss — so it hands the worker the path and requires the hash back as `briefing` in its result. An absent or wrong hash fails the task closed with a named reason, exactly as a missing handoff packet does today.

  `interlock run classified --classified <file>` folds the mechanical work after the classifier — coverage, `waves`, `wave-state create`, the run-start event, and the first step — into one call, so the classifying agent no longer runs four CLI commands whose output it is also the one reporting on. `interlock run record-batch` folds the lane merge (under `--isolate-waves`), `wave-state record-batch --write-state`, and `tasks tick` into one call. `interlock run close` builds the receipt and the summary text every driver prints verbatim, and takes host-only banners through `--host-banners` so "no degradation banners" stays true across two hosts. `LIMITS.maxRunSteps` (200) replaces the literal `MAX_LOOP_STEPS` both drivers used to hardcode; each driver keeps its own `RUNAWAY_BACKSTOP` (1000) as a runtime ceiling, named in a comment as not a policy cap. The one loop text left in a driver after that change was the `host-tail` seam — the strict tail, inline in `workflows/ship.js` behind a single step name, refused by the ACP driver with exit `2`. `emit-strict-tail-from-cli` (below) removed it.

  Prompt assembly moved with it, into `lib/prompts/` (`implementer.mjs`, `planner.mjs`, `replan.mjs`, `commit.mjs`, `verify.mjs`, `stage.mjs`, `schemas.mjs`) — the ten pinned implementer fixtures under `test/fixtures/prompts/` are byte-identical, and the "publish the ship stage" fragment now renders from `lib/ship-stage.mjs`'s own constants instead of a literal duplicated in `workflows/ship.js` and drift-tested against it. The planner prompt is the same on both hosts now: the ACP form (write `classified.json` and stop) rather than the Workflow form that used to ask the same agent to run four commands afterward.

- **Cohesion lanes, a per-tier lane cap, and solo mode — fewer, fatter implementers on minor work.** A lane could only form from a path collision, so sixteen path-disjoint tier-2 test tasks were sixteen agents, each paying a spawn prefix and re-reading the same design to change one line. Inside a dependency layer, `interlock waves` now packs disjoint components whose hardest tier is at or below `LANE_CAPS.cohesionMaxTier` (3) into shared lanes — next-fit over hardest-first components, tasks in id order, never across a layer, a section, or the implementation/test boundary. Tier 4 and 5 are excluded on purpose: cross-file and novel work is where a fresh context per task still earns its cost. Every fold is a named warning and a `kind` on the lane, so a plan says what it packed rather than leaving it inferred from a smaller agent count.

  The lane cap is now the table `LANE_CAPS.byTier` (`1:8 2:8 3:6 4:4 5:8`) rather than one scalar, because a bound that is right for eight trivial edits is wrong for four cross-file refactors. `LIMITS.maxTasksPerAgent` is **removed rather than aliased** — a deprecated alias would have let a reader keep the old scalar silently, while removal fails the stale reader at import. The `maxTasksPerAgent` override survives as a uniform ceiling, so an override of 1 still reproduces one agent per task exactly.

  **Solo mode** ships a small change as one opus agent holding all of it: one wave, one batch, one lane, every implementation task in section-then-layer-then-id order followed by the test tasks, inside the same verify-and-commit loop and the same failure budget. `--solo` and `--waves` force it either way (both at once halts at parse); absent a flag, the classifier emits a `recommendedMode` and the planner honours solo only inside the published envelope `SOLO.maxTasks` (20), refusing it above that with a warning naming the count and the bound. The prompt asking for that recommendation never states the number — the envelope is a cap in `lib/limits.mjs`, printed by `interlock limits` as its own `laneCaps` and `solo` groups and read by the planner, so it cannot be re-argued in prose. A solo lane is promoted to opus after the classifier clamp (each promotion reported like a clamp) and briefed at the full-read ladder without rewriting any task's tier.

  The plan preview opens by naming the mode and its source, and the plan format is bumped to `interlock.ship-plan/3`: every stored `/2` plan is rebuilt once, because a `/2` plan has no cohesion lanes and no mode, and reusing one would silently keep the old shape. The mode override is part of the fingerprint, so a plan built under a different override is re-planned rather than adopted.

- **`interlock report` — the reader the corpora never had.** Interlock wrote three corpora and read none of them: `lib/outcomes.mjs` says in its own header that per §4.15(a) it "records and nothing else", `lib/run-log.mjs` accumulates a trajectory per run, `lib/metrics.mjs` writes a review's counts. That was the right call for *gating* and the wrong one for *reading* — the §4.16 ladder waits on evidence that was accumulating unread. `report` computes indicators over all three: coverage, first-pass ship, rework, plan fidelity, review findings, and which deterministic gate actually blocks. Add `--since` for a window, `--change` for one change, `--json` for the payload.

  Three properties are load-bearing. **A denominator travels with every value** — a zero denominator yields `null` and a reason, never `0`, because a rate over an unstated denominator commits both the error `lib/doctor.mjs` names ("an unknown is not a pass") and the one `lib/outcomes.mjs` names ("a biased control group is worse than none, because it looks like evidence"). **Provenance survives the arithmetic** — the observed/reported partition is carried through, so the review series from receipts and the one from metrics files are reported separately and never summed. And **one indicator is declared uncomputable**: "does the merged diff match the plan" is the sharpest question here and nothing records the comparison, so rather than approximate it from `planStatus` (stored-plan reuse over planning inputs) or the replan rate (the plan changing mid-run) — both about the plan, neither about the diff — it reports `computable: false` with what would close it.

  It **gates nothing, and that is policy rather than convenience**: always exit 0, no value compared against anything, no verdict word in the output, nothing in the loop reading it, and no file written — not even a cache. Every value here is one `if` away from a threshold and §4.15(a) forbids exactly that `if`; wiring one is decision §4.16 / slice F6.6, which has not been made. Metrics files are classified by their `schema` key and never by filename, because `skills/review-artifacts` writes `review-artifacts-*.json` into the same directory — matching the glob `review-*.json` while carrying finding bodies instead of counts — and a filename reader would mix a skill's prose into a counts indicator with nothing to notice. Ships with `/interlock:report`, which explains a census and is forbidden from recommending a cap or gate change on the strength of a figure, and [docs/11](docs/11-the-indicators.md).

  Its first run against this repository found three things nobody knew: the `run-receipt` event type had never once been written across 740 trajectories, 738 of those trajectories were attributed to no change at all, and every file in `.claude/metrics/` had been written by a skill in a shape the counts reader does not accept. A corpus nobody can read is a corpus nobody notices is empty.

- **`interlock doctor` — the preflight.** Every other gate in this repository judges the work; this one judges the machine the work runs on, because those are the expensive failures. A run that stops on wave four because `openspec` is not installed, or parks on an approval prompt for `npm test` with nobody watching, has spent four waves of agents to learn something a filesystem read knew at second zero — and since the reconstructability gate landed, an unwritable `.claude/ship/` no longer degrades a run, it ends it. `doctor` checks the Node version against both floors that apply (the plugin's, and the OpenSpec CLI's higher 20.19.0), the **installed** plugin's workflow / agent types / binaries (resolved from the plugin, never from the checkout you happen to be standing in — conflating them produces a report that checked the wrong copy), `interlock` / `interlock-graph` / `openspec` / `git` on PATH, whether the project is an OpenSpec project and a git work tree, `.claude/testing/profile.json`, the permission allowlist, and the writability of every run-state directory. It exits 1 when a check would stop an unattended run, and never repairs anything: each failure carries the fix as text, including a paste-ready `permissions.allow` snippet.

  Two properties make the allowlist half worth trusting. The required-command set is **derived, not hardcoded** — the four the flow always shells out to, plus whatever `.claude/testing/profile.json` says this project runs, truncated at the first `<placeholder>` — so a repo whose suite is `pnpm vitest run` is checked for `pnpm vitest run`. And a rule that exists but is *narrower* than the command it would have to permit (`Bash(interlock waves:*)` against a loop that calls ~30 subcommands) is reported as narrower **by name**, never counted as coverage; counting it would produce the one thing a preflight must never produce, a green report followed by the halt it promised to prevent. A `deny` overlapping a required command fails, an `ask` warns, and `defaultMode: "bypassPermissions"` warns and checks nothing, because nothing will prompt. The matcher reads both the current `Bash(git status:*)` spelling and the older `Bash(git *)` glob form.

### Fixed

- **A fresh ship run could die with `TypeError: lanes.some is not a function` instead of running its first wave.** A step never reaches `workflows/ship.js` from the CLI — the script has no shell, so every step arrives transcribed by an agent into a JSON schema. Two schemas carry a step, and only one of them was widened when batches became lanes: the `plan-waves` classifier still declared the pre-lane flat `tasks` and never declared `remainingBatches` at all. An undeclared property passes validation holding anything, so an agent told to copy `wave-state next` stdout with no slot to copy into wrote a list of task ids, and the wave loop called `.some` on a string. The throw happened outside `halt`, so the run lost its outcome record, its trajectory close event, and its banners along with the wave. The step shape is now stated once (`STEP_FIELDS`) and read by every schema that carries a step; `stepFromAgent` accepts a step only if the loop can actually dispatch it, so a bad transcription takes the existing single `next-retry-` re-read of state rather than the loop; and a step that stays misshapen halts by name. Test fixtures no longer always attach `cliStdout`, which is why the transcription fallback was reachable in production and unreachable in tests.

### Removed

- **`/interlock:session-retro`** moved to [renzrollon/shippable-skills](https://github.com/renzrollon/shippable-skills). It is no longer part of this plugin. Install it with `npx skills add renzrollon/shippable-skills` (or the Claude Code plugin on that repo). The live-session retro was never Interlock-specific; shipping it here blocked Cursor, Copilot, and Codex.

### Changed

A `LEAN SHIP:` banner lists what was skipped so a lean run cannot look like a strict one. Continuity (`spec --continue`) also launches lean unless a tail flag is passed. Coverage checking and the first `wave-state next` are folded into the planner (no extra `plan-coverage` or `next-1` agents). `interlock autonomy record` runs only under `--strict`.

as enforced were prose, and one was not wired up at all. Those claims are now
either true or gone.

### Added

- **Slim spawn prefix.** Every `/interlock:ship` `agent()` call names a plugin agent (`interlock:ping` / `interlock:worker`) and passes a tools allowlist that excludes Skill, Agent, and MCP, so workers stop inheriting the parent session's ~40k tool-and-skill catalog. ACP prepends `--agent <type>` when the command is the Claude Code CLI.

Inter-wave verification is capped (`LIMITS.interWaveVerifications`, default 3) and skipped for docs-only waves. `formatPlan` prints a projected agent count and warns on effectively serial plans. `verify plan` accepts `--context inter-wave` and `--changed`; docs-only `--changed` emits no steps. Ship fuses a following verify into the `record-batch` ping and records every remaining batch of a wave in one ping. Cheap pings use haiku when a one-time Bedrock probe says it is reachable. Wave-entry `wave-state next` logs one `agent-spawn` per task in `remainingBatches` so the ship-run trajectory matches the implementers the loop actually launches.
- **`/interlock:session-retro`** — a retro that runs while the transcript is still
  in context. Scores the live session against a new session-shapes taxonomy
  (`shared/SESSION-SHAPES.md`), flags where it wasted tokens against
  `shared/TOOL-ECONOMY.md` in relative magnitude (never fabricated counts), and
  writes wire-in notes under `.claude/handoff/` that fold repeatable steps back into

- **`docs/` — four human-facing pages.** [The first hour](docs/01-first-hour.md)
  (install → `bootstrap` → one `spec` → read it → `ship` → archive, plus an

  [when it stops](docs/04-when-it-stops.md) (every halt and banner, and the
  three-way split between harness-enforced, code-enforced, and model-followed).
- **The tolerance band is now applied.** `lib/findings.mjs` exported
  `TOLERANCE_BAND` since 0.1.0 and nothing called it. `applyToleranceBand()`
  now partitions findings into `{ reportable, dropped }`, and `evaluateGate()`
  applies it after the skeptics' dismissals and before counting blockers — so a
  finding scored below 3 of 5 for how well-grounded it is can no longer block a
  change. Unscored findings are kept: absence of a score is not evidence of low
  quality. When two skeptics disagree by more than `drift`, the disagreement is
  treated as signal and the finding survives. Gate results carry
  `droppedByQuality`, counted separately from `dismissedCount`.
- `interlock gate --min-quality <n>` and `--no-tolerance` to move or disable the
  band per run. It is on by default, in the CLI rather than in review prose,
  so it cannot be quietly re-argued on each run.
- **Loud failure banners** in `ship`'s final summary — `GRAPH UNAVAILABLE`,
  `NO TEST PROFILE`, `VERIFICATION SKIPPED`, `E2E FAILED (non-blocking by
  policy)` — printed whenever the condition holds, including on otherwise
  successful runs. A degraded run no longer reads like a clean one.
- Structural tests: a skill whose body instructs spawning subagents must list
  `Agent` in `allowed-tools`, and `shared/` + `lib/` are scanned for
  predecessor-project strings the way `skills/` already was.

**The ship loop became a program**

- **`workflows/ship.js`** — the eleven numbered headings of `skills/ship/SKILL.md`
  are now a script the runtime executes. The script holds the loop, the
  branching and the intermediate results; the `interlock` CLI holds the rules;
  the agents do the work. A cap is no longer a sentence a tired model can talk
  itself out of.
- **`lib/limits.mjs`** — every cap in one place: 8 parallel agents, 2 inter-wave
  fix attempts, 2 replans, 2 remediation rounds, 5 root-cause iterations, 2
  tolerated task failures. The CLI help text interpolates them, so the
  documentation cannot drift from the constant.
- **`lib/waves.mjs`** gained a pure execution state machine beside the planner:
  wave order, inter-wave verification, replan eligibility and the task-failure
  halt. Every transition returns a new deep-frozen state, because a resumed
  workflow replays transitions from cached results and a machine that mutated in
  place would answer differently on the replay than on the first pass.
- **`lib/remediate.mjs`** — blockers are fixed, suggestions are deferred,
  same-file findings never run in parallel. Rounds 1–2 fix; round 3 is a
  verdict-only round that is the sole round able to halt, so the last fix pass
  is never pre-empted by a halt it had not yet earned.
- **`lib/review-core.mjs`** — skeptic majority survival, severity refinement, and
  the quality band, with counts that distinguish *dismissed by a skeptic* from
  *dropped as too weak to report*. Ties keep the finding: a surviving false
  positive costs ten seconds of reading, and a wrong dismissal is invisible.
- **`lib/verify.mjs`** — plans verification from the test profile and judges the
  results, without ever running anything itself. Commands come from the profile
  verbatim; a red unit suite halts; coverage is advisory; e2e is reported and
  never repaired. Failures cluster by normalized error signature so a shared
  root cause is fixed once. Whether a typecheck halts now depends on where
  verification was called from — blocking between waves, reported but
  non-halting at the final gate, so the three documented hard halts stay three.
- **`lib/metrics.mjs`** — the review's dismissed and quality-dropped counts, and
  nothing else, under `.claude/metrics/`. This is the number the README points
  at as evidence a review is worth trusting; it is now real.
- **CLI**: `limits`, `remediate`, `review`, `verify plan|judge|unit|cluster|repair`,
  `wave-state create|next|record-batch|record-verify|replan`, `risk`, `ledger`,
  `ready`, `outcomes`. Every gating command exits non-zero when it blocks, and
  the workflow branches on exit status rather than on parsed prose.

**Opt-in continuity (`/interlock:spec --continue`)**

- **`lib/risk.mjs`** — classifies a change `low`/`medium`/`high`/`critical` from
  its paths and artifact text, and **fails closed**: no usable signal classifies
  as `high`, never `low`, and source paths matching no rule floor at `medium`
  because unrecognised is not safe. Every classification carries the signals and
  evidence that produced it.
- **`lib/ledger.mjs` + `shared/DECISION-LEDGER.md`** — a durable decision ledger
  at `openspec/changes/<name>/decisions.md`. An `agent_resolved` row without a
  written resolution *and* evidence is invalid, and an invalid row blocks exactly
  like an unanswered one.
- **`lib/ready.mjs`** — the gate. Fifteen named checks; `ready` is true only when
  every one affirmatively passed. A check that could not run is never a pass, an
  omitted artifact-review result is an unrun check rather than a clean one, and
  an exception while gathering evidence becomes a blocker.
- **`lib/outcomes.mjs`** — `.claude/learning/outcomes.jsonl`, appended for
  checkpoint and continuity runs alike. **Nothing gates on it yet** (§4.15a);
  it exists so that a later decision can be made on evidence instead of feel.

## [0.1.0] — 2026-08-12

Initial release. Interlock is a Claude Code plugin that layers autonomous
spec-driven orchestration on top of the OpenSpec CLI.

### Added

**Distribution**
- Claude Code plugin with a single-plugin marketplace — installs in two commands.
- `bin/` executables (`interlock`, `interlock-graph`) join the Bash tool's `PATH`
  automatically when the plugin is enabled.

**The deterministic spine (`interlock`)**
- `waves` — plans execution waves from classified tasks: orders groups, clamps
  over-eager model assignments, defers test tasks, and **caps parallel fan-out**
  (default 8).
- `surface` — classifies changed files as UI-TESTABLE / UI-INDIRECT /
  NOT-UI-TESTABLE, and decides whether a manual test plan or devops review is
  warranted.
- `gate` — decides whether a review blocks, and partitions findings per file for
  parallel remediation. Exits non-zero when blocked.
- `validate` / `changes` — OpenSpec change readiness and discovery.
- `autonomy` — the L2→L3 earned-autonomy ladder with transitive blame.

**The code graph (`interlock-graph`)**
- Local, deterministic import/symbol graph with OpenSpec and memory overlays.
  Zero dependencies, no network, no vector store.
- Token-budgeted retrieval: `query`, `consumers`, `path`, `explain`, `context`,
  `docs`, `docs-index`.

**Skills**
- Onboarding: `graph`, `docs-digest`, `bootstrap`.
- Loop: `explore`, `spec`, `ship`, `mr`.
- Supporting: `review-code`, `review-artifacts`, `manual-test-plan`,
  `explain-code`, `commit`, `fix-tests`, `dispatch`.

**Guardrails enforced by the harness rather than by prose**
- `ship` sets `disallowed-tools: AskUserQuestion` — its zero-touch contract is
  structural, not aspirational.
- `ship`, `commit` and `mr` set `disable-model-invocation: true`, so Claude
  cannot decide on its own to commit or open a merge request.

**Testing**
- 171 tests, no dependencies. Covers the spine, the graph, and structural
  validation of every skill (frontmatter fields, description budget, and whether
  every bundled-file reference resolves).
- CI validates the plugin manifests with `claude plugin validate --strict` and
  smoke-tests the CLIs as executables.

### Notes

- Interlock **composes** OpenSpec rather than forking its skills. `/interlock:spec`
  drives the `openspec` CLI directly, so it does not drift when OpenSpec
  releases. Stock `openspec-*` skills remain available alongside it.
- Structural graph indexing covers JavaScript/TypeScript, Python and shell. Other
  languages get docs and spec indexing plus the full workflow, but no
  import/symbol edges — the skills state this rather than implying completeness.
- The autonomy ladder ships opt-in until it has accumulated real run data.
